## 摘要
计算机使用智能体（CUA）正越来越多地以多智能体系统形式部署，这类系统将任务分解为多个子任务，并在并行虚拟机（VM）上执行。然而，一个关键的物理瓶颈是两台虚拟机的状态无法合并。以往系统以临时方式处理这一问题，而不是将其视为首要关注点。我们提出面向多智能体计算机使用的 Spine-Branch 协同框架，该框架将任务分解为“主干-分支”图，其中主干承载具有连续 VM 状态的主任务流，分支任务并行执行，以收集主干完成任务所需的信息。分支 VM 在任务完成后即被丢弃，因此永远不会发生 VM 合并。实验表明，在 Odysseys 的 200 个长时程任务上，并在三种 CUA 骨干模型上，Spine-Branch 相比基线系统将成功率提高 6.0% 至 16.5%，同时将单任务成本降低 34% 至 70%，这表明显式建模 VM 状态合并约束可使多智能体计算机使用高效扩展。

## Abstract
Computer use agents (CUAs) are increasingly deployed as multi-agent systems that decompose a task into multiple subtasks executed across parallel virtual machines (VMs). However, a critical physical bottleneck is that the state of two VMs cannot be merged. Previous systems handle this ad-hoc rather than treating it as a first-class concern. We propose Spine-Branch Coordination for multi-agent computer use, a framework that decomposes a task into a "spine-branch" graph, where the spine carries the main task flow with continuous VM state and branch tasks execute in parallel to collect information the spine needs to complete the task. Branch VMs are discarded once their tasks finish, so no VM merging ever occurs. Experiments show that on 200 long-horizon tasks from Odysseys and across three CUA backbones, Spine-Branch improves success rate over the baseline system by 6.0% to 16.5%, while reducing per-task cost by 34% to 70%, indicating that explicitly modeling VM-state merging constraint enables multi-agent computer use to scale efficiently.

- **关键物理瓶颈**：CUA 必须处理两类本质不同的信息：
  - *可提取产物（extractable deliverables）*：文本、下载文件、导出数据集等，可以脱离 VM 自由复制、广播、拼接；
  - *VM 状态（VM state）*：登录会话、打开的标签页、RAM 内容、未提交的表单、未保存的编辑等，**无法被"提取"**——交付它等于交付整台 VM。
- **核心约束（single-parent VM inheritance，单亲 VM 继承）**：VM 状态只能通过两种方式产生——从 base image 全新启动，或从**一台**现有 VM 克隆（`init_from`）。所有主流虚拟化栈（VMware、KVM/QEMU、Hyper-V、Xen）都不提供融合两台运行中机器的操作。且 VM 状态包含浏览器标签、cookie、GUI 窗口、显示缓冲、剪贴板、文件系统变更、终端会话、本地服务、网络连接、应用缓存等**难以合并的异构数据类型**（引 CRDT 文献说明其不可合并性）。因此每个子任务至多从**一个**前驱继承 VM 状态。
- **现有系统的缺陷**：

### 2.1 核心思想

> **无法廉价重建的状态留在唯一连续流（Spine）上；一切可归约为可转移产物的在并行分支（Branch）中运行。**

- 主干承载主任务流与持续 VM 状态（通过 VM 克隆传递），分支在全新 VM 或主干 VM 的克隆上并行执行、返回可提取产物，完成后其 VM 即被丢弃——**因此永远不会发生 VM 合并**。

- 任务表示为角色化依赖 DAG：`G = (V, Evm, Eart, ρ)`，其中 `V = W ∪ {a}`（W 为 CUA worker 节点，a 为 Manager 执行的聚合节点）。
- `Evm ⊆ W × W` 为 VM 状态依赖（`init_from`）；`Eart ⊆ W × V` 为产物依赖；`ρ: W → {SPINE, BRANCH}` 分配执行角色；联合图无环，存在合法拓扑序。
