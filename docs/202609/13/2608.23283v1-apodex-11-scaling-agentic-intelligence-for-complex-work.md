## 摘要
通用语言模型能够推理和综合知识，但复杂工作还要求与文件、信息源和可执行代码持续交互，并具备状态维护、故障恢复和可验证交付能力。我们将这种能力称为\emph{工作能力}：朝着真实世界目标持续取得可验证进展。Apodex 1.1 沿两个互补维度发展这一能力。\emph{环境扩展}扩展可执行文件、搜索和代码环境的多样性与可验证性，而\emph{智能体协调扩展}训练智能体分解长时程任务、委派并行工作、整合异步结果并重新规划。共享执行框架与 AgentOS 跨工具和智能体维护任务状态与溯源信息，训练则将环境轨迹和协调轨迹转化为可靠行为。在复杂的专业工作、金融、科学研究、数学、编程和搜索等任务中，尽管所用模型比许多前沿系统小得多，Apodex 1.1 仍达到领先性能区间。拥有 350 亿参数的 Apodex 1.1 Mini 进一步以可本地部署的形式保持强大的工作能力。这些结果将智能体智能建立在随时间完成的有用且可验证的工作之上，并推进我们构建面向宏大、长时运行任务的\emph{重型求解器}的目标。

## Abstract
General-purpose language models can reason and synthesize knowledge, but complex work also requires sustained interaction with files, information sources, and executable code, together with state maintenance, failure recovery, and verifiable delivery. We call this \emph{working capability}: sustained, verifiable progress toward a real-world objective. Apodex 1.1 develops this capability along two complementary dimensions. \emph{Environment Scaling} expands the diversity and verifiability of executable file, search, and code environments, while \emph{Agentic Coordination Scaling} trains agents to decompose long-horizon tasks, delegate parallel work, integrate asynchronous results, and replan. A shared execution harness and AgentOS maintain task state and provenance across tools and agents, and training turns environment trajectories and coordination traces into reliable behavior. Across complex professional work, finance, scientific research, mathematics, coding, and search, Apodex 1.1 reaches the leading performance band despite using a substantially smaller model than many frontier systems. The 35B-parameter Apodex 1.1 Mini further retains strong working capability in a locally deployable form. These results ground agentic intelligence in useful, verifiable work completed over time and advance our goal of building a \emph{Heavy-Duty Solver} for ambitious, long-running tasks.

## 1. 核心问题与研究动机

- **背景缺口**：通用语言模型在知识、推理、数学、编程上进步迅速，但许多有价值的工作即使模型"能说出正确答案"仍然做不成，因为任务在**长时程**上展开：需要寻找与解读证据、操作异构文件、执行与调试代码、在多步中维持并修订计划、在不丢弃有效进展的前提下从失败动作中恢复，并交付他人可检查、可继续使用的工件。
- **核心命题**：限制能力不是孤立的推理能力，而是**把推理转化为环境中持续工作**的能力。作者据此提出"**工作能力**（working capability）"——朝真实世界目标取得**持续且可验证的进展**。
- **分析单元转变**：智能体智能的分析单元应是"**已完成的工作**（completed work）"，而不是一次孤立回答。终局自然语言答案只是工作区中的一个工件，本身不定义成功。
- **长期目标**：**重型求解器（Heavy-Duty Solver）**，能对日益宏大、长时运行、可验证的工作负责。
- **现有工作对照**：ReAct、Toolformer、AgentBench、WebArena、OSWorld、SWE-bench、APEX-Agents 等已暴露"答案质量"与"可靠行动"之间的差距；多智能体系统（AutoGen、MetaGPT、ChatDev、AI co-scientist 等）展示了协作收益，但也提示"更多智能体并非一律有益"。

## 2. 方法论

### 2.1 总体思想：两条互补的扩展维度 + 一个共享执行契约

- **环境扩展（Environment Scaling）**：扩展可执行文件 / 搜索 / 代码世界的**多样性、保真度与可验证性**，而非增加提示词数量。
- **智能体协调扩展（Agentic Coordination Scaling）**：把分解、委派、异步结果整合、共享计划修订、分支重组**训练成模型行为**，并由 Agent Team 在运行时实现。
- **共享执行框架（harness）+ AgentOS**：把两个维度绑定到持久化状态、类型化观测、重放与完成检查之上。
- **训练**：统一 SFT + 智能体 RL，把环境轨迹与协调轨迹转化为能力；训练**不被视为第三条独立扩展轴**，而是前两条维度的"学习机制"。
- **受控自演化**：自演化仅用于"工程闭环"（失败→任务构造→环境→训练→评测），不做无约束的模型自我修改。

### 2.2 形式化任务契约

- 任务契约定义为 **E = (W, W₀, q, A, T, Ω, B, D, V_D)**：
  - **W / W₀**：工作区状态空间与初始工作区；**q**：归一化目标；**A**：可用动作集合；
  - **T**：状态转移算子（可随机，故重放需保留外生状态、工具版本、随机种子）；**Ω**：观测接口；
  - **B**：资源预算向量（轮次、工具调用、token、墙钟时间、并发数）；**D**：交付契约；**V_D**：任务级验证器。
- **关键区分**：
  - 初始用户输入 u₀ 与目标 q **不是同一对象**：前者是输入消息，后者是任务规格的一部分。
  - 用户消息若**不改变目标或交付物**（澄清证据、优先级、方法），仍属同一任务；若实质改变 q 或 D，则**实例化新任务契约**（但可复用有效工作区状态）。
  - **异步用户干预** uₜ 是运行时记录在轨迹中的更新，**不是模型选择的动作**；子智能体报告、求解器可见的验证器结果、工具失败、超时都属于**工具响应 o_{t+1}**，而非用户输入。
- **转移与观测**：W_{t+1} = T(Wₜ, aₜ)，o_{t+1} = Ω(Wₜ, aₜ, W_{t+1})；允许 no-op 转移以支持只读动作。
- **轨迹与判定**：τ_H = (u₀, a₀, o₁, …, u_{H−1}, a_{H−1}, o_H)；终局验证 **S_D = V_D(W₀, W_H, τ_H) ∈ Y_D**。
  - 终局验证器 V_D 与"作为工具暴露给求解器的验证器"概念上不同：后者只产生普通观测 o_{t+1}，前者判定已完成的交付。
  - 成功 = 有用结果 **+** 从输入到交付的可辩护路径。

### 2.3 环境扩展

- **三大环境族**（共享同一任务契约，可在同一轨迹中组合）：
  - **文件世界**：中心是**权威性与转换**。构造文件世界是"解题的逆过程"：先定义底层业务状态、权威关系、推导逻辑与交付要求，再投影成工作区。覆盖度按职业条件化：当前场景注册表覆盖 **33 个领域、318 个职业、1,208 个交付物簇**；结构深度由贡献系统数量、业务逻辑链长度、以及需要从上下文推断（而非照抄提示）的交付契约比例决定——**与文件数量无关**。
  - **搜索世界**：中心是**发现与证据对齐**。黄金对象不只是最终答案，还包括相关来源集合、论断—证据对齐、以及来源冲突处的显式不确定性。检索溯源保持精确，语义支持可做有界模型复核。
  - **代码世界**：中心是**可执行转换与验证**。共享基础镜像 + 任务特定仓库状态；长尾环境一次构建、缓存复用。覆盖来自真实 PR 的采集世界与合成世界（组合、抽象迁移、请求变异、对抗性输入改变）。**验证器加固先于任务扰动**，否则产生的是"被破坏的任务"而非新的可执行世界。
- **验证边界**（表 1）：文件世界用代码推导值或记录的溯源；搜索世界用溯源 + 论断复核；代码世界用测试 + 工件检查。**"精确"意味着代码推导或独立对账，而非仅由语言模型裁判接受**。
- **难度标定**：采集类世界提出**采集压力坐标** ρ_acq(E) = (N_cand(E) + N_hop(E)) / B_tool(E)，作为一阶坐标而非通用难度度量；代码世界需用依赖深度、状态转移深度、测试可观测性、失败到可执行验证信号的距离等不同坐标。
- **验证、隔离与重放**：
  - 生成任务、测试、参考解三者可能**共享同一错误**，故验证器必须建立在产生候选结果的路径之外。
  - 每次 rollout 获得**不可变世界清单 + 全新可变沙箱**，粘性路由保持会话在同一 worker；求解器观测、隐藏验证器状态、事后标签相互分离。
  - 轨迹仅在初始状态可重建、工具执行隔离、验证器可重放时保留；重放记录含世界种子、生成器版本、工具版本、动作/观测序列、文件增量、验证器版本、终止原因。
  - 构造原则：**"正向便宜，逆向昂贵"**——生成器用潜在状态或参考程序廉价地构造并求解世界；智能体只看到渲染后的工作区，必须在约束下恢复相关路径。

### 2.4 智能体协调扩展：Apodex Agent Team 1.1

保留 1.0 的"主导智能体全局推理 → 分解 → 按需构造专家子智能体"架构（团队由问题诱导，而非从固定角色目录中挑选），并新增四项能力：

- **显式任务板（Task Board）**：主导智能体在委派前把分解写入任务板，条目含受限目标、依赖、解决状态、指派的智能体、返回的证据/工件。任务板是**模型、运行时与用户之间的共享协调记录**，而不只是私有推理的可视化。效果：结果可立即解锁依赖任务；被推翻的前提只使其后代失效；慢分支不再阻塞独立工作；分解从一次性前言变为**长时程的持久控制面**。
- **异步人工干预**：构造覆盖需求澄清、任务事实纠正、优先级变更、新文件/证据、假设或方法修订、来源与工具约束、预算/截止时间变化、暂停—恢复—取消、进度查询、输出格式与语言偏好、无关侧问题等干预轨迹。训练模型判断**干预改变了什么、什么仍然有效、后续工作如何继续**——不是"打断按钮"，而是一种习得策略。任务保持型查询获得简短及时回应，独立执行继续。
- **非对称验证（Asymmetric Verification）**：仅上下文分离不够（同能力验证者重解整题会引入第二条同样不受约束的错误链）。因此验证**刻意比生成更窄**：验证者只接收某个具体论断、其支持证据、适用的交付约束，任务是攻击该论断（找反例、用真正独立的来源类三角验证、核对名称/日期/数字/公式等原子细节、检查格式与规格合规）。**非对称在于任务而非模型规模**；反馈可操作（指名争议论断、反驳证据或失败检查、所需修复）。
- **自适应最大团队投入（Adaptive Max Team Effort）**：只对薄弱、有争议或承重的论断追加独立范围的调查；沿真正不同的假设、方法、来源类、查询框架扇出；后续波次分配给未解决或被否证的分支；承重结论定稿前要求定向验证。**扩展变量是有用的协调工作量，而非固定的智能体数或样本数**。
- **证据接地综合（Evidence-Grounded Synthesis）**：团队执行与验证后增加专门综合阶段，消费终局任务板、子智能体报告
