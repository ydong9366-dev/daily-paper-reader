## 摘要
设计大语言模型（LLM）多智能体系统（MAS）仍依赖试错和非正式的“民间智慧”。人工研究仅测试少数通信结构或拓扑（如顺序、并行、共享内存或辩论），而自动化优化器在选定任务特定工作流后会丢弃搜索轨迹。我们提出一个两阶段流水线，从工作流代码和执行轨迹中挖掘可复现的设计原则。我们改造 AFlow 的 MCTS 优化器，使其作用于六种可组合算子和 26 个经确定性验证的 Enigmata 任务，并保留所有中间轮次以构建包含 28,568 个可执行工作流的语料库。随后，一个沙箱化的 AutoResearch 循环在带 L0 惩罚的验证目标下挖掘编排代码和提示模板，并在留出搜索中检验候选原则。在 300 次特征挖掘试验中，我们识别出在工作流设计的三个层面上于留出搜索中持续存在的效应：以独立求解器和一次性聚合开始的工作流（Star-first）表现更差（Δ = -0.045）；持久共享文档（SharedMemory）优于辩论（Δ = +0.135）；提示词具体性和基于占位符的上下文路由带来的增益与通信结构选择相当（Δ = +0.118）。更广泛地说，我们的流水线和结果表明，将丢弃的搜索轨迹转化为用于发现和验证多智能体工作流设计原则的统计测试平台是可行的。

## Abstract
Designing large language model (LLM) multi-agent systems (MAS) still relies on trial and error and informal "folk wisdom." Manual studies test only a few communication structures or topologies (e.g., sequential, parallel, shared-memory, or debate), while automated optimizers discard search trajectories after selecting a task-specific workflow. We present a two-phase pipeline for mining reproducible design principles from workflow code and execution traces. We repurpose AFlow's MCTS optimizer across six composable operators and 26 deterministically verified Enigmata tasks, retaining all intermediate rounds to build a corpus of 28,568 executable workflows. A sandboxed AutoResearch loop then mines orchestration code and prompt templates under an $L_0$-penalized validation objective and tests candidate principles on held-out searches. Across 300 feature-mining trials, we identify effects that persist on held-out searches across three levels of workflow design: workflows beginning with independent solvers and one-shot aggregation (Star-first) perform worse ($Δ= -0.045$); persistent shared documents (SharedMemory) outperform debate ($Δ= +0.135$); and prompt specificity and placeholder-based context routing yield gains comparable to communication-structure selection ($Δ= +0.118$). More broadly, our pipeline and results show the feasibility of turning discarded search trajectories into a statistical testbed for discovering and validating multi-agent workflow design principles.

## 2. 方法论

### 2.1 总体框架：两阶段流水线
- **采样阶段（Sampling Phase）**：用改造后的 AFlow MCTS 大量生成并评估可执行工作流，**保留全部中间节点**。
- **分析阶段（Analysis Phase）**：用沙箱化的 AutoResearch 循环从工作流源码中自动挖掘特征，拟合回归器，再在留出搜索上做方向性验证。

### 2.2 工作流与环境的形式化
- 工作流 $W=(N, C, \Omega)$ 被实现为两个耦合的 Python 源文件：
  - `graph.py`：编排图（算子组合、参数）；
  - `prompt.py`：各角色提示模板（含 `{problem}`、`{worker_outputs}` 等运行时占位符）。
- 环境 $E=(T,G)$：任务包 $T$（某谜题某难度下 $M=20$ 个实例）＋确定性验证器 $G$；执行后得到性能向量 $m=G(W,T)$，记录**平均验证准确率**与**推理成本（USD）**。
- 语料为三元组 $\mathcal{D}=\{(W_i,T_i,m_i)\}$。

### 2.3 六种可组合算子原语
| 算子 | 通信结构 | LLM 调用数 |
|---|---|---|
| Sequential | 单智能体线性提示链，重复 $r$ 轮 | $\lvert p\rvert\cdot r$ |
| Star | 并行独立 worker → 一次性聚合 | $n+1$ |
| SharedMemory | worker 轮流读写同一持久文档（黑板）→ 聚合 | $n\cdot r+1$ |
| Debate | 全对全提案交换 → 聚合 | $n\cdot r+1$ |
| StarWithCoordinator | 协调者与 worker 迭代式 hub-and-spoke | $(n+1)\cdot r$ |
| DebateWithModerator | 辩论＋每轮主持人干预 | $(n+1)\cdot r$ |

- 参数约束：$n\in[1,10]$ worker，$r\in[1,5]$ 轮，每个工作流最多 20 次原子 LLM 调用。

### 2.4 MCTS 搜索（复用 AFlow）
- 每轮 $N=20$ 步：**选择**（top-$k$，$k=4$，混合均匀/softmax 分布，$\lambda=0.2$，温度 $\alpha=0.4$）→ **扩展**（LLM 优化器 GPT-5.4、温度 0 提出算子增删改与提示改写）→ **评估**（在 20 实例上执行）→ **回传**。
- 每个条件跑 $K=5$ 次独立搜索，**保留全部 20 轮（含失败设计）**。

### 2.5 特征挖掘目标（$L_0$ 正则化验证目标）
- 学习特征提取器 $\phi: W\to\mathbb{R}^d$（解析 `graph.py`/`prompt.py`）、任务描述 $\psi(T)$ 与回归器 $\kappa$，目标函数：

$$F(\phi,\psi,\kappa)=R^2_{D_{\text{val}}}(m,\hat{m})-\lambda\|\phi\|_0,\quad \hat{m}=\kappa(\phi(W),\psi(T))$$

- 其中 $\|\phi\|_0=d$ 惩罚活跃特征数，用于抑制过拟合、鼓励简约。
- AutoResearch 的 LLM 智能体每轮直接编辑 `train.py`（特征工程＋回归脚本），并按提交记录保存 `metrics.json`、`feature_names.json` 等可复现工件。

### 2.6 防泄漏与验证设计
- **搜索级切分**：按 AFlow 搜索（而非工作流）划分 train/val/test（69.4% / 15.0% / 15.6%），保证同一 MCTS 轨迹的 20 轮全部落在同一划分。
- **沙箱隔离**：剥离搜索哈希、MCTS 轮次索引、文件路径；禁止以行标识符、目标派生特征（目标编码、组内目标均值、残差、排序等）作为特征。
- **可预测性门控**：每谜题用 LightGBM 代理模型（200 树、lr 0.05、31 叶、min_child_samples=10）在验证集上评估，要求 $R^2>0.05$ 且 Spearman $\rho>0.30$；阈值经置换零分布校准（零分布 95 分位 $R^2_{p95}\le-0.06$、$\rho_{p95}\le0.23$）。
- **对比估计**：每个谜题内按特征存在/不存在（或按谜题中位数）分高/低臂，估计 $\Delta=\mathbb{E}[\text{score}\mid \text{high}]-\mathbb{E}[\text{score}\mid \text{low}]$；使用以**搜索 ID 为聚类单元**的 cluster-robust Wald 95% CI，并配合 Wilcoxon 检验、二项符号一致性检验与条件性测试验证。

## 3. 实验设计

- **任务与 Benchmark**：Enigmata（合成可验证推理谜题）。共 30 个同时提供生成器与验证器的谜题，覆盖 Arithmetic、Crypto、Graph、Grid、Logic、Search、Sequential 七类；27 个有 Easy/Medium/Hard 三档、3 个（Hitori、LightUp、TicTacToe）仅 Medium/Hard，共 87 个 (puzzle, difficulty) 包。
- **评分方式**：工具无关（无代码解释器、无检索）、无 LLM-as-a-judge，采用**精确匹配的确定性规则验证器**，单实例得分 $\in\{0,1\}$；同一包内固定复用 20 个实例以消除实例抽样噪声。
- **模型配置**：优化器固定 GPT-5.4（温度 0）；worker 与 aggregator 取自 {GPT-5.4-mini, GPT-5.4-nano}（温度 0）。
- **数据清洗**：从 1,740 个网格单元中完成 1,701 次搜索，得 34,020 个候选工作流；剔除 1,031 个（3.0%）不可执行/语法无效者；再剔除 4 个全零的滑块谜题（Eight/Nine/Fifteen/SixteenPuzzle），最终 **28,568 个工作流**。
- **对比基线**：三个单骨干模型（GPT-5.4、GPT-5.4-mini、GPT-5.4-nano）在相同谜题包上的**一次性（无脚手架）通过率**；另以算子有无（w / w/o）做语料内对照（如 SharedMemory 平均 0.23 vs Debate 0.18 vs Star 0.16）。
- **分析规模**：10 次主 AutoResearch 运行（仅 `graph.py` vs `graph.py`+`prompt.py`），共 300 次特征工程试验，产出 **70 个二值化候选对比**，最终 7 个变体在留出测试集上验证。

- **规模**：87 个 (puzzle, difficulty) 单元 × 2 种 worker × 2 种 aggregator × 5 次搜索 × 20 轮 MCTS；10 次 AutoResearch 运行、300 次特征试验、70 个候选对比、7 个最终变体在 13 个通过门控的谜题上做逐谜题检验。
- **消融/对照**：
  - `graph.py` 单独 vs `graph.py`+`prompt.py`（验证 $R^2$ 0.521 → 0.638）；
  - 6 种算子的出现率与得分/成本对照（Sequential 47.2%、Star 44.5%、Debate 22.3%、SharedMemory 20.8% 等）；

- **统计严谨性**：train/val/test 严格按搜索切分、置换零分布校准门控阈值、聚类稳健 CI、Wilcoxon、符号一致性检验、条件性测试验证（$p^{tr}_B\le.035$）。

## 6. 主要结论与发现

- **原则 1（入口拓扑）**：以 Star 作为首个算子的工作流（并行独立求解 + 一次性聚合）表现更差——训练集 7/13 谜题显著为负（中位 $\Delta=-0.036$，$p_W=.008$），留出测试集中位 $\Delta=-0.045$（$p_W=.038$，9/10 条件性符号复现），呼应“无协调的智能体扇出会放大错误”。
- **原则 2（通信状态）**：黑板式 SharedMemory（顺序读写持久文档）优于会话式 Debate——训练 10/13（$\Delta=+0.072$）、测试 6/10（$\Delta=+0.135$，9/10 符号一致）；其语料内平均准确率最高（0.23 vs Debate 0.18、Star 0.16），但成本更高（\$0.25 vs \$0.13）。
- **原则 3（子拓扑提示结构）**：提示模板字符长度高于中位数者带来正增益（训练 11/13，$\Delta=+0.073$；测试 6/13，$\Delta=+0.118$，13/13 符号一致）；`{name}` 占位符数量亦有正效应（测试 $\Delta=+0.059$，11/13 符号一致）。作者明确**不主张字符长度单独具有因果性**，而是强调“提示具体性与上下文路由”的效应量与宏观拓扑选择相当。
- **可预测性**：仅用图特征解释验证 $R^2=0.521$，联合提示特征升至 0.638——说明宏观拓扑只解释部分方差，提示模板丰富度与占位符路由不可忽视。
- **总体结论**：全轨迹挖掘可行且必要；被丢弃的搜索轨迹可转化为发现与验证 MAS 设计原则的统计试验台。

## 7. 优点（方法与实验设计亮点）

- **“全轨迹”视角的范式转换**：把优化器的副产品（含失败与中间设计）当作科学数据，直接针对“argmax 只留一个解”的信息浪费问题。
- **混杂因素控制到位**：工具无关设定消除外部工具与领域知识混杂；确定性验证器消除 LLM-as-a-judge 噪声（$\epsilon_{judge}=0$）；同包固定实例复用使实例抽样方差在配对对比中抵消。
- **泄漏防护体系完整**：搜索级切分、沙箱剥离搜索哈希/轮次索引/路径、禁止目标派生特征，并明确论证选择机制的条件独立性 $S(\phi)\perp\!\!\!\perp m_{\text{test}}\mid a$，使测试集成为真正的样本外复现检验。
- **简约性与多重检验意识**：$L_0$ 惩罚抑制特征膨胀；门控阈值用置换零分布校准，且刻意保守（优先假阴性稳健）。
- **算子词汇表设计可追踪**：六种原语源自 MAS 综述与既有工作，既能组合成复杂拓扑，又使“算子使用”可被结构化统计。
- **可复现性承诺强**：确定性切分哈希、固定种子、冻结依赖、逐提交保存 `metrics.json`/`feature_names.json`/`train.py`，承诺重跑可字节级复现，并公开语料与沙箱分析流程。
- **结果呈现诚实**：同时报告训练/测试两侧的效应量、符号一致率与显著单元数，并主动说明测试集聚类数不足带来的不确定性。

## 8. 不足与局限

- **任务域狭窄**：仅在工具无关、确定性可验证的合成推理谜题（Enigmata）上验证，未覆盖代码仓库级编程、网页导航、游戏、社会模拟等工具交互与开放环境；结论能否外推到真实 agentic 场景未知。
- **单一模型家族**：优化器固定 GPT-5.4，worker/aggregator 仅用 mini/nano，未涉及开源权重模型或其他厂商
