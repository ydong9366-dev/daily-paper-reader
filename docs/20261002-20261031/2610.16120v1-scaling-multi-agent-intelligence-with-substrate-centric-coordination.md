## 摘要
现有基于大语言模型（LLM）的多智能体系统已被证明扩展性较差，我们识别出三个问题：阅读负担随群体规模增长、有用信息被质量未知的共享工作稀释、以及对失败智能体的脆弱性。我们认为这些问题很大程度上源于以智能体为中心的设计：协调结构被固定在工作流、中央协调器或点对点消息传递中，而近期将协调移入共享介质的黑板式方法仅缓解了最后一个问题。为弥补这些差距，我们构建了 ScaleMAS，其中异步智能体通过三种操作与由链接消息组成的共享数据存储交互：发布消息并可选择引用其所基于的早期消息、按内容搜索消息、以及按地址访问消息。搜索最多返回 k 条消息，因此无论群体规模多大，智能体的读取量都保持有界；结果按相关性和被引用频率排序，我们发现后者是质量的有效代理指标；消息在其生产者离开后仍会保留，因此当个别智能体失败时群体仍能继续运作。在四项智能体任务中，ScaleMAS 在更低推理计算下优于以智能体为中心和黑板式基线，可继续扩展至 128 个智能体，并能容忍智能体中途丢失。

## Abstract
Existing large language model (LLM) based multi-agent systems have been shown to scale poorly, and we identify three problems: reading burden that grows with the group, useful information diluted by shared work of unknown quality, and fragility to failed agents. We argue that the problems are largely due to agent-centric designs: the coordination structure is wired into fixed workflows, central coordinators, or peer-to-peer messaging, and recent blackboard-style methods that move the coordination into a shared medium relieve only the last problem. To close the gaps, we build ScaleMAS, where asynchronous agents interact with a shared datastore of linked messages via three operations: publishing messages with optional references to earlier ones that they build on, searching for messages by content, and visiting messages by address. Search returns at most $k$ messages, so an agent's read stays bounded at any group size; results are ranked by relevance and by how often they are cited, which we find to be an effective proxy for quality; and messages persist after their producers leave, so the group carries on when individual agents fail. Across four agentic tasks, ScaleMAS outperforms agent-centric and blackboard-style baselines at lower inference compute, continues to scale up to 128 agents, and tolerates losing agents midway.

## 1. 核心问题与研究动机

- **背景**：基于 LLM 的多智能体系统（MAS）理论上应随智能体数量增加而提升集体能力，但实证研究显示其常出现推理算力超线性增长、收益递减甚至负收益，群体在同等算力预算下可能不如单智能体。
- **三个随规模放大的问题**：
  - **阅读负担增长**：消息传递系统把所有人的输出送给接收者，协调器系统把所有子智能体结果汇入中心上下文，群体越大越容易超出上下文限制。
  - **有用信息被稀释**：即使读取有界，智能体也需在大量质量未知的部分工作中找到少量相关内容，缺乏质量信号。
  - **对失败智能体脆弱**：智能体越多，停滞或崩溃越常见；固定工作流和中心协调器使单个失败可能拖垮整个系统。
- **根源判断**：现有系统采用“智能体中心式”设计，把协调结构写死在工作流、中心协调器或点对点消息传递中。黑板式方法虽将协调移入共享介质，但仅缓解第三个问题，未解决阅读膨胀与质量甄别。
- **核心主张**：应设计“基底中心式”（substrate-centric）协调——协调结构存在于智能体共享的介质中，而非智能体自身；借鉴 Web 的搜索有界阅读与超链接重要性信号。

## 2. 方法论：ScaleMAS

### 2.1 核心思想
构建一个任务无关的智能体基底，由三部分组成：**消息数据存储**、**三种读写操作**、**确定性规则**。N 个异步智能体运行相同 harness 和 prompt，不分配角色、不互相发消息、不指派任务，只与共享数据存储交互。

### 2.2 数据存储
- 数据存储 D 是**只追加**的消息序列，消息永不编辑或删除。
- 每条消息 \(m=(u,a,r,R)\)：子任务描述 \(u\)（用未来检索时会用的措辞书写）、产出物 \(a\)、简短理由 \(r\)、引用集合 \(R\)。
- 引用可指向早期消息或任务工具暴露的资源（如语料片段、仓库文件）；引用形成只在新端增长的**有向无环图**。
- 每条消息有引用权重 \(s_m\in[0,1)\)，用于搜索排序；消息长度按基准限制为 256 或 1,024 tokens，最多 32 条引用。

### 2.3 三种操作
- **publish**：追加消息，立即可被所有智能体读取。
- **search(q)**：按自由文本查询返回最多 \(k\) 条最高排名消息，阅读量有界。
- **visit(m1,…,mj)**：按地址取回指定消息，最多 \(k\) 条。
- 读取结果展示消息四字段、其引用及最近引用它的至多 8 条消息；**不展示作者与引用权重**，读者仅凭内容与链接判断。
- 最终答案以消息形式提交，其引用沿传递闭包构成**证据链**，用于分析正确答来源。

### 2.4 确定性规则
- **写入约束**：所有引用必须指向真实存在对象；理由必须逐一点名每个引用并说明其贡献，否则整条消息被拒收。这把引用从“顺便提及”变成可核查的显式依赖。
- **权重更新**：新消息 \(s_0=0\)；被引用时 \(s_m \leftarrow s_m+\alpha(1-s_m)\)，每步全体权重衰减 \(s_m\leftarrow\gamma s_m\)。被后续工作使用则升权，停止被使用则降权；对任务资源的引用不计权。
- **搜索排序**：
  \[
  \text{score}(q,m)=s_m+\frac{\text{Rel}(q,m)}{\max_{m'\in D}\text{Rel}(q,m')}
  \]
  其中 Rel 采用 BM25；只有检索分正的消息参与排序，平局取更早消息，返回前 \(k\) 条。权重只能重排相关消息，不能使无关消息浮现。
- **效果**：每次读取最多加入 \(k\) 条定长消息，读取量取决于智能体读取频率而非群体规模；重要性由“被他人复用”挣得；消息在生产者离开后仍存在，成员可随时加入/退出。

### 3.1 数据集 / 场景

## 6. 主要结论与发现

- **性能随群体规模增长**：Qwen3.5-9B 下，BrowseComp-Plus 从 38.1%（1 agent）升至 65.3%（16 agents），FATE-M 从 24.0% 升至 56.0%，Contradiction Audit \(x4\) 从 4.1% 升至 29.4%；SWE-bench 在 8 agents 后饱和。
- **计算效率更高**：同等算力下全面优于基线；例如 BrowseComp-Plus 约 20M tokens 时，8 个 ScaleMAS 智能体达 60.0%，而 16 个 DeLM 智能体仅 26.0%；SWE-bench 上 4 个 ScaleMAS 智能体以约一半 token 达到与 8 个 ReAct 相同的 80.0%。
- **智能体轮数下降**：群体越大，单个智能体提交前轮数越少，因可复用他人已发布结果，总工作量增长慢于群体规模。
- **可扩展至 128 智能体**：Contradiction Audit \(x4\) 上持续提升至 50.9%；MAD 在 32 后下降，DeLM 在 128 时低于 8 时。
- **同行引用可自动策展**：被引用最多的消息中 85% 位于正确答案证据链上（最少引用组为 29%）；命名金标证据的消息获得约 2 倍引用。
- **正确答案跨智能体组装**：正确答中使用“他人发现且自己从未打开的金标文档”的比例从 2 agents 的 9% 升至 8 agents 的 24%。
- **容错性强**：一个永久失败智能体存在时，群体表现约等于健康智能体单独运行；dropout 概率 0.8 时仍能工作，而 AOrchestra 在 \(p=0.2\) 时已损失过半。

## 7. 优点

- **问题诊断清晰**：将多智能体扩展失败归因于“智能体中心式”协调结构，并用阅读负担、信息稀释、失败脆弱性三个可操作维度组织全文。
- **设计简洁且任务无关**：仅三种操作与少量确定性规则，不依赖角色分配、工作流或中心协调器，易迁移到不同 harness。
- **有界阅读与质量信号结合巧妙**：用 top-\(k\) 检索限制读取，用“被引用”作为去中心化质量代理，且引用必须可核查，避免空泛引用。
- **鲁棒性内生于设计**：消息持久化、无等待关系，使成员动态变化不破坏系统。
- **实验分析较深入**：不仅报告准确率，还追踪证据链、引用分布、轮数与工具调用变化，并用案例研究展示 relay、纠错、分工等自发协调行为。
- **消融设计有说服力**：引用权重 vs BM25 vs 随机排序的对比，较好证明收益来自引用信号而非单纯检索。

## 8. 不足与局限

- **算力信息缺失**：未报告 GPU 型号、数量与总时长，难以评估绝对成本与实际可复现性。
- **规模上限有限**：最多 128 智能体，且仅部分基准验证；更大规模、更长时程任务未覆盖。
- **仅推理时使用**：未训练智能体学习通过基底协调，方法上限可能受基础模型能力约束。
- **自建基准的偏差风险**：Contradiction Audit 的矛盾由 LLM 注入与判定，可能偏向特定文档风格或“易被检索发现”的矛盾；评分对多余报告不惩罚，可能高估召回导向行为。
- **评价口径**：Pass@N 更接近“群体是否找到答案”，未解决多答案选择与最终提交策略问题；与单智能体比较时，ScaleMAS 单智能体仍带私有基底，存在一定结构性差异。
