## 摘要
基于大语言模型（LLM）的多智能体系统通常依赖预定义的协作结构，限制了其对不断变化的任务需求的适应能力。尽管近期方法能够实现动态编排，但其采用的轨迹级奖励为每个决策分配一个结果，往往难以识别单个结构变化的贡献。我们提出 RoleFlow，一种自演化的多角色智能体系统，通过反馈驱动的原子编辑和按需角色合成来优化协作结构。为使结构自适应可学习，我们引入单编辑反事实策略优化（SECPO），它在同一链状态下将每次编辑与其无编辑对应版本进行比较，并为编辑特定的 token 分配定向信用。在涵盖四个领域的七个基准上，RoleFlow 取得最优平均性能，比最强竞争者高 4.7 分。它在全部三个多跳问答基准上以 3.2–7.5 个 F1 点领先，并在数学推理、网页交互和代码生成方面也展现出领先性。进一步分析展示了跨基准可迁移性、训练数据效率和跨执行器泛化能力。

## Abstract
Large language model (LLM) based multi-agent systems often rely on predefined collaboration structures, limiting their adaptability to evolving task requirements. Although recent approaches enable dynamic orchestration, trajectory-level rewards they apply assign one outcome to each decision, ofen struggling to identify the contributions of individual structural changes. We propose RoleFlow, a self-evolving multi-role agentic system that refines collaboration structures through feedback-driven atomic edits and on-demand role synthesis. To make structural adaptation learnable, we introduce Single-Edit Counterfactual Policy Optimization (SECPO), which evaluates each edit against its no-edit counterpart at the same chain state and assigns targeted credit to edit-specific tokens. Across seven benchmarks spanning four domains, RoleFlow achieves the optimal average performance, surpassing the strongest competitor by 4.7 points. It leads on all three multi-hop QA benchmarks by 3.2-7.5 F1 points and also shows supremacy on mathematical reasoning, web interaction, and code generation. Further analyses demonstrate cross-benchmark transferability, training-data efficiency, and cross-executor generalization.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：基于 LLM 的多智能体系统（MAS）已能通过角色分工协作解决复杂任务，但现有系统（如 ChatDev、Chain-of-Agents、LinearRAG）大多依赖**预先定义或预先优化、执行期间固定不变**的协作结构。
- **核心问题**：面对动态变化的任务需求，多角色智能体系统能否在执行过程中**自主演化其协作结构**（增删角色、调整顺序）？
- **关键障碍**：学习结构自适应面临**信用分配难题**。主流方法（如 GRPO）使用轨迹级奖励，给一次 rollout 内的所有决策分配同一优势值，无法区分"哪一次结构编辑带来了性能提升"。图 1 直观展示了这一矛盾：轨迹级奖励（R−R_mean）会掩盖单次编辑（如 Add Comparator）的真实贡献。
- **论文含义**：将结构演化分解为**可单独评估的原子编辑**，使每次编辑都能获得局部化、可学习的学习信号，从而让系统不仅学会"如何改结构"，更学会"哪些结构改动值得做"。

## 2. 方法论

### 2.1 核心思想
- 将协作结构的演化视为一系列**原子编辑**，每次编辑与其**同一链状态下的无编辑反事实**对照，隔离该编辑的即时贡献。
- 采用**单编辑/周期**设计，保证相邻链条最多相差一个编辑，避免多编辑相互混淆。

### 2.2 RoleFlow 执行循环
- **组件**：可训练的 Global Router（GR，Qwen2.5-7B-Instruct）+ 角色库 R + 冻结的执行器 LLM（gpt-4o-mini）+ 任务验证器 V。
- **链结构**：RoleFlowChain 是角色有序序列，默认以 Planner 开头、Validator 结尾；每个角色接收任务及前序角色输出。
- **编辑算子** E：`ADD(ρ)`（末尾前插入）、`PRUNE(ρ)`（删除）、`SWAP(ρ,ρ′)`（原位替换）、`REROUTE(p,q)`（交换位置）、`∅`（空编辑）。
- **流程**：cycle 0 执行初始链 → 验证器返回 (h_t, s_t, d_t) → 若被拒，GR 基于 deficit 与 scratch memory 提出一个编辑 → 执行新链；最多 T_max=3 个适应周期，即推理时最多 1+T_max 次链执行。

### 2.3 SECPO（单编辑反事实策略优化）
- **同状态反事实优势**：固定当前链状态（链 + 记忆 + 角色库），分别执行"带候选编辑"与"不带编辑"两次，得到
  - `A_i^(t) = R(y+_{i,t}) − R(y0_{i,t})`
- **编辑提交门控**：仅当 `A_i^(t) > δ`（δ=0.005）才在训练中保留该编辑，否则置为空编辑；但反事实对仍参与策略更新。
- **编辑 token 级优势**：在 GR 计划 token 中，仅对拼写该编辑的 token span E_i^(t) 叠加编辑优势：
  - `Ã_ℓ = A_ℓ^GRPO + λ·1[ℓ ∈ E_i^(t)]·A_i^(t)`（λ=1）
  - 不同周期的 span 不重叠，其余 token 保留 GRPO 优势。
- **策略优化**：使用 PPO 裁剪目标 + KL 正则化（β=0.001，ε=0.2），对 K=5 条 rollout 的计划 token 求平均。

### 2.4 角色合成与库增长
- **按需合成**：GR 命名但库中不存在的角色，由 LibraryExpander 根据角色名、任务与 deficit 合成规格，存入该 rollout 的临时 overlay `R̂(i)`。
- **deficit 驱动合成**：若 GR 在有 deficit 时仍提出空编辑，则强制合成针对该 deficit 的新角色并执行 ADD。
- **返回门控入库**：训练步结束后，合成角色仅当其 rollout 回报超过同批参考 rollout 时，才进入共享库 R（式 6）。推理时只使用领域种子库，不加载训练增长的库。

## 6. 主要结论与发现

- **整体最优**：RoleFlow 七基准平均

- **整体最优**：RoleFlow 在 7 个基准上的平均表现优于手工流水线、自动化工作流搜索、训练型执行器与训练型编排器四类基线，并在 HotpotQA、MATH-500、MBPP、WebShop 等分布内任务上取得领先或接近领先的结果；在 2Wiki、MuSiQue、HumanEval 等未参与训练的 OOD 基准上同样保持优势，说明其收益并非仅来自对特定任务链的过拟合。
- **结构自适应的必要性**：消融结果显示，移除 Global Router 或固定初始链后性能明显下降，表明“执行中按 deficit 触发一次原子编辑”的机制本身贡献了主要增益；仅依赖更强的执行器或更多角色并不能替代结构演化。
- **SECPO 的信用分配有效**：在相同或受控训练预算下，SECPO 优于轨迹级 GRPO、COMA-Operator 以及仅做编辑 token 归因的变体。说明“同链状态下的无编辑反事实 + 编辑 token 级优势叠加”能够把稀疏的轨迹奖励转化为可学习的局部信号，是 RoleFlow 性能提升的关键组件之一。
- **单编辑周期设计更稳**：多编辑变体（每周期允许 ≤2 或 ≤4 次编辑）并未稳定优于单编辑版本。作者将其部分归因于训练—测试不匹配：训练时允许多编辑、推理时仍按单编辑周期执行；同时也说明多编辑会重新引入编辑间混淆，削弱反事实优势的隔离性。
- **角色库与按需合成有价值**：禁用角色库或禁用专家角色后性能下降；使用“通用规格专家”替代按需合成专家时表现次之，表明角色库不仅提供候选角色，角色规格与任务 deficit 的对齐程度也会影响编辑质量。返回门控入库机制有助于避免低质量合成角色污染共享库。
- **效率与性能存在权衡**：SECPO 因反事实对照需要额外链执行，训练与推理成本高于普通 GRPO/固定链方案；Fig. 5 显示 RoleFlow 在 API 成本—F1 曲线上处于较有利位置，但并非无条件“更便宜”。其优势更多体现为：在相近成本档位下获得更高性能，或为达到同等性能所需训练数据更少。
- **跨执行器具有一定泛化性**：将执行器从 gpt-4o-mini 替换为 Qwen3-8B/32B、Llama-3.1-8B 后，RoleFlow 仍保持相对优势，说明学到的路由与编辑策略并非完全绑定于单一执行器；但绝对性能与增益幅度随执行器能力变化，强执行器下结构自适应的边际收益可能收窄。
- **案例层面可解释**：附录案例显示，系统能够针对具体失败模式提出如 Add Comparator、Prune 冗余角色、Swap/Reroute 调整顺序等编辑，且编辑与 deficit 之间存在可读的对应关系；这为“结构演化”提供了定性证据，但案例选择仍属示意性，不能替代大规模统计检验。

## 7. 局限与风险

- **反事实成本**：SECPO 每个训练问题需额外执行无编辑对照链，训练链执行次数与 token 消耗均高于 GRPO；虽然论文报告了相对开销，但未给出完整墙钟时间与端到端推理成本明细。
- **单编辑粒度的长程限制**：每周期仅允许一次编辑，有利于信用隔离，但可能限制需要多步协同修改才能见效的结构调整；多编辑版本又面临信用混淆与训练—测试不一致问题，二者之间的最优粒度尚未充分解决。
- **验证器依赖**：执行循环依赖任务验证器返回成功信号与 deficit 描述；验证器噪声、deficit 表述质量会直接影响编辑提议与门控。论文未系统评估验证器误差对结构演化的影响。
- **训练—推理角色库不一致**：训练中可增长共享角色库，但推理时仅使用领域种子库、不加载训练增长库。该设计虽控制推理分布，却可能使训练期学到的“库增长收益”无法在推理端完全兑现，二者一致性仍可进一步研究。
- **超参数敏感性**：编辑提交阈值 δ、KL 系数、周期上限 T_max 等对成本与稳定性有影响；论文给出默认设置，但未展示完整的敏感性曲线。
- **基线复现偏差**：部分自动化工作流搜索与训练型编排器基线依赖复现或自建训练集，尽管统一了执行器与评测协议，仍不能完全排除实现差异带来的比较偏差。

## 8. 启发与可复现性评价

- **方法启发**：论文的核心贡献可概括为“把结构演化拆成可单独评估的原子编辑，并用同状态反事实隔离即时贡献”。这一思路不限于多智能体角色链，也可迁移到工具调用序列、记忆读写策略、检索管道拓扑等“离散结构决策”的信用分配问题。
- **实验规范**：主实验覆盖 4 领域 7 基准，包含分布内与 OOD、统一执行器、多次运行均值±标准差，并配套消融、信用信号对比、效率与跨执行器分析，整体证据链较完整。
- **可复现性**：论文给出了训练框架（verl）、硬件（4×H200）、主要超参数、编辑算子与 SECPO 目标形式，复现关键要素较清楚；但训练总时长、完整成本明细、验证器实现细节与部分基线复现配置仍需依赖附录或代码发布。
- **总体判断**：RoleFlow 在“让多智能体协作结构在执行中自主演化”这一问题上给出了较自洽的训练框架与较充分的实证支持；其主要价值不在于提出更复杂的拓扑搜索空间，而在于为离散结构编辑提供了可学习的局部信用信号。若能进一步降低反事实成本、处理多编辑信用隔离，并统一训练/推理角色库策略，该方向的实用性与扩展性会更强。
