## 摘要
多智能体系统正越来越多地部署于复杂知识工作，但其编排层在很大程度上仍是无记忆的：每个新任务都从头开始分解、分配和执行，无法从先前成功的执行中获益。我们提出 WorkflowOps，一种多智能体工作流编排框架，它从历史工作流中学习智能体协作先验，并按需扩展其智能体池以覆盖新的能力需求。我们的方法引入了三个相互耦合的机制。首先，转移概率矩阵从过去的工作流中捕获成对智能体协作频率，并在 DAG 工作流构建过程中通过层内排序优化、概率阈值化边建议以及用于最大化并行性的传递归约，将其作为软引导应用。其次，充分性驱动的智能体创建循环通过语义匹配分数检测能力缺口，通过 LLM 生成专用智能体，并同时将它们注入协作矩阵，从而使新创建的智能体能够立即结合预测的协作先验使用。第三，分层语义匹配策略使用预训练句子嵌入进行快速、确定性的能力匹配作为第一遍，仅对低置信度情况调用 LLM 验证，从而相比纯 LLM 方法将 LLM 路由调用减少 80% 以上。在代码、数学和问答混合套件上的实验表明，WorkflowOps 相比近期的工作流构建基线提高了端到端通过率，并且在结构化、可分解任务上收益最大，因为这些任务中过去的智能体交接模式可以迁移。

## Abstract
Multi-agent systems are increasingly deployed for complex knowledge work, yet their orchestration layers remain largely memoryless: each new task is decomposed, assigned, and executed from scratch with no benefit from prior successful executions. We present WorkflowOps, a multi-agent workflow orchestration framework that learns agent collaboration priors from historical workflows and expands its agent pool on demand to cover new capability requirements. Our approach introduces three coupled mechanisms. First, a transition probability matrix captures pairwise agent collaboration frequencies from past workflows and applies them as soft guidance during DAG workflow construction through intra-layer ordering optimization, probability-thresholded edge suggestion, and transitive reduction for parallelism maximization. Second, a sufficiency-driven agent creation loop detects capability gaps via semantic matching scores, generates specialized agents through an LLM, and simultaneously injects them into the collaboration matrix, so that newly created agents are immediately usable with predicted collaboration priors. Third, a layered semantic matching strategy uses pre-trained sentence embeddings for fast, deterministic capability matching as a first pass, invoking LLM verification only for low-confidence cases, thereby reducing LLM routing calls by over 80\% compared to pure-LLM approaches. Experiments on mixed code, math, and question-answering suites show that WorkflowOps improves end-to-end pass rates over recent workflow-construction baselines, with the largest gains on structured, decomposable tasks where past agent handoff patterns transfer.

## 2. 方法论

### 2.1 核心思想
WorkflowOps 是一个**历史条件化（history-conditioned）的编排框架**，维护三类持久状态：协作先验矩阵 P、可演进的智能体池 A、语义能力索引。整体将工作流构建形式化为**在依赖合法 DAG 上的近似约束优化**：

- 目标函数：`Q(W, π, A′) = α·Align(W,P) + β·Suff(π) + γ·Par(W)`
  - **Align**：工作流边上的转移概率均值（与历史协作模式的一致性）；
  - **Suff**：子任务–智能体匹配得分均值（能力覆盖度）；
  - **Par**：`|S| / depth(W)`（结构并行度）。
- 约束：保留硬任务依赖、保持无环、智能体池只允许**单调扩展**（A′ ⊇ A）。
- 论文明确该目标作为**设计原则**而非全局求解，通过分阶段流程近似实现。

### 2.2 三大耦合机制

**（1）转移概率矩阵（一阶马尔可夫协作先验）**
- 定义：`P_ij = count(a_i → a_j) / Σ_k count(a_i → a_k)`，行随机，统计历史工作流中智能体相邻调用的频率。
- 部署中从约 **65 个合成工作流**（覆盖 8 个任务域）引导构建，得到 **35×35**、约 **20% 非零**的稀疏矩阵；构建仅需一次计数遍历，查询 O(1)，内存 O(N²)，仅几 KB。
- **三重作用**：
  - **(a) 层内排序优化**：同一拓扑层内，按与上一层智能体的转移概率降序排列，优化信息流顺序；
  - **(b) 概率阈值化边建议**：对无显式依赖的子任务对，若 `P_π(si),π(sj) ≥ θ` 且满足拓扑序（depth(si) < depth(sj)），则添加**软边**；
  - **(c) 传递归约**：若 (u,v)、(v,w) 与 (u,w) 同时存在，删除直连边 (u,w)，以最大化并行度。
- **动态更新**：新智能体创建时，由 LLM 预测其前驱/后继，注入 P 的对应行与列并重新归一化，使新智能体“即刻可用”。
- **为何用软引导而非硬约束**：矩阵仅约 20% 密度，硬约束会阻断合法但历史上未见过的工作流；依赖结构始终不可被覆盖；新任务模式仍应可表达。

**（2）充分性驱动的智能体池扩展**
- 定义匹配得分 `ϕ(s_j, a_i) = cos(f_enc(c_j), e_i)`，充分性阈值 τ；缺口集合 `G = {s_j | ϕ(s_j, π(s_j)) < τ}`。
- 循环流程（Algorithm 2）：构建匹配索引 → 计算最优分配 → 识别缺口 → 对每个缺口子任务（可选 LLM 充分性校验）→ LLM 生成专用智能体 → 持久化到磁盘 → 加入池 → LLM 预测协作者 → 注入并归一化 P。
- **需求驱动**：仅在检测到可度量能力缺口时创建，避免池膨胀（对比 AOrchestra 对每个任务都创建）。
- **安全机制**：最大轮数 R（默认 3）、子任务去重保护、单次运行最大创建数（默认 4）。
- **生命周期**：支持探索（自由演化）、受控（定期整理）、冻结（生产版本锁定）三种模式。

**（3）分层语义匹配**
- **第一层**：Sentence-BERT（all-MiniLM-L6-v2，384 维）余弦相似度，确定性、零 LLM 成本、批矩阵乘法亚毫秒级；智能体嵌入预计算缓存。
- **第二层**：仅当最佳匹配分低于 τ 时，调用 LLM 做充分性验证。
- **复杂度对比**：纯 LLM 路由需 K×N 次 LLM 调用（如 K=5、N=35 即 175 次）；本方法仅需 K×N 次向量运算 + 至多 K′×1 次 LLM 调用（K′ ≪ K），**减少 80% 以上路由 LLM 调用**。

### 2.3 分层并行执行
- 按拓扑层执行，同层节点无依赖、可并发；下游节点接收单前驱输出或多前驱的**合并消息**（fan-in merge，保留来源标注与 artifact 并集）。
- 统一 `AgentMessage` schema，避免异构消息格式的成对适配问题。
- 错误传播策略：单步失败生成 error 类型消息并向下传播，优先保证可追溯与部分结果，而非立即中止。
- 提供 Linear 对照模式（相同分解与分配，但串行执行），用于受控比较。

## 6. 主要结论与发现

- **Mixed 测试集**：WorkflowOps（DAG）达 **0.890**，比最强查询级基线 MetaAgent（0.751）高 **13.9 个百分点**，比最强任务级基线 ADAS（0.694）高 **19.6 个百分点**；Linear 模式 0.870。
- **Mixed_Hard**：达 **0.770**，超过所有完整完成的基线至少 **15 个百分点**，比 ADAS 最强部分结果高 4 个百分点；分项为 MATH 0.850、CODE 0.780、QA 0.700。
- **分类别表现**：CODE 提升最大（Linear 0.940 / DAG 0.960，领先基线 40+ 分）；MATH 与 MetaAgent 打平（0.940）；**QA 是弱项**，MetaAgent 领先 4–8 分。
- **DAG vs. Linear**：Mixed 上 DAG 提升 2 分（集中在 CODE 与 QA）；Mixed_Hard 上两者相差 1 分以内，说明高难度任务更依赖稳健分配与能力覆盖，而非额外 DAG 结构。
- **显著性**：Mixed 上 DAG vs. MetaAgent 的差距 p < 0.001，主要由 CODE 驱动；MATH 统计打平，QA 边际偏向 MetaAgent。
- **消融结论**：
  - 移除转移矩阵：下降 **4.5–5.0 分**；
  - 禁用智能体演化：下降 **1.7 分**，但调用与 token 大幅下降（7.8 calls / 15.9k tokens vs. 14.8 / 43.6k，即 1.9× 调用、2.7× token 换 +1.7 分）；
  - 用 TF-IDF 替代语义嵌入：下降 **8.5–13.0 分**（最大单因素）；
  - 纯 LLM 匹配：更贵且更不准（因绕过了智能体创建循环）；
  - 边阈值 θ 在默认 0.3 附近峰值，0.5 紧随其后。
- **核心论断**：提升并非来自单一主导组件，而是**语义匹配（最大因素）+ 转移先验（稳定增益）+ 有界池扩展（以成本换小幅精度）+ DAG 结构（近等墙钟时间的适度增益）**的耦合；简单频率统计即可作为有效的、无需训练的编排操作先验。

## 7. 优点

- **问题定位精准**：抓住“编排层无记忆”这一被忽视但实际的瓶颈，提出持久化编排状态的三要素框架。
- **方法轻量且可解释**：转移矩阵仅靠频率计数，无需梯度训练，可解释、可增量更新、在无历史时优雅退化；矩阵接口还可无缝替换为矩阵分解/神经补全等更强方法。
- **机制耦合设计巧妙**：新智能体创建后**立即注入协作矩阵**，解决了“新角色需多次执行才能积累转移统计”的冷启动问题，这是相对 AOrchestra 等工作的关键差异。
- **成本意识强**：分层语义匹配将路由 LLM 调用减少 80%+，并以 K=5、N=35 的具体算例说明从 175 次降至约 1 次验证调用；明确将“是否启用池扩展”作为部署旋钮。
- **工程完备性**：统一消息协议、fan-in 合并、错误传播、审计日志、智能体卡片 schema、三种生命周期模式，具备从实验到企业部署的治理路径。
- **实验规范度较高**：报告 bootstrap CI、p 值、Cohen's h 效应量；消融严格控制变量；同时报告精度与效率（调用/token/延迟）。

---

## 8. 不足与局限

**方法层面（作者自述）：**
- **仅一阶马尔可夫**：只建模成对相邻交接，无法表达重复智能体序列等高阶协作模式；
- **智能体创建依赖 LLM 生成质量**：规格不佳的

- **智能体创建依赖 LLM 生成质量**：规格不佳的智能体可能被写入池中，而池只允许单调扩展、缺少淘汰机制，长期运行存在“低质量智能体沉积”的风险；
- **矩阵规模随池增长而平方增长**：虽然当前 35×35 仅几 KB，但若池扩展到数百个智能体，O(N²) 存储与稀疏度下降会影响先验的可解释性与有效性；
- **阈值（τ、θ）为经验设定**：τ = 0.45、θ = 0.3 未经系统性敏感性分析（仅对 θ 做了粗粒度扫描），跨域迁移时需重新调参；
- **并行度与合并语义的简化**：fan-in 采用 artifact 并集 + 来源标注，未处理多前驱输出之间的**冲突消解**（如相互矛盾的中间结论），也假设同层节点无副作用、可安全并发。

**实验层面：**
- **单 backbone 验证**：全部实验基于 gpt-5，未检验方法在较弱模型（如开源 7B–70B）上的收益是否保持——考虑到语义匹配与 LLM 校验均依赖模型能力，跨模型泛化性未知；
- **历史先验的构建依赖合成工作流**：初始矩阵来自约 65 个合成工作流，而非真实生产轨迹，可能低估（或高估）真实协作分布的迁移价值；
- **缺少与“检索式”基线的对比**：如“检索相似历史工作流并直接复用/改写”这类直观的强基线未被纳入，难以判断持久化矩阵相对朴素 RAG 式复用的净增益；
- **QA 弱项未被深入剖析**：仅报告 QA 落后 MetaAgent 4–8 分，未分析原因（是分解粒度、还是多跳检索类任务不适合当前 DAG 结构）；
- **长尾与鲁棒性缺失**：无失败案例分析、无对抗/分布外输入测试、无多次运行的方差报告（仅单次评测 + bootstrap 重采样）。

**部署与治理层面：**
- **成本未量化**：只给调用数与 token 数，未折算为实际费用；DAG 并发的资源峰值（16 worker）在真实服务中的调度开销未讨论；
- **安全与合规**：LLM 自动生成的智能体可能引入提示注入、越权工具调用等风险，论文的“生命周期模式”提供了治理接口，但未给出具体的安全审计机制；
- **可复现性**：核心超参、提示模板、智能体卡片的完整定义若未随附录公开，矩阵初始化与演化路径难以精确复现。

## 9. 启示与可拓展方向

- **先验的阶数升级**：将一阶转移矩阵扩展为二阶/变阶马尔可夫或轻量序列模型（如条件频率 + 低秩分解），可在保持 O(1) 查询的同时表达“A→B→C”式固定套路；论文亦指出矩阵接口可替换为矩阵分解或神经补全。
- **从“只增不减”到“优胜劣汰”**：为智能体池引入基于使用频次、成功率、下游贡献的**衰减/归档机制**，与单调扩展约束形成张力平衡，避免池污染。
- **冲突感知的 fan-in**：在多前驱合并处加入一致性检查或 LLM 仲裁，把“并集”升级为“共识/择优”，可提升 QA 类多跳任务的可靠性。
- **在线学习闭环**：把执行结果（成功/失败、人工反馈）回流为矩阵的加权更新（而非纯计数），使先验从“历史频率”走向“历史效果”。
- **跨 backbone 与跨规模验证**：在开源模型上复测，检验“语义匹配是最大增益因素”这一结论是否稳健；若弱模型下 LLM 校验成本上升，分层匹配的性价比可能更突出。
- **与检索增强的结合**：将“检索相似历史工作流”作为矩阵先验的补充信号，形成“显式模板复用 + 隐式统计引导”的双通道编排。

## 10. 总体评价

WorkflowOps 的价值主要不在单点算法创新，而在于**把一个被普遍忽视的系统层问题——编排层缺少持久记忆——清晰地问题化，并给出一套轻量、可解释、可增量演进的工程化解法**。其技术选择高度克制：频率计数代替训练、软边代替硬约束、分层匹配代替全量 LLM 路由、需求驱动代替无差别创建，每一项都对应明确的成本–收益权衡，并以消融实验量化了各机制的边际贡献（语义匹配 > 转移先验 > 池扩展 ≈ DAG 结构）。

在证据强度上，论文的实验规范度（CI、p 值、效应量、效率指标）优于多数同类工作，Mixed 上 +13.9 分对最强查询级基线的提升具有说服力；但基线在 Mixed_Hard 上的不完整运行、单 backbone 设定、以及缺少检索式强基线与失败分析，使其结论的**外部有效性**仍需后续工作补强。此外，“池只增不减”“一阶马尔可夫”“无冲突消解”等简化在短期实验规模下可接受，但在长期生产部署中会成为主要风险点。

总体而言，这是一篇**问题定义清晰、方法务实、工程完成度高、实验基本可信但仍有公平性与泛化性缺口**的系统性工作；它更适合被定位为“编排层记忆化”这一方向的**奠基性框架与强基线**，而非终局方案——其矩阵接口、生命周期治理与成本旋钮，为后续在阶数、淘汰机制、在线学习与安全审计上的扩展留下了清晰的接口。
