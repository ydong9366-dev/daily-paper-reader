## 摘要
大语言模型（LLM）智能体正成为自主无线网络操作的规划器。然而，当支持遥测数据过期或不一致时，在提议时正确的任务答案在执行时可能仍不安全。现有基准主要从固定观测评估任务解决，而未测试执行时的支持检查。我们提出了 WirelessOptBench，一个用于无线操作中动作保障的基准。它将无线任务转化为具有受控遥测故障和动作约束的执行状态决策片段。我们进一步开发了 WirelessOpsAgent，它使候选动作建立在当前证据之上，并在执行前修复可恢复的支持失败。在三种骨干模型的评估中，每种包含 600 个片段，WirelessOpsAgent 达到最高 0.983 的精确动作准确率。在 Claude Sonnet 4.6 上，相对于最安全的基线，不安全 APPLY 率从 82.2% 降至 10.3%。我们已在 https://anonymous.4open.science/r/wirelessopsbench-artifact-D969/ 提供 WirelessOptBench。

## Abstract
Large language model (LLM) agents are emerging as planners for autonomous wireless network operations. Yet a task answer that is correct at proposal time can still be unsafe at execution time if supporting telemetry is stale or inconsistent. Existing benchmarks mainly evaluate task solving from fixed observations and leave support checking at execution time untested. We introduce WirelessOptBench, a benchmark for action assurance in wireless operations. It turns wireless tasks into execution state decision episodes with controlled telemetry faults and action constraints. We further develop WirelessOpsAgent, which grounds candidate actions in current evidence and repairs recoverable support failures before execution. Across three backbone evaluations with 600 episodes each, WirelessOpsAgent achieves up to 0.983 Exact Action Accuracy. On Claude Sonnet 4.6, the Unsafe APPLY Rate decreases from 82.2% to 10.3% relative to the safest baseline. We make WirelessOptBench available at https://anonymous.4open.science/r/wirelessopsbench-artifact-D969/.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：大语言模型（LLM）智能体在自主无线网络操作中，往往基于固定观测数据生成任务答案，但这些答案在“提议时正确”并不等于“执行时安全”——如果支持的遥测数据在提议与执行之间过期、不一致或不完整，那么看似正确的决策可能在实际执行时导致不安全操作。
- **现有基准的不足**：已有基准（如 WirelessAgent、WirelessBench、NetConfEval 等）主要评估智能体从固定观测中求解任务的能力，即“能否算出正确答案”，而未测试“答案在执行时是否仍受当前网络证据支持”，即缺少对执行边界的评估。
- **本文提出的解决思路**：将“任务求解”（task solving）与“动作授权/保障”（action assurance）明确分离，引入面向无线操作的执行状态决策基准（WirelessOptBench）和安全智能体架构（WirelessOpsAgent），确保候选动作在进入控制平面之前完成证据核查、故障修复和重新验证。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

### 2.1 WirelessOptBench 基准

- **目标**：把三类无线任务（WCHW 无线知识计算、WCNS 5G 网络切片、WCMSA 移动性服务保障）转为“执行状态决策片段”（execution-state decision episodes），每段由以下组成：
  - 固定任务与参考答案；
  - 观察账本（observation ledger）：暴露字段元数据和依赖关系；
  - 执行契约（execution contract）：规定执行前必须满足的字段和网络约束；
  - 压力实现（stress realization）：受控的遥测故障，如 schema/unit、freshness/order、availability/brownout、conflict/provenance、mixed evidence 五种类型；
  - 规则参考动作（reference action）：由有序策略产生，包括 APPLY/HOLD/RETRY/ESCALATE（ABSTAIN 为备用但非参考动作）。

- **无线执行模型**：通过 SINR、速率、带宽预算、QoS 最低速率、RSRP 切换条件等无线约束，结合遥测字段的时效性约束（如 field age ≤ freshness limit），判断动作是否可安全执行。

- **评估协议**：基于可复放的决策记录（决策、效用、状态、记录四个维度），指标包括 Exact Action Accuracy、Safe APPLY Recall、Unsafe APPLY Rate、Task Score、OPS 等。

### 2.2 WirelessOpsAgent 智能体架构

- **两阶段闭环保保障**：
  1. **输入绑定（input binding）**：将公开观测数据固化为不可变账本，构建保留来源的规范化视图，供模型生成提案。
  2. **输出授权（output authorization）**：将模型输出视为“提案”，把关键字段绑定到其证据依赖，执行完整性诊断、有界修复、重新验证，最终由动作治理器（action governor）决定 APPLY/RETRY/HOLD/ESCALATE/ABSTAIN。

- **决策链接证据图**：三个关联视图——原始状态、规范化状态、决策状态；每个关键字段记录值、schema、单位、来源 ID、溯源、事件时间、接收时间、新鲜度限制、质量状态与父节点 ID，形成从原始观测到候选动作的完整证据图。

- **类型化完整性诊断**：每个关键字段在时间 t 通过五项布尔检查：
  \( Valid(k,t) = SchemaOK(k) ∧ UnitOK(k) ∧ SourceOK(k,t) ∧ Fresh(k,t) ∧ ConflictFree(k,t) \)
    - Schema/Unit 检查支持别名与兼容单位转换；
    - 时间检查结合事件到接收年龄、新鲜度限制、状态版本顺序和有界时钟偏移；
    - 溯源检查要求每个字段或修复操作可解析到现有账本来源；
    - 冲突检查拒绝未解决的分歧或旧事件覆盖新信任值。

- **依赖范围的有界恢复**：
  - 只对失败字段及其在证据图中的后代进行修复：\( D_t = B_t \cup Desc_{G_t}(B_t) \)；
  - 修复接受条件：所有变更字段有证据支持、通过重新验证、不降低任务效用：\( Accept(x'_t) = Supported_t ∧ \bigwedge_{k∈D_t} Valid(k,t+1) ∧ [V(d'_t) ≥ V(d_t)] \)；
  - 清洁字段保持冻结，旧证据覆盖新证据被视为不安全覆盖并计入违规；
  - 记忆（memory）被视为不可信来源，仅在当前工具缺失关键字段时使用且须通过相同检查。

- **风险感知授权**：Ready 状态须满足字段有效、网络约束通过、授权记录完整；有序策略从 APPLY 到 ESCALATE、RETRY、HOLD、ABSTAIN 依次判定。

## 3. 实验设计：数据集、基准、对比方法

- **基准规模**：WirelessOptBench 共 600 个片段，从三个任务族（WCHW、WCNS、WCMSA）各取 200 个基准项，每族包含 5 种压力类型各 40 个片段；标签分布为 200 APPLY、100 HOLD、100 RETRY、200 ESCALATE。
- **方法对比**：
  - **Direct**：单次生成，无额外检查；
  - **WirelessAgent++ + contract**：官方流程 + 显式动作契约；
  - **CRITIC style**：工具交互式批判修正；
  - **WirelessOpsAgent**（本文方法）。
- **骨干模型**：GPT-5.4-mini、Qwen3-8B、Claude Sonnet 4.6，每个方法在每个骨干上各跑 600 个片段。
- **消融实验**：在 GPT-5.4-mini 上进行 7 组消融，包括移除完整性监控器、移除动作治理器、无效用修复、无 schema/unit 规范化、无冲突与新鲜度检查等。
- **条件诊断**：按压力类型分域统计路由结果和表现。

## 6. 论文的主要结论与发现

- **动作准确率大幅提升**：WirelessOpsAgent 在三个骨干上达到 0.972–0.983 的精确动作准确率，而最强基线仅为 0.707。
- **不安全执行显著下降**：Unsafe APPLY Rate 降至 7.8%（GPT-5.4-mini）、17.2%（Qwen3-8B）、10.3%（Claude Sonnet 4.6）；在 Claude Sonnet 4.6 上，相对 CRITIC 基线降低 71.9 个百分点。
- **安全进展未受损**：Safe APPLY Recall 最高达 72.5%，完全优于基线（最高仅 25.5%），说明低不安全率并非来自“一律拒绝”的保守策略。
- **修复机制有效**：修复后所有骨干上的假阳性 APPLY（blocking 片段中）降为 0，同时保持 96%–99.5% 召回率；且零不安全覆盖。
- **差异路由合理**：Freshness/order 故障主要路由到 HOLD，availability/brownout 到 RETRY，conflict/provenance 到 ESCALATE。
- **消融说明组件各自不可或缺**：移除完整性监控或动作治理器导致 Macro F1 从 0.972 跌至约 0.22、Unsafe APPLY 升至约 0.69；无效用修复时安全召回从 0.725 跌至 0.245。

## 7. 优点

- **问题切入点新颖且重要**：把“任务正确性”和“执行支持”分离开，聚焦真实网络运维中遥测超过时效/不一致导致的不安全执行边界，具有很强的实践价值。
- **基准设计精细**：固定任务与答案、变化执行状态，构造 600 段受控故障片段，五种压力域覆盖典型遥测故障类型；策略化标签、双 oracle 一致性和审计性设计增强了可信度。
- **智能体架构具有工程实用性**：证据图、类型化诊断、依赖范围修复、风险感知授权形成完整闭环；支持别名规范化与单位转换，不误伤合法修复；记忆被降权为不可信来源，避免特权缓存。
- **评估指标多层次**：区分任务质量（Task Score）、执行就绪（OPS）、动作准确率（Exact Action Accuracy）、安全应用召回率（Safe APPLY Recall）和不安全率（Unsafe APPLY Rate），避免单一指标掩盖问题。
- **实验覆盖面广且可复现**：多骨干、多任务族、多条件域、消融与失量分析一起给出，并提供可复放的授权记录。

## 8. 不足与局限

- **非生产部署研究**：WirelessOptBench 是受控基准，压力域是人为设计的故障频率，不代表真实网络中故障分布或完整故障目录。
- **假设遥测元数据正确**：WirelessOpsAgent 依赖暴露的遥测元数据与溯源字段的正确报告，若遥测本身在 source 端被篡改或错误上报，保障效果可能失效。
- **未覆盖安全与并发控制**：执行器安全（actuator security）和并发控制不在本文评估范围内，实际部署还有额外边界条件。
- **conflict/provenance 域评分存在混淆**：评审后审计发现非实质性硬负例被计为冲突，导致该域 Unsafe APPLY 指标被高估（0.325），作者已明确将该域从相关结论中排除，但保留冻结评分以维持可复现性。
- **骨干范围有限**：只有 3 个骨干模型且消融仅在 GPT-5.4-mini 上执行，泛化性证据偏窄。
- **没有披露算力消耗**：未给出推理成本、时延或 API 开销，对实际部署的工程参考有限。
