## 摘要
自主移动GUI智能体需要准确的行动反思以确保可靠的长程执行。现有方法在每个动作后进行开放式多模态推理，成本高昂且与GUI状态转换的结构化特性不匹配。我们提出StepReflect，将每步GUI反思形式化为基于显式转换规范与配对视觉证据的监督结构化预测。StepReflect通过结合监督微调、师生蒸馏以及偏好与奖励优化的分阶段流水线进行训练。离线阶段，所得8B模型在AndroidWorld上达到82.16%的转换级准确率，在相同结构化输入下超过零样本GPT-5.2达11.83个百分点。在线阶段，在M3A、Agent-SAMA、MAI-UI-8B和Seed-2.0-Pro上，StepReflect在四种智能体配置中的三种实现了更高的任务成功率，并在第四种配置中保持在一个成功任务之内。同时，在所有四种配置中，相比基于GPT的反思，StepReflect减少了付费API费用。这些结果使StepReflect成为长程移动GUI智能体替代反复使用前沿模型进行反思的实际且可本地部署的选择。

## Abstract
Autonomous mobile GUI agents require accurate action reflection for reliable long-horizon execution. Existing approaches rely on open-ended multimodal reasoning after each action, which is costly and poorly matched to the structured nature of GUI state transitions. We propose StepReflect, which formulates per-step GUI reflection as supervised structured prediction conditioned on explicit transition specifications and paired visual evidence. StepReflect is trained through a staged pipeline combining supervised fine-tuning, teacher-student distillation, and preference- and reward-based refinement. Offline, the resulting 8B model achieves 82.16% transition-level accuracy on AndroidWorld, exceeding zero-shot GPT-5.2 by 11.83 percentage points under the same structured input. Online, across M3A, Agent-SAMA, MAI-UI-8B, and Seed-2.0-Pro, StepReflect achieves higher task success in three of four agent configurations and remains within one successful task of the GPT-5.2 Reflection Agent in the fourth. It also reduces paid API charges relative to GPT-based reflection in all four configurations. These results establish StepReflect as a practical, locally deployable alternative to repeated frontier-model reflection for long-horizon mobile GUI agents.

# StepReflect：移动GUI智能体的结构化UI转换反思

## 一、核心问题与整体含义

**研究动机：**
- 自主移动GUI智能体在执行长程任务（如订餐、叫车）时，需要在多屏幕间执行一系列GUI操作，其可靠性高度依赖每个动作执行后的**行动反思（action reflection）**——即判断已执行的动作是否产生了预期的界面转换。
- 现有方法（如AppAgent、Mobile-Agent-E等）在每个动作后调用大型云VLMs进行**开放式多模态推理**来评估界面状态，存在两大问题：
  1. **成本高**：每步都调用前沿大模型的API，延迟和费用随轨迹长度线性增长；
  2. **特征不匹配**：GUI交互遵循结构化、可预测的状态转换规律，用开放式推理来处理这种结构化问题既不必要也不高效。
- 此外，现有系统本质上是"反应式"的，缺乏显式结构、持久状态和执行反馈，导致长程任务中微小反思错误逐步累积，最终导致任务失败。

**核心洞察：**
GUI行动反思应被重构为**对UI状态转换的监督结构化预测问题**——即判断观测到的UI转换是否与动作在当前任务上下文下的预期效果一致，而非开放式多模态推理。

## 二、方法论

### 2.1 核心思想

将每步GUI反思形式化为一个结构化预测任务：

**输入元组：**
```
x_t = (s_t, a_t, s_{t+1}, h_t, I_t)
```
- `s_t`, `s_{t+1}`：动作前后的符号状态表示（屏幕描述+前/后置条件）
- `a_t`：执行的动作及其意图描述
- `h_t`：当前子目标内的有界历史轨迹（上限 h_max = 5）
- `I_t = (I_t^before, I_t^after)`：成对的BEFORE/AFTER截图

**学习目标：**
```
f_θ : S × A × S × H × I → {0, 1} × R
```
- 输出二元决策（转换是否一致）+ 结构化自然语言推理

### 2.2 关键技术细节

**结构化转换表示：**
- 将语义期望与观测证据分离：期望由宿主智能体通过动作意图和前/后置条件提供；证据由屏幕描述和截图对提供
- 历史轨迹按子目标（subgoal）划定范围，只包含当前子目标内的最近转换，避免无关上下文干扰

**三阶段训练流水线：**

1. **阶段一：监督微调（SFT）**
   - 学习基本GUI转换动态，输出结构化JSON（决策+解释）
   - 使用GPT-5.2辅助生成并人工审核的转换级标签

2. **阶段二：师生蒸馏（TS-Dis.）**
   - 以GPT-5.2为教师，生成更长的模板化推理过程
   - 目标：提升推理结构的一致性和质量

3. **阶段三：偏好与奖励优化（GRPO + DPO）**
   - **GRPO**：使用非对称奖励设计——正确"是"得+2.5，正确"否"得+2.0，误接受罚-2.0，误拒绝罚-2.5。这一设计反映长程执行中误拒绝（假阴性）成本更高
   - **DPO**：通过拒绝采样构建偏好对（5个候选/输入），直接对齐模型行为使其更可靠
   - 最终顺序为：TS-Dis. → GRPO → DPO

**模型架构：**
- 使用Qwen2.5-VL（3B/7B）和Qwen3-VL（4B/8B）作为基础模型
- 采用LoRA微调（rank=16, α=16），4-bit加载，梯度检查点

### 2.3 训练数据

- 来源：Mobile-Eval-E 和 SPA-Bench
- 覆盖45个英语跨域任务、40个应用（电商、信息管理、社交媒体等）
- 训练集规模：882个转换实例（58.6%正样本，41.4%负样本）
- 标签生成：GPT-5.2初始判断 → 人工审核修正
- 负样本增强：包含4种扰动方式（无变化、同轨迹历史状态、同轨迹未来状态、其他任务状态）

## 七、优点

**方法设计亮点：**
- **问题重构新颖**：首次将GUI行动反思作为监督结构化预测，明确区分语义期望与观测证据，与问题的结构化本质匹配
- **非侵入式集成**：通过轻量提示接口映射各宿主智能体输出，不修改规划或行为策略，可即插即用
- **三阶段训练流水线设计精巧**：SFT学基础→蒸馏提升推理结构→GRPO/DPO校准决策边界，各阶段目标明确

- **子目标有界历史**：将历史限制在同一子目标内（h_max=5），避免无关转换的干扰，设计合理且通用
- **本地可部署**：8B模型推理，完全消除付费反射API调用，实用性强

**实验设计亮点：**
- 离线/在线双轨评估，全面覆盖反射能力本身及其系统级影响
- 公平性控制良好：统一结构化输入、统一反馈注入方式
- 跨框架验证（4个异构智能体框架）展示了良好的迁移性和通用性

## 八、不足与局限

1. **数据规模与扩展性**：训练集仅882条转换实例，依赖GPT-5.2辅助+人工审核的标签产生流程，人力成本高、扩展性受限
2. **上游错误传播**：StepReflect依赖宿主智能体提供的符号字段（描述、前/后置条件），若上游字段本身有误，错误会传导至反射决策
3. **在线评估范围有限**：AndroidWorld只用了36个中等难度任务，未覆盖简单（存在天花板效应）和最难（主要受规划影响）任务的完整谱系
4. **差异方差未报告**：无重复运行的方差数据，无法判断结果差异的统计显著性
5. **成本统计不完整**：仅报告付费API费用，未包含本地推理的硬件、电力和运维成本
6. **跨平台泛化未验证**：结构化转换公式仅针对移动GUI，扩展到Web/桌面环境需要适配不同的动作空间、布局和状态表示
7. **正面偏差仍需关注**：虽然正类准确率最高（86.79%），但负类准确率（76.12%）在对比变体中偏低，可能影响对意外/错误转换的检测灵敏度
8. **Agent-SAMA场景增益有限**：当宿主已内建状态感知反思机制时，StepReflect仅提供成本-准确率权衡而非绝对优势
