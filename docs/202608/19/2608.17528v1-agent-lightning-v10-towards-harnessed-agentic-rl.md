## 摘要
现代代理在管理工具、上下文和控制流的代理框架中运行，这使得该框架成为代理系统的重要组成部分。我们最初的Agent Lightning引入了一种解耦架构，通过LLM端点代理将任意代理连接到强化学习训练，这种方法后来被诸如verl Uni-Agent、AReaL 2.0、slime和Polar等框架采用。我们将这种范式称为受控代理强化学习，其中部署时的代理框架直接参与模型的后训练。受控代理强化学习与传统代理强化学习有根本不同：由代理框架而非训练引擎掌控环境交互循环，而训练器仅观察LLM请求-响应对的序列。这带来了在重新分词、样本合并、优势计算、损失归一化和后端调度方面的挑战，这些挑战会显著影响训练的稳定性和有效性。我们提出了Agent Lightning v1.0，一个用于受控代理强化学习的轻量级框架，以约3,500行代码实现。它支持任意代理框架，并作为研究这些挑战的实用测试平台。我们在指令遵循、搜索和编码代理上对其进行了评估，并为编码代理强化学习提供了一个完整且可复现的流程。仅使用6K个训练样本和适度的计算资源，强化学习将Qwen3.5-9B在SWE-bench Verified上的性能从41.8%提升至56.4%，绝对提升了14.6个百分点。我们发布了完整的工作流程和训练脚本，以促进受控代理强化学习的可复现研究。

## Abstract
Modern agents operate inside agent harnesses that manage tools, context, and control flow, making the harness a critical part of the agent system. Our original Agent Lightning introduced a disaggregated architecture that connects arbitrary agents to RL training through an LLM endpoint proxy, an approach later adopted by frameworks such as verl Uni-Agent, AReaL 2.0, slime, and Polar. We refer to this paradigm as harnessed agentic RL, where the deploy-time harness directly participates in model post-training. Harnessed agentic RL differs fundamentally from traditional agentic RL: the harness, rather than the training engine, owns the environment interaction loop, while the trainer observes only sequences of LLM request-response pairs. This introduces challenges in retokenization, sample merging, advantage calculation, loss normalization, and backend scheduling, which can substantially affect training stability and effectiveness. We present Agent Lightning v1.0, a lightweight framework for harnessed agentic RL implemented in approximately 3,500 lines of code. It supports arbitrary agent harnesses and serves as a practical testbed for studying these challenges. We evaluate it on instruction-following, search, and coding agents, and provide a complete reproducible pipeline for coding-agent RL. Using only 6K training examples and modest compute, RL improves Qwen3.5-9B on SWE-bench Verified from 41.8% to 56.4%, a 14.6-point absolute gain. We release the complete workflow and training scripts to facilitate reproducible research on harnessed agentic RL.

### 1. 核心问题与研究动机

传统智能体强化学习（Agentic RL）中，训练引擎直接拥有环境交互循环，模型在训练时以连续token历史与环境直接交互。然而，现代智能体在部署时实际运行在**代理框架（Agent Harness）**中，由harness管理工具调用、上下文构建、控制流和异常恢复等。由于传统RL训练方式需要将harness环境循环重新实现在训练框架内部，导致训练与部署存在严重脱节。

本文系统定义了**“受控代理强化学习”（Harnessed Agentic RL）**范式：让部署阶段实际使用的harness直接参与模型后训练，训练系统通过LLM端点代理观察模型调用序列（request-response对），从而缩小训练与部署之间的差距。但该范式引入了一系列新挑战，包括重新分词（retokenization）、样本合并、优势计算、损失归一化和训练后端调度等。现有框架对这些挑战的处理方式各不相同且常被低估，本文首次对这些挑战进行系统性表征，并提出轻量级框架Agent Lightning v1.0。

### 2. 方法论

#### 核心思想
- **分离式架构（Disaggregated Architecture）**：训练器与harness分离，通过API Gateway代理LLM调用连接二者。harness拥有环境交互循环，训练器只观测模型调用序列并优化策略。
- **设计原则**：保持极简主义（约3,500行代码）；任意harness只需将LLM端点切换到代理即可接入训练。
- 系统包含三个组件：**API Gateway**（存储rollout、模型和事件）、**Rollout Controller**（基于Kubernetes或本地进程池管理agent执行）、**Customized Trainer**（基于VERL构建，注册rollout、收集轨迹、组装训练样本）。

#### 关键技术细节与挑战解决方案

1. **重新分词与样本合并（Retokenization & Sample Merging）**
   - 问题：harness以文本消息通信，但RL训练基于token。上一轮response的文本在下一轮prompt中被重新tokenize后，token边界可能变化，破坏token级前缀连续性。三种成因：chat template非组合性、解码-再分词偏移、推理时输出变换。
   - 方案：采用**best-effort序列合并**——仅当两个连续调用的token ID满足精确前缀条件时才合并；否则关闭当前训练序列并开启新序列。这保证了训练所用的prompt与rollout中实际消费的prompt完全一致，同时不需要复杂的树形训练后端。

2. **优势计算（Advantage Calculation）**
   - 问题：一次rollout因retokenization、子agent生成、上下文压缩等可能产生动态数量的训练样本，reward按rollout整体分配，那么baseline应在rollout层面还是sample层面计算？
   - 方案：采用**rollout层面优势计算**。理由：retokenization是偶然现象，子agent生成和上下文压缩是harness内部操作，不应改变整组的baseline。文中示例显示sample-level会使baseline从1/2变为3/4，改变优化目标。

3. **损失归一化（Loss Normalization）**
   - 比较了三种方式：token-mean (DAPO)、seq-mean-token-mean (GRPO)、rollout-level token-mean。
   - 方案：采用**rollout-level token-mean loss**（先对同一rollout的所有样本token合并求平均，再对所有rollout求平均），避免样本数量影响梯度归一化权重。不采用token-mean是因其对长序列敏感，训练后期可能不稳定。

4. **训练后端调度**
   - 动态样本数使得在固定GPU配置下无法提前规划mini-batch。要求物理展平后的每个序列保留rollout标识和prompt-group标识，且同一rollout的序列必须在同一次optimizer update中，避免策略不一致。

5. **协同异步RL（Collocated Async RL）**
   - 同步RL需等待最慢rollout导致GPU闲置；传统异步RL需分离rollout与update的GPU池，资源要求高。
   - 本文让rollout和weight update**共享同一GPU池**，通过API Gateway在训练阶段暂停新的推理请求，切换对harness透明。实验中比同步RL快约2倍且用更少GPU。

6. **可靠性设计**：API Gateway所有端点幂等；训练时对相同prompt的重复model_request事件去重（只保留最后一次）；agent执行基于自托管Kubernetes集群而非商业沙箱服务。

### 6. 主要结论与发现

1. **Harnessed agentic RL范式成立**：通过LLM端点代理将任意agent harness接入RL训练可行，且能显著提升部署时智能体能力。
2. **rollout级设计是更优选择**：优势计算和损失归一化都应在rollout层面进行，样本数量受retokenization等偶然因素驱动，不应影响优化权重。消融实验证实rollout-level advantage + rollout-level norm组合取得最高验证reward（38.2%）且训练更稳定。
3. **轻量级实现可行**：约3,500行代码即可构建完整的harnessed agentic RL框架，无需大型工程团队或商业沙箱服务。
4. **编码智能体RL训练可复现**：通过完整数据清洗流程、防reward hacking措施和适中算力，仅6K训练样例即实现SWE-bench Verified 41.8%→56.4%的绝对14.6%提升，证明了小规模、可复现的编码agent RL训练是可能且有效的。
5. **协同异步RL有效**：共享GPU池的异步训练策略在降低资源需求的同时保持了高效性。
6. **Harness行为导致动态样本数是普遍现象**：编码训练中平均每rollout产生2.41个训练样本，动态样本数必须作为框架设计的核心约束。

### 7. 优点

- **概念贡献清晰**：首次系统定义和表征harnessed agentic RL，提出了区别于传统agentic RL的POMDP建模差异，为后续研究提供统一术语框架。
- **极简代码设计**：约3,500行代码实现完整架构，大幅降低了社区复现门槛。
- **设计哲学一致**：将“rollout为统计单位”的原则贯穿到优势计算、损失归一化和样本合并等各个环节，逻辑自洽，并通过消融实验支撑。
- **高度工程可用性**：幂等API、去重机制、幂等控制面、Kubernetes集成、本地进程池、轨迹监控系统等设计考虑了真实训练中网络故障、reward hacking、agent异常等工程问题。
- **完善的实验复现性**：开源完整数据清洗流程、训练脚本、reward-hacking防护方案，填补了编码agent RL训练中数据与脚本缺失的空白。
- **成本意识强**：选择SWE-smith（295 GB镜像）而非SWE-Gym（6 TB）或R2E-Gym（4 TB），使用自托管Kubernetes替代商业沙箱，使用协同异步RL减少GPU需求，体现了对中小团队资源约束的尊重。

### 8. 不足与局限

- **算力信息不透明**：未报告具体GPU型号、数量和训练时长，难以评估“modest compute”的实际规模，影响可复现性判断。
- **横向对比缺失**：未与verl Uni-Agent、AReaL 2.0、Polar等同类框架在相同任务上进行基准测试，对设计选择的优劣判断主要依赖内部消融。
- **评估规模有限**：搜索agent验证集每数据集仅50例，编码agent测试集400例，统计置信度有限；SWE-bench Verified本身为真实GitHub issue，但训练数据来自合成的SWE-smith，存在分布差异。
- **消融覆盖不完整**：rollout级设计的消融只在编码场景实施，未验证在搜索、指令跟随场景下是否同样有效。
- **理论论证偏直觉**：对“为什么rollout层面比sample层面更合理”主要基于retokenization偶然性的论述，缺乏严格的数学证明或更细致的credit assignment分析，论文也承认未来需要更好的rollout内部分样本信用分配方法。

### 9. 总体评估与展望

本文在智能体强化学习领域做出了一个有价值的框架性贡献。它将长期以来被忽视的"训练-部署脱节"问题正式化，并给出了一个工程上可行、代码量极小的解决方案。核心思想——让部署时的agent harness直接参与训练，通过API Gateway代理LLM调用实现训练器与harness的解耦——在概念上是简洁且有说服力的，三个实验场景的实际收益也验证了该范式的有效性。

在技术选型上，作者展现出强烈的实用主义倾向：不追求复杂的树形tensor parallelism或异步调度算法，而是通过"rollout级统计单位"这一统一原则，将retokenization、样本合并、优势计算、损失归一化等琐碎但关键的问题逐一化解。这种设计哲学使得框架易于理解和复现，其消融实验也证明了核心设计选择的合理性。

然而，论文的短板同样明显：算力信息不透明、横向对比缺失、评估规模有限、消融覆盖不完整。这些不足共同指向一个事实——本文更像一个"基准性"工作（确立了范式与框架），而非"竞争性"工作（在绝对性能上超越其他方案）。未来研究可以在以下方向延伸：

- **更丰富的harness行为建模**：如何将多agent协作、上下文压缩、长程记忆等复杂动态纳入统一的训练样本管理中；
- **rollout内部分样本的精细化credit assignment**：当前统一按rollout分配reward的做法虽保持了统计一致性，但可能稀释了长序列中关键决策的信用信号，探索基于token importance或工具调用关键点的加权方法是重要方向；
- **跨域验证与标准化benchmark**：建立harnessed agentic RL的公共基准，使不同框架（verl Uni-Agent、AReaL 2.0、Polar等）能在相同数据、相同硬件条件下公平对比；
- **与推理时计算扩展的结合**：当harness本身参与decoding-time scaling（如多轮校验、并行候选搜索）时，如何与RL训练协同优化，是尚未探索的前沿问题。

总体而言，Agent Lightning v1.0以其清晰的概念、极简的实现、扎实的工程细节和可复现的实验，为该领域提供了一个坚实的起点和参照系。尽管存在多处待完善的环节，但它对"harnessed agentic RL"这一重要却长期被低估的问题的系统性刻画，本身就具有较高的学术与工程参考价值。
