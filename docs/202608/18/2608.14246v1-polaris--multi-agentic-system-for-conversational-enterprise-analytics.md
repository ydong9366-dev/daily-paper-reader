## 摘要
在当今快节奏的环境中，快速访问、理解和运用数据的能力不再是可选项，而是必需的。然而，大多数组织仍然数据丰富但洞察贫乏，受限于查询、解释和阐述企业级信息的复杂性。我们提出了Polaris，一个由监督者领导的多智能体框架，用于对话式企业分析，填补了这一空白。Polaris引入了动态任务协调（DTC），一种决策理论驱动的编排层，将智能体任务分配建模为自适应二分匹配，实现了跨查询、可视化和推理等专业智能体的实时协调、恢复和优化。通过将DTC与推理优先的ReAct风格智能体相结合，Polaris将自然语言查询转化为连贯的分析工作流，不仅检索和可视化数据，还解释其背后的“为什么”。在结构化企业数据集上的评估表明，该方法具有较高的语义保真度和答案相关性，凸显了多智能体编排在规模化提供可信赖的端到端商业智能方面的潜力。

## Abstract
In today's fast-paced environment, the ability to swiftly access, understand, and act on data is no longer optional; it is essential. Yet most organizations remain data-rich but insight-poor, constrained by the complexity of querying, interpreting, and explaining enterprise-scale information. We present Polaris, a supervisor-led multi-agent framework for conversational enterprise analytics that bridges this gap. Polaris introduces Dynamic Task Coordination (DTC), a decision-theoretic orchestration layer that models agent-task assignment as adaptive bipartite matching, enabling real-time coordination, recovery, and optimization across specialized agents for querying, visualization, and reasoning. By coupling DTC with reason-first, ReAct-style agents, Polaris transforms natural-language queries into coherent analytical workflows that not only retrieve and visualize data but also explain the underlying "why." Evaluation on structured enterprise datasets demonstrates high semantic fidelity and answer relevancy, underscoring the potential of multi-agent orchestration to deliver trustworthy, end-to-end business intelligence at scale.

## 方法论

### 核心思想
Polaris 是一个由**监督者（Supervisor）主导**的多智能体框架，核心创新在于引入**动态任务协调（DTC）**，将智能体任务分配建模为**自适应二分匹配（adaptive bipartite matching）**，从而在运行时实现实时协调、恢复和优化。

### 技术细节：DTC 形式化
- 模型定义：图 G = (A ∪ T, E)，A 为智能体集合，T 为任务集合。每个智能体具有能力向量 θ_a，每个任务具有描述符 τ_t。
- 边效用的计算（融合能力匹配、经验可靠性、成本惩罚）：

  > U(a, t | s) = α · sim(θ_a, τ_t) + β · q(a, t) − γ · c(a, t)

- 最优化目标：

  > M* = arg max Σ_{(a,t)∈M} U(a, t | s)

  其中 M 满足前置约束、容量约束、工具/数据可用性约束。该问题可在运行时近似求解（参考匈牙利算法、在线二分匹配）。
- 执行反馈（诊断轨迹、错误、延迟）动态更新 q(a, t) 和 θ_a 的信念，支撑重规划、抢先执行和回滚机制。

### 系统架构与智能体分工
1. **监督者智能体（Supervisor Agent）**：系统主控制器，解析意图、维护上下文、按 DTC 求解任务路由；触发恢复协议，处理模式不匹配等异常，保持会话连续性。
2. **查询专家（Query Expert）**：负责 NL→SQL++ 转换。关键步骤包括：模式推断与语义标注、输入规范化、ReAct 风格的 NL-to-SQL++ 翻译、数据质量检查与自适应恢复（如检测空值过多的列、输出过大时采用自适应聚合）。
3. **图表专家（Charting Expert）**：基于规则启发式与 ReAct 框架选择图表类型（时间序列→折线图、分类比较→柱状/饼图）；动态生成可视化代码（Seaborn/Plotly），在 Python REPL 中执行；通过错误堆栈反馈实现自动纠错与重执行。
4. **推理专家（Reasoning Expert）**：解释查询结果，识别潜在模式与因果关联，借助领域知识生成解释性叙述。
5. **报告专家（Report Expert）**：汇总洞察、内嵌可视化，生成结构化报告，包含方法文档、数据源和查询参数等元数据。

### 与其他方法的区别
所有智能体采用**“推理优先”（reason-first）的 ReAct 范式**，即在工具选择和执行前先进行上下文推理，形成思考-行动-观察的迭代循环，而非简单调用现成工具。

## 主要结论与发现

1. **NL2SQL++ 模块表现优异**：语义相似度 0.85、上下文精确度 0.99，100% 的样本超过 0.70/0.90 的阈值，说明自然语言意图捕获和 SQL 生成高度准确且忠实于 ground truth。
2. **答案相关性良好**：平均 0.90，92.5% 样本超过 0.70 阈值。
3. **生成式偏差存在但影响有限**：少数响应在风格或解释上出现偏差，未显著降低整体答案质量，显示多智能体系统对 LLM 生成偏差具有鲁棒性。
4. **整体判断**：基于决策理论的编排（DTC）+ 推理优先的智能体是构建可靠、可审计的高效企业级对话分析系统的一条有效路径。

## 优点

- **编排机制具有理论根基**：将智能体协调正式化为有约束的二分匹配优化问题，相比启发式路由更具原则性。引入执行反馈的在线学习，支持重规划、抢占和回滚。
- **系统设计完整清晰**：五大智能体（监督、查询、图表、推理、报告）分工明确，覆盖“检索→可视化→解释→报告”的完整分析工作流。
- **结合 ReAct 与编排层**：推理与行动交叉，使智能体能动态适配中间结果和系统约束，明显优于“先规划后执行”的单调管道。
- **企业导向的工程细节**：包括语义标注（如识别“amount”为“total sales amount”）、输入规范化、自适应聚合以绕开上下文长度限制、图表代码自动纠错等，切中企业数据的真实痛点。
- **会话连续性维护**：监督者层保持跨会话持久状态，强调多模态输出之间的语义对齐。

## 不足与局限

- **评估规模有限**：单数据集、单领域（短租市场），40 个样本不足以支撑统计显著性；未在多样化的企业数据（如医疗、金融、制造）上测试。
