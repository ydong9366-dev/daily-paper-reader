## 摘要
基于大语言模型的代理式框架主要优化能力：代理是否能够推理、检索信息、调用工具、委派工作并完成目标。企业执行需要更强的属性。如果成功结果是通过未经授权的数据访问、扩大的委托权限、未批准的副作用、不可恢复的预算消耗或不完整的证据产生的，那么它就不是可靠的。本文将可靠能力定义为路径属性：仅当代理通过行为事件完成任务，且这些事件在身份、配置文件、工具、数据、内存、预算、工件、批准和审计约束下保持可接受时，代理才是可靠有能力的。我们提出了一种策略代数，定义了代理能力可在其中行使的可靠性边界。安全配置文件和运行时义务通过连接、交集、预算缩减、批准继承和证据积累进行组合；所得组合既保持信任，又是满足所有治理输入的最不严格状态。该代数还在多代理调用之间传播限制，并引入成本感知的工件物化，随着预算暴露的增长，将开放式执行导向可恢复的结果。评估被解释为可靠性-能力权衡而非能力基准：策略代数运行时干预了94.8%的违反策略事件，同时保持了86.9%的任务完成率，消除了观察到的配置文件单调性和零工件耗尽违规，并将审计完整性提高到98.6%。该方法为研究人员和从业者提供了正式的正确性条件、可执行决策语义和痕迹证据，以构建不仅有能力而且可靠有能力的代理。

## Abstract
Large language model-based agentic frameworks primarily optimize capability: whether an agent can reason, retrieve information, call tools, delegate work, and complete a goal. Enterprise execution requires a stronger property. A successful result is not reliable if it was produced through unauthorized data access, widened delegated authority, unapproved side effects, unrecoverable budget consumption, or incomplete evidence. This paper defines reliable capability as a path property: an agent is reliably capable only when it completes a task through action events that remain admissible under identity, profile, tool, data, memory, budget, artifact, approval, and audit constraints. We propose a policy algebra that defines the reliability envelope within which agent capability may be exercised. Security profiles and runtime obligations compose through joins, intersections, budget narrowing, approval inheritance, and evidence accumulation; the resulting composition is both trust-preserving and the least restrictive state satisfying all governing inputs. The algebra also propagates restrictions across multi-agent calls and introduces cost-aware artifact materialization, which redirects open-ended execution toward a recoverable outcome as budget exposure grows. The evaluation is interpreted as a reliability-capability trade-off rather than a capability benchmark: the policy-algebra runtime intervenes on 94.8% of policy-violating events while retaining an 86.9% task-completion rate, eliminates the observed profile-monotonicity and zero-artifact-exhaustion violations, and increases audit completeness to 98.6%. The method provides researchers and practitioners with formal correctness conditions, executable decision semantics, and trace evidence for building agents that are not only capable, but reliably capable.

## 论文核心问题与整体含义

**研究动机与背景**
- 大语言模型（LLM）驱动的代理式 AI 框架主要优化"能力"（capability）：是否能推理、检索、调用工具、委派任务并完成目标。但在企业环境中，仅有能力是不够的，还需要"可靠性"（reliability）。
- 代理系统从"生成文本"转向"执行动作"：调用 API、使用 MCP 工具、更新记忆、创建工单、发送邮件、写数据库、委派子代理等。这使得安全问题的性质从"不安全的内容输出"转变为"不安全的动作执行"。
- 最终答案可靠，仅当产生它的动作序列本身是可接受的（admissible）。论文将安全定义为**路径属性（path property）**而非单纯的输出属性：能力是存在性（至少一条轨迹可达目标），可靠性是在所选轨迹的每个推理到动作的转换事件上满足通用不变量。
- 现有工作（OWASP AISVS、NIST AI RMF、MAESTRO、AgenticSecurity.info 等）提供了风险清单和评估框架，但缺乏可执行的运行时语义；公开测试基准（WebShop、AgentBench、WebArena）以任务成功率为指标，而非企业级授权、可审计性和配置保持执行。
- 研究问题：**企业代理平台如何在保持有用自主性的同时，确保每个已执行动作被授权、在委派下不放大权限、经济上可恢复（不耗尽预算而无产出）、且可审计？**
- 核心贡献：提出一种**策略代数（Policy Algebra）**，将异构治理工件编译为可执行谓词，组合成"可靠性包络"（reliability envelope），在不替代代理推理的前提下约束其动作空间。

## 方法论

**核心思想**
- 将"可靠能力"形式化为：存在一条可达目标的轨迹，且该轨迹中每个动作事件都满足身份、角色、配置、数据、内存、工具、预算、工件、人机审批、审计等 10 个谓词的合取（式 2）。
- 安全配置文件构成有序策略空间：`Low ⪯ Medium ⪯ High ⪯ VeryHigh`，每个配置文件是一个策略对象（模型集、工具集、数据类别、内存范围、保留期、预算、工件物化策略、审批谓词、外部暴露策略等）。
- 策略组合算子 ⊗（式 9）：配置取 join（更严格者）、工具与内存取交集、预算取 min、物化策略取更严格者、审批取析取（继承）、证据取并集。

**关键定理与性质**
- **定理 1（组合保持信任）**：组合结果不会降低配置保证、不会增加工具权限、不会扩大内存范围、不会增加预算、不会削弱物化要求、不会移除审批或审计义务。
- **定理 2（最不严格组合）**：组合结果是满足所有治理输入的最小上界（least upper bound），不施加超出任一输入所要求的限制。
- 配置级联（式 15）：`peff = pplatform ⊔ pteam ⊔ puser ⊔ pagent ⊔ ppublication`，任何层级都可收紧，但低层不能放松继承的约束（单调配置解析引理）。
- 工具授权为**多策略合取**（式 16）：RBAC 权限 ∧ 代理允许列表 ∧ 服务暴露策略 ∧ 分层威胁模型策略 ∧ 数据策略 ∧ 预算可行性 ∧ 工件物化 ∧ 审批满足。
- RAG/内存访问控制（式 17、18）：读取要求分类兼容、ACL 授权、范围交集、目的匹配；写入要求分类兼容、所有权、范围子集、保留期约束、脱敏映射。
- **信任保持的委派**（式 19-23）：子上下文通过配置 join、工具交集、预算 min、审批析取、内存交集推导，防止"配置洗白"（profile laundering）和权限放大；并有预算守恒约束（式 24），防止并发子调用倍增预算。

**关键算法**
- **算法 1** 配置级联解析（平台→团队→用户→代理→发布）。
- **算法 2** 工具授权门（RBAC → 允许列表 → 服务暴露 → 威胁层 → 数据策略 → 预算 → 审批，任一失败则拒绝或要求审批）。
- **算法 3** 多代理调用链评估（沿路径累加配置 join、工具交集、预算 min、审批析取，深度超限则拒绝）。
- **算法 4** 受治理的执行主循环（每次推理到动作转换都过策略门，记录审计证据）。
- **算法 5** 成本感知工件物化：按累计成本/预算比例设 α、β 阈值，低消耗放行，中消耗重定向到物化，高消耗限制为仅允许工件写入；防止预算耗尽且无持久化工件。

**其他关键设计**
- 残差风险模型（式 25-28）：风险分解为威胁似然、影响向量、企业权重、控制后残差暴露四部分；风险只用于排序和阈值，不能凌驾于硬策略可行性之上。
- 预留容量定理（定理 4）：只要非物化动作满足 `Ct + cost(at) + RQ(st+1) ≤ B0`，开放式执行就不会消耗掉尝试有效工件所需的预留预算。
- 受控动作选择（式 31）：效用最大化约束在可行域内，硬策略约束优先。
- 策略修复循环（式 40、41）：失败案例转化为新策略规则和回归测试。

## 主要结论与发现

- 策略代数运行时干预了 **94.8%（798/842）** 的不安全事件，显著高于 RBAC+允许列表基线的 **67.1%（565/842）**，同时将任务完成率保持在 **86.9%**（基线的 95.8%）。
- **配置单调性违规从 31 降为 0**（188 条委派链中），验证了委派模型防止权限扩大的有效性；配置洗白场景干预率达 100%。
- **零工件预算耗尽从 18 降为 0**（44 个耗尽运行中），成本感知物化机制消除了"预算耗尽却无可恢复输出"的失败模式。
- **审计完整性从 71.9% 提升到 98.6%**，使得失败案例可复现、可修复。
- 权衡代价：误干预率从 2.1% 升至 4.2%，中位授权延迟从 38ms 升至 71ms（P95 从 91ms 升至 184ms）——这是多谓词合取的预期成本。
- 场景级分析表明最大增益来自需要多个授权来源联合决策的案例（RBAC 单独看通过但配置/数据/发布/预算/审批/委派链违规）；残差漏网主因是上下文感知错误（工具意图模糊、元数据不完整、文档误分类、语义投毒、陈旧服务元数据等），对应条件正确性分解式（7）的第一项，而非代数决策错误。
- 核心主张：代理安全应作为**轨迹属性**治理，而非仅看最终答案；可靠能力 = 目标达成 ∧ 每个动作事件满足全部策略谓词。

## 优点

- **形式化严谨**：给出明确的定义、引理、定理及证明（信任保持、最不严格性、闭包性、预算守恒），使安全属性可验证而非仅停留在设计讨论。
- **路径属性视角**：将安全从"最终输出检查"前移到"推理→动作转换"的每个事件，准确定位了代理安全的关键风险面。
- **组合性设计**：单一策略代数统一处理配置级联、工具授权、RAG/内存、委派传播、预算、物化、审批和审计，可组合且单调，支持跨代理调用链传播。
- **成本感知的物化机制**：将经济可恢复性纳入策略核心，解决无监督/异步代理"花完预算零产出"的独特失败模式，并给出预留容量定理保证。
- **条件正确性分解**：明确区分"上下文感知错误"与"决策错误"（式 7），避免过度承诺，并为后续改进指明方向。
- **策略修复闭环**：失败案例转化为更强配置、新审批规则和回归测试，形成持续改进的治理循环。
- **工程可落地**：给出了配置文件、权限门、审计事件的代码级草图，以及多个可执行的测试用例，缩短了形式化方法到生产实现的距离。

## 不足与局限

- **条件性保证**：定理是"在策略和上下文被正确表示时"的条件保证，不证明系统感知了真实上下文、不保证所有相关谓词已被指定、不证明实现无法绕过策略门。
- **元数据依赖**：运行时质量依赖于工具、数据对象、服务、内存条目的正确标签和元数据；误分类会直接削弱强制执行。论文对此有明确认知（式 7 第一项），但未提供解决方案。
- **配置集过于简单**：`Low → VeryHigh` 的线性序无法表达真实组织中不可比较的维度（如安全关键配置与隐私关键配置可能无法线性排序），需要更丰富的偏序格。
- **实验充分性不足**：单次运行、单一自建工作负载、无重复/区间估计、无独立外部数据集、无消融分解、无与现有运行时防御工具的直接对比；结果是描述性而非因果性的。
- **多代理扩展有限**：仅覆盖调用链和委派边；并发分支、协商、广播通信、共享

共享状态、异步消息传递、广播与协商等复杂交互模式未覆盖；委派链深度限制可能误拒合法跨域协作。此外，以下局限也未充分讨论：

- **实时性**：P95 授权延迟 184ms 在低延迟交互场景（如在线客服）下可能难以接受，论文未评估配额预计算或语义缓存等优化对延迟的改善效果。
- **绕过风险**：策略门只约束平台可控的调用路径，若代理直接通过系统调用、自定义工具或未受管插件绕过策略层，则无防护能力；论文未将策略引擎自身纳入威胁模型，也未讨论引擎被攻破或配置被篡改时的降级方案。
- **策略维护成本**：将失败案例转化为新规则虽形成修复闭环，但规则数量持续增长可能带来可维护性下降、规则冲突和策略漂移，论文未讨论规则的生命周期治理（版本化、废弃、冲突消解）。
- **配置表达力**：线性安全配置序无法表达多维、不可比较的治理要求（如安全关键与隐私关键的权衡），尽管作者提到了偏序格扩展方向，但并未给出具体构造与合并语义。
- **审计证据的可信性**：虽然审计完整率提升至 98.6%，但证据的防篡改、完整性校验、跨系统关联审计未被验证，也未讨论日志可能被代理误写、恶意覆盖或异步丢失的风险。

综上，该论文的价值在于首次以策略代数统一表达并计算代理执行的可靠性包络，用可执行谓词将治理意图嵌入推理-动作循环，为构建可审计、可组合、可修复的企业代理治理层提供了坚实的理论基础和可落地的工程原型。但其安全保证是条件性的、上下文依赖的，离普适生产级安全基线仍有距离；未来的关键工作包括：引入偏序策略格以表达非可比治理目标、将元数据质量作为一等公民进行自动校验与修正、扩展并发/协商/异步拓扑下的组合语义，以及针对策略引擎自身的抗篡改与审计链完整性做深入设计。
