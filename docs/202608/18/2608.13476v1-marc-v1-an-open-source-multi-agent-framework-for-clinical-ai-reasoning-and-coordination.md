## 摘要
我们提出了多智能体推理与协调（MARC），这是一个开源框架，用确定性的多智能体编排取代了单一的大型语言模型（LLM）提示，用于临床推理。MARC协调专门角色的智能体，分别负责提取、推理、答案生成和评估，通过显式的上下文传递和可追踪的中间输出，实现分阶段故障归因。我们还引入了一个分解器（Decomposer）模块，该模块从自然语言描述生成特定于任务的智能体提示，消除了手动提示工程。该框架支持基于API和本地CPU兼容的部署，并且完全通过YAML进行配置，无需修改代码。MARC的设计目标是模型无关、可解释，并让没有编程专长的临床领域专家也能使用。完整框架可在 https://github.com/Penn-RAIL/MARC-v1 获取。

## Abstract
We present Multi-Agent Reasoning and Coordination (MARC), an open-source framework that replaces monolithic LLM prompting with deterministic multi-agent orchestration for clinical reasoning. MARC coordinates role-specialized agents for extraction, reasoning, answer generation, and evaluation, with explicit context passing and traceable intermediate outputs, enabling stage-wise failure attribution. We additionally introduce a Decomposer module that generates task-specific agent prompts from a plain-language description, eliminating manual prompt engineering. The framework supports both API-based and local CPU-compatible deployments and is entirely configurable via YAML, without code modifications. MARC is designed to be model-agnostic, interpretable, and accessible to clinical domain experts without programming expertise. The full framework is available at https://github.com/Penn-RAIL/MARC-v1.

- **背景与动机**：大语言模型（LLM）在医学和放射学中发展迅速，但大多数临床部署仍依赖单一提示（single-prompt）策略，让同一个模型同时完成信息提取、推理、验证和答案生成。这种整合式方法限制了可解释性，并使得错误定位变得困难：当最终输出错误时，无法判断错误源于信息遗漏、推理缺陷、指令遵循不足还是格式问题。
- **核心问题**：如何构建一种可解释、可配置、可本地部署的多智能体临床推理框架，以替代“黑盒”式的单次模型调用，使临床团队能够理解、调试和验证每一步推理过程。
- **整体含义**：论文提出 MARC（Multi-Agent Reasoning and Coordination）开源框架，通过确定性多智能体编排将临床推理拆分为多个专门阶段，并以显式上下文传递和中间输出日志实现分阶段故障归因，旨在提升临床 AI 的可解释性、可访问性和机构可部署性。

## 2. 论文提出的方法论

- **核心思想**：将单一 LLM 提示替换为多个角色专用的智能体（agents），按固定顺序协作处理临床任务，每个智能体只负责一个子任务，并通过显式变量传递上下文。
- **多智能体设计**：
  - 采用 Level 2 自主性的结构化工作流设计模式：智能体按预定义顺序执行，阶段之间显式交接。
  - 默认三智能体流水线：
    - **Agent 1（信息提取）**：只提取任务相关的 2–4 条简洁证据要点，不做出结论。
    - **Agent 2（分类与分析）**：结合原始输入和 Agent 1 的证据进行多步推理，并以标准化判定行（VERDICT）结束。
    - **Agent 3（推荐生成）**：仅定位并原样返回 Agent 2 的判定标签，避免额外解析。
- **配置方式**：所有智能体、模型分配、提示模板和可选上下文文件均通过 YAML 声明式配置，无需修改代码即可调整流水线。
- **Decomposer 模块**：
  - 使用 MedGemma 4B 模型，从自然语言任务描述中自动生成三个智能体所需的角色提示模板，并以 JSON 输出。
  - 生成的提示会经结构约束校验（变量绑定、VERDICT 格式、长度限制）后加载到流水线中，实现任务自适应的流水线构建，免去手动提示工程。
- **代理提示策略**：所有智能体在 temperature = 0 下零样本运行，确保输出确定性和可复现性。每个提示包含角色定义、任务指令、输出约束和运行时变量四部分。
- **上下文传递与协作**：
  - Agent 1 只接收原始输入；
  - Agent 2 接收原始输入 + Agent 1 完整输出；
  - Agent 3 接收原始输入 + Agent 2 输出（其中隐含 Agent 1 的分析信息）。
  - 每阶段中间输出均被记录，便于事后诊断错误来源。
- **部署方式**：
  - API 模式：使用 Google Gemini 系列模型，配置 API 密钥即可。
  - 本地模式：通过 Ollama 支持 CPU 兼容本地推理，适合数据隐私敏感场景。
  - 两种模式共享同一 YAML 配置，仅模型标识不同。
