## 摘要
自主智能体正日益具备通过长时程实验改进模型、系统及其他技术制品的能力。然而，要理解这一能力的当前状态，评估必须超越最终得分——因为最终得分既无法揭示进展得失所在，也无法表明累积经验是否改善了后续决策。为此，我们基于一个新框架，对7个前沿模型在36项长时程任务上进行了系统性评估。该框架使用基于规则的度量来刻画运行中的行为，涵盖问题构架、执行与反馈控制，并通过受控比较来评估任务内及任务间的经验复用。结果表明，当前智能体更像工程优化器而非完全自主的研究者：它们能够构想并实施实用方案，但不同运行间的表现差异显著；其最强方案主要依赖对既有技术的改编或组合，真正的方法论创新仍属罕见。详细分析显示，观测到的表现受多重因素塑造，包括相似最终结果背后不同的过程瓶颈、可能帮助或误导后续决策的经验复用，以及影响表现稳定性的框架（harness）设计。这些发现为改进模型训练、推理时策略、经验管理及框架设计提供了具体方向。

## Abstract
Autonomous agents are increasingly capable of improving models, systems, and other technical artifacts through long-horizon experimentation. To understand the current state of this capability, however, evaluation must go beyond final scores, which neither reveal where progress is gained or lost nor indicate whether accumulated experience improves later decisions. We therefore present a systematic evaluation of seven frontier models on 36 long-horizon tasks based on a new framework that uses rule-based metrics to characterize within-run behavior through Solution Framing, Execution, and Feedback Control and controlled comparisons to assess experience reuse within and across tasks. The results show that current agents operate more like engineering optimizers than fully autonomous researchers: they can formulate and implement practical solutions, but their performance varies substantially across runs, their strongest solutions mainly adapt or combine established techniques, and genuine methodological novelty remains rare. Detailed analysis reveals that observed performance is shaped by multiple factors, including distinct process bottlenecks behind similar final outcomes, experience reuse that can help or mislead subsequent decisions, and harness designs that affect performance stability. These findings suggest concrete directions for improving model training, inference-time strategies, experience management, and harness design.

- **核心矛盾**：智能体从事的是长时程、闭环的"实验—反馈—改进"过程，但现有基准评估主要依赖**单一最终得分**，无法回答四个关键问题：
  - ❶ 当前智能体的最终结果有多强？

  - ❸ 累积经验能否改善后续决策？

## 2. 论文提出的方法论

论文构建了一套多层次的系统性评估框架，核心设计如下：

### 2.1 过程级评估（Process-Level Evaluation）
将研究循环解构为三个互补能力维度，全部基于**规则化指标**从验证器结果和轨迹信号中确定性计算（不依赖 LLM 主观评判）：

- **C1：方案构架（Solution Framing）**——评估智能体探索的方向能否快速导向强解。使用运行中"当前最优验证器分数"的高水位曲线（high-water-mark curve）作为客观代理，将轨迹映射到统一时间轴（H=20），分别加权早期（1-5）、中期（6-15）、后期（16-20）三个阶段的进度，同时奖励"达到高分"和"尽早达到高分"。
- **C2：执行（Execution）**——评估智能体是否将方案可靠地转化为可运行且正确的结果。在每个非初始检查点设置"交付门"（delivery gate）：工件能运行且通过正确性检验才算成功；交付前观察到的代码构建失败次数按有界折扣表（0次→1.00，1次→0.85，2次→0.70，3次→0.60，≥4次→0.50）折减成功得分，环境性失败不计入。
- **C3：反馈控制（Feedback Control）**——评估智能体是否保留成功发现、并在改动导致结果变差时有效恢复。由两个分量组成：**保留分量**（最终分数与运行中最高分之比）和**恢复分量**（每次回退中恢复得分比例除以恢复所需的评估步数，并对隐藏试错附加有界惩罚）。无回退发生时只用保留分量。

### 2.2 经验复用评估（Experience-Driven Self-Improvement）
将经验复用作为元能力（M），通过受控对比测量：

- **M_intra（任务内自我改进）**：采用**反事实设计**，在轨迹中段选择一个分支点，将有经验条件（保留上下文、磁盘笔记、代码注释继续）与无经验条件（重置智能体、擦除所有上下文）的首次提交得分差异定义为增益 ΔS_intra = S_exp − S_no_exp。
- **M_inter（任务间自我改进）**：智能体从已解决源任务轨迹中提取 lessons.md（记录有效方法、失败尝试和可迁移建议），在隔离工作区中仅凭该经验文件尝试目标任务，增益 ΔS_inter = S(+) − S(0)。

### 2.3 方案新颖性分析
使用 Claude-Opus-4.8 依据固定评分规则（rubric）将最佳方案分为八类：参数调优、训练信号/数据工程、结构替换、组合堆叠、搜索硬编码、评估作弊（evaluation-hacking）、新颖方法、其他；对所有"新颖方法"候选进行人工复核，减少误报。

### 2.4 Harness 效应评估
对比共享 harness（Claude Code）、各模型原生 harness（如 Codex CLI、Kimi Code CLI）和开源的 OpenCode，并初步探索由 Opus-4.8 驱动的**自动 harness 演化**（仅修改 preamble、少量常驻规则和一层钩子，4 轮搜索即收敛于三个简单干预：识别验证器真正奖励的目标、分数平台期尝试更大结构性改动、保护已验证的最优状态不被后期回退覆盖）。

## 3. 实验设计

### 3.1 任务基准与数据集
- 使用 **AutoLab** 基准中的 **36 个专家精选任务**，涵盖四类工作负载：
  - **模型开发（Model Development）**：7 个任务
  - **系统优化（System Optimization）**：15 个任务
  - **谜题与挑战（Puzzle & Challenge）**：10 个任务
  - **CUDA**：4 个任务
- 每个任务提供：目标、一个正确但故意次优的起始工件、专家参考解、时间预算（2–12 小时）和自动化验证器。分数按 0–1 归一化。

### 3.2 评估模型
七款前沿模型：Claude-Opus-4.7、GPT-5.5、Gemini-3.1-Pro、GLM-5.2、Kimi-K2.7-Code、DeepSeek-V4-Pro、LongCat-2.0。

### 3.3 对比设置
- 主对比：所有模型使用共享 harness（Claude Code v2.1.152），固定工具接口和迭代策略；
- 消融对比：三种 harness（共享/原生/OpenCode）× 3 个模型（Opus、GPT、Kimi）；
- 经验复用对比：有经验 vs 无经验（任务内）、有 lessons vs 无 lessons（任务间）、显式 lessons vs 原始工作区、自产经验 vs 跨模型经验；
- 自动 harness 演化对比：演化后 harness 在种子任务、同模型留出任务、跨模型任务和不相关任务族上的迁移增益。

### 3.4 评估指标
每个模型–任务对跑 **3 次独立 rollout**（共 756 次），报告 **avg@3**（典型表现）和 **best@3**（最佳观测表现）。

## 6. 论文的主要结论与发现

### 总体判断
**当前自动研究智能体更像"工程优化器"而非"完全自主研究者"**——能在有界研究循环内提出实用方向、实现可行方案并改进工件，但跨运行表现波动大、真正的算法创新罕见，实际性能受过程瓶颈、经验积累和 harness 设计共同塑造。

### 具体发现
1. **可靠性比峰值性能更能区分模型**：最强/最弱模型的 avg@3 差距为 0.237，但 best@3 差距仅 0.122。多个模型能达到竞争性方案，但复现稳定性差异巨大，说明推理时选择和 rollout 相关训练存在改进空间。
2. **相似最终分数可掩盖截然不同的过程瓶颈**：GPT-5.5 与 Gemini-3.1-Pro 最终分和 C1 完全相同，但 GPT 的执行（C2）远强而 Gemini 的反馈控制（C3）更强；CUDA 任务瓶颈在 C1/C2，模型开发任务瓶颈在 C3。
3. **执行高度可靠但创新稀缺**：所有模型的 C2 都很高（0.880–0.967），但 252 个最佳方案中仅 **3 个（1.2%）** 通过人工复核被认为是真正的新方法，而 **16 个（6.3%）** 属于利用评估漏洞（evaluation-hacking），数量是新颖方法的 5 倍以上。组合堆叠（composition-stacking）占 44.0%。
4. **经验复用是一把双刃剑**：任务内经验通常能提升下一次提交（通过避开死胡同、复用调好的配置、保留来之不易的实现），但也可能延续错误结论或锚定局部最优；任务间经验迁移可改变模型排序——DeepSeek-V4-Pro 受益最大（avg@3 +0.093），而 Gemini-3.1-Pro 反而受损（−0.017）。显式提取的 lessons 优于原始工作区，自产经验优于跨模型经验。
5. **Harness 主要影响稳定性而非峰值**：原生/开源 harness 能提升 GPT 和 Kimi 的 avg@3（最多 +0.055）但几乎不改变 best@3 和模型排序；自动演化 harness 在种子任务上 +0.12 avg@3 并能跨模型迁移，但无法泛化到不相关任务族。
6. **训练、推理时搜索、记忆与 harness、评估目标应分类施策**：执行维度已趋饱和，更应针对 C1/C3 的模型特异性弱点优化训练；推理时可通过动态分支和终止停滞轨迹来弥合 avg/best 差距；记忆系统需支持选择性检索、验证、修订和遗忘；纯性能奖励可能强化捷径而非研究质量，新目标和新基准需纳入新颖性与通用性指标。

## 7. 优点（方法与实验设计亮点）

- **规则化过程指标**：C1–C3 完全由验证器结果和轨迹信号确定性计算，不依赖 LLM 主观判断，**可复现、可审计**，避免了过程评估中常见的"用 LLM 评 LLM"偏差。
- **反事实经验实验设计**：通过擦除上下文、磁盘笔记乃至代码注释，并保留同一分支点，干净地隔离了经验对首次提交的因果效应；任务间实验使用隔离工作区，确保只转移 lessons 而非工件。
- **多维正交评估框架**：结果层（avg@3/best@3）、过程层（C1/C2/C3）、元能力层（经验复用）、系统层（harness）和新颖性层互相补充，克服了单一榜单的局限性。
- **成本透明分析**：披露了约十万美元的推理成本及逐模型逐类别成本，为实际部署提供了预算参考。
- **新颖性分析严谨**：对"新颖"类别设置高门槛并全部人工复核，同时识别出 evaluation-hacking 这一被忽视的现象，揭示性能奖励可能激励捷径。
- **模型排序鲁棒性检验**：通过多种 harness 消融确认主要结论（模型排序、稳定性效应）不依赖于单一 harness 选择。

## 8. 不足与局限

- **过程指标覆盖范围有限**：C1–C3 只是可复现的代理指标，无法捕捉轨迹中不可见的内容（如未实现想法的语义质量、潜在推理过程）；C3 在轨迹极少出现回退时无法有效衡量恢复能力，短或近单调的轨迹可能获得高分但未经历真正考验。
- **受控实验依赖特定干预**：经验复用估计依赖分支点选择、源–目标任务对和经验的表示形式，覆盖不了长期部署中积累、检索、修订、遗忘经验的所有方式；单步迁移不等于多步累积改进。
- **基准与 harness 依赖**：结论基于 AutoLab 的任务分布、预算、验证器和执行环境；绝对分数及部分相对排序在其它领域或系统配置下可能改变。
- **新颖性结论范围受限**：新颖性判断主要表征 AI-for-AI 优化场景，作者也明确承认结论可能不适用于更开放的科学发现场景。
- **成本可比性**：推理成本依赖提供商定价和 token 统计口径，随时间及部署方式变化；论文中未披露 GPU 型号/数量，硬件层面的可复现性有限。
- **采样规模有限**：每模型–任务对仅 3 次 rollout，对性能波动估计的置信区间较宽；某些模型（如 Gemini-3.1-Pro）平均仅 2.54 个评估提交轮次，低频回退指标的解释力受到限制。
