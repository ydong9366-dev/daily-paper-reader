## 摘要
长时程智能体可以持续执行任务，但人类的注意力仍然是间歇性的且稀缺的。这产生了一个双向协调问题：用户可能需要在后台工作继续的同时立即访问智能体，而智能体可能在用户已停止监控执行后遇到需要用户判断的关键决策。我们提出一个常驻的注意力协调层——\textit{Jarvis}\footnote{以《钢铁侠》中的虚构AI助手命名。}——来调解这一界面，并在一个或多个工作智能体之间分配人类注意力。我们引入\textit{JarvisBench}来评估这种协调的两个方向：中间人能否准确且及时地回答用户对正在进行的工作提出的问题，以及它能否识别智能体何时需要用户判断，在合适的时机征求该判断，并将其路由回以改善任务结果。JarvisBench包含45个智能体任务实例：20个单智能体任务和25个工作流，组织成10个多智能体项目。这些任务涵盖19个领域，从超过2000个公开候选任务中选取并改编而来。关键在于，对用户注意力的需求是在执行过程中自然产生的，而非来自初始提示中的明显遗漏。JarvisBench被设计为可与任意智能体运行时集成，无需修改其底层执行循环。我们的参考实现进一步提供了全双工语音接口，使用户能够自然地与Jarvis交互，同时及时的注意力协调支持在后台工作的智能体。通过将智能体执行与注意力协调分离，JarvisBench在智能体能力持续提升时提供了一个稳定的评估目标。

## Abstract
Long-horizon agents can execute continuously, but human attention remains intermittent and scarce. This creates a bidirectional coordination problem: users may need immediate access to an agent while work continues in the background, whereas agents may encounter consequential decisions that require user judgment after the user has stopped monitoring execution. We posit an always-on attention-coordination layer---\textit{Jarvis}\footnote{Named after the fictional AI assistant in \textit{Iron Man}.}---that mediates this interface and allocates human attention across one or more working agents. We introduce \textit{JarvisBench} to evaluate both directions of this coordination: whether an intermediary can accurately and promptly answer user-initiated questions about ongoing work, and whether it can recognize when an agent requires user judgment, solicit that judgment at the right moment, and route it back to improve task outcomes. JarvisBench contains 45 agentic task instances: 20 single-agent tasks and 25 workstreams organized into 10 multi-agent projects. The tasks span 19 domains and were selected and adapted from more than 2,000 public candidates. Crucially, the need for user attention arises naturally during execution rather than from an obvious omission in the initial prompt. JarvisBench is designed to integrate with arbitrary agent runtimes without modifying their underlying execution loops. Our reference implementation further provides a full-duplex speech interface, allowing users to reach Jarvis naturally while timely attention coordination supports agents working in the background. By separating agent execution from attention coordination, JarvisBench provides a stable evaluation target as agent capabilities continue to improve.

## 一、核心问题与整体含义（研究动机与背景）

- **研究动机**：长时程（long-horizon）智能体可以持续执行任务，但人类的注意力是**间歇性且稀缺**的。这种“机器持续运行”与“人类分散注意”的错配产生了一个**双向协调问题**：
  - **用户 → 智能体方向**：用户希望在后台工作继续的同时，能随时向智能体提问或提供指导，而非被迫打断其执行。
  - **智能体 → 用户方向**：智能体在遇到需要人类判断的关键决策时，无法确保用户正在关注执行过程，常被迫猜测并继续，这可能导致偏离用户真实意图的结果。
- **既有研究的不足**：现有智能体主要被训练和评估用于任务完成，而非决定“何时应引入间歇可用的用户”。已有研究（如 Qian et al., 2025; Zhang et al., 2026; He et al., 2025）表明智能体的“主动性”（proactivity）是独立能力，且当前的校准表现较差。同时，这些工作通常让工作智能体自己兼任“执行”与“交互”双重职责，且主要面向“智能体 → 用户”单向方向。
- **论文提出的解决方案**：提出一个**常驻的注意力协调层——Jarvis**（以《钢铁侠》中的 AI 助手命名），它作为“中介”位于用户与一个或多个工作智能体之间，负责：
  - 持续地向用户提供可用的语音交互接口（用户随时可提问、指导）；
  - 监控工作智能体的执行事件，识别需要用户判断的关键决策点，在正确时机请求用户注意，并将用户反馈路由回相关智能体，以改善任务结果。
- **JarvisBench 的定位**：一个用于评估上述双向注意力协调能力的新型基准。它包含 45 个任务实例（20 个单智能体任务、10 个多智能体项目共 25 个工作流），覆盖 19 个领域，从 2000+ 公开候选任务中精选并改编而成。其关键设计是**将“智能体执行”与“注意力协调”分离**，使基准能随智能体能力提升而保持稳定评估价值。

## 二、方法论

- **核心思想**：分离两个关注点——工作智能体（执行任务）与 Jarvis（协调人类注意力）。Jarvis **不解决具体任务**，不使用工作智能体的工具，也不替换其计划；它仅通过有界任务事件（bounded task events）和窄接口（narrow guidance interfaces）与外部运行时连接，从而实现与任意智能体运行时（如 OpenClaw harness）的即插即用。
- **三种角色与设定**：
  - **用户**：拥有意图、偏好、权威、私人上下文和验收判断；在受控评估中由具有冻结任务专属用户配置文件的 LLM 模拟。
  - **Jarvis**：连接两侧，始终可用，观察有界任务事件，并将用户指导传回相关工作智能体。
  - **工作智能体**:执行任务,底层执行循环保持固定不变。
- **任务类型**：
  - **单智能体任务（20个）**：每个任务跟随一个 worker 完成完整轨迹，测试 Jarvis 能否识别轨迹中的用户私有决策点。若需干预，Jarvis 会在执行边界处暂停 worker、取消待定动作、将用户响应作为局部软指导注入，然后继续执行，不丢弃已完成工作。
  - **多智能体任务（10个项目/25个工作流）**：每个项目由耦合的工作流组成，共享实体、约束或后果，其交互会暴露一个“项目级决策”，该决策的相关性随工作推进才变得清晰。
- **关键技术细节与公式**：
  - **任务结果得分（Task Outcome Score, 式1）**：每个任务定义一组冻结的加权检查点：\( S_i = 100 \sum_j w_{ij} c_{ij} \)，其中 \( c_{ij} \in [0,1] \) 是检查点 j 的完成度，权重之和为 1。检查点覆盖目标执行、与用户决策的一致性、交付质量、安全性。
  - **Agent-Collaboration Track（智能体-用户方向）**：报告均值 `S_base`（仅 worker）、`S_Jarvis`(带 Jarvis)、`N_req`（平均注意请求次数）。**注意力效率（式2）**：\( \text{Eff.} = (\bar{S}_{Jarvis} - \bar{S}_{base}) / (100 \bar{N}_{req}) \)，表示每次请求用户交互所获得的占满分数尺度的平均增益。
  - **User-Interaction Track（用户-智能体方向）**：采用**因果回放（causal replay）**协议——每个 worker 轨迹只记录一次，按时间顺序回放给 Jarvis，只显示当时可见的状态（不重跑 worker）。每个轨迹设置早期(~25%)和晚期(~75%)检查点；先问固定的“通用问题”（General），再让 GPT-5.6-Luna 基于 Jarvis 的最近回答生成一个具体追问（Follow-up）。评估员独立为每个回答打分 0/1/2，分开计算 General 和 Follow-up 得分并线性转换为 0–100 分。

## 六、主要结论与发现

- **Jarvis 在不同 worker 间普遍带来提升**（表 1）：以 GPT-5.6-Sol 作为 Jarvis 时，所有完成的 worker 配置均获得提升——单智能体任务提升 4.9–24.7 点，多智能体任务提升 12.5–28.2 点。效果跨模型家族迁移，但幅度依赖具体 worker。
- **Jarvis 不是被动消息路由器**：增益幅度在 worker 和 Jarvis LLM 之间差异明显，说明 Jarvis 必须理解进行中的工作、识别何时人的判断重要、并将判断转化为有效干预。
- **GPT-5.6-Sol 是最强的 Jarvis LLM**（表 2）：在单/多智能体任务上都产生了最大的分数增益（+24.1 和 +28.2）和最高的最终分数；但**注意力效率**上，DeepSeek V4-Pro 在多智能体任务中表现更优（0.41 vs 0.28），因为它只需 0.30 次请求/任务就实现了较高增益——说明“强模型”不等于“最注意高效”。
- **用户交互得分**（表 3)：GPT-5.6-Sol 获得最高 Overall 分数（96.3），本地部署的 Qwen235B 与 GPT-OSS-120B 延迟最低（1.6s 和 1.3s），但延迟与部署条件纠缠，不能直接作为模型速度对比。
- **干预强度权衡**：增加请求可能提升任务得分，但消耗更多人类注意力并可能干扰 worker；不存在普适的最优策略，JarvisBench 的作用是**暴露这种权衡**而非压缩成单一分数。
- **分离执行与协调的价值**：这套设计使 JarvisBench 能作为“参考控制系统”与未来更强的 agent 运行时、干预策略、交互模式和语音接口在同一协议下比较。

## 七、优点

- **创新性的问题定义**：率先将“人类注意力的稀缺性”作为中心议题进行专门评估，而不是将其作为多智能体协作或单智能体任务完成的附带产物。
- **双向评估设计**：同时评估“agent → user”（代理协作轨道）和“user → agent”（用户交互轨道），对应真实部署中的两个方向，形成了完整的注意力协调评估闭环。
- **任务设计真实性**：需要用户注意力的决策点**在执行过程中自然涌现**，而非通过从初始提示中故意删除关键信息来人工制造；这避免了“显而易见的遗漏”带来的评估偏差。
- **执行与协调的解耦**：Jarvis 与工作智能体通过有界任务事件和窄接口连接，不修改 worker 的执行循环，使得基准可以兼容任意智能体运行时，评估目标稳定。
- **因果回放协议**：用户交互轨道的“读-拷贝”式回放避免了为每个 Jarvis LLM 重跑 worker，节省了计算成本，同时严格保证时间因果性（禁止未来信息或私有信息泄漏）。
- **注意力效率指标**：式（2）将“分数增益”与“请求用户注意的次数”关联起来，明确量化了“代价-收益”关系，有助于寻找最优干预密度。
- **严格的基准构建流程**：从 2000+ 候选任务经过四重筛选、适配、多阶段验证（含人工轨迹审查和参考结果验证），保障了任务质量和评估可靠性。

## 八、不足与局限

- **实验覆盖有限**：任务数量较少（45 个实例、19 个域），每个配置仅跑一次取宏平均，未报告方差、置信区间或显著性检验，因此结论的统计稳健性无从判断。
- **潜在评估偏差**：用户交互轨道的评分和追问生成均依赖 GPT-5.6-Luna，评估语言

- 模型自身的回答质量差异与任务真实回答质量之间的区分不够明确，可能引入系统性偏差。
- **缺少真实人类评估**：虽然论文声称“以用户为中心”，但主要实验全部依赖 LLM 模拟用户和 LLM 评分员，并未报告真人用户对干预时机、请求自然度、语音交互体验的主观评价；这对“人类注意力”研究而言是一个关键缺口。
- **多智能体结果不完整**：表 1 中 GPT-5.6-Sol 作为 worker 的多智能体结果缺失，导致最强模型在协作场景中的基线不完整；且多智能体任务仅有 10 个项目，样本量更小，结论外推需谨慎。
- **未考虑长期记忆与状态累积**：JarvisBench 的每个任务都是独立、有界的；但在真实“always-on”部署中，Jarvis 需要跨任务、跨会话维护用户偏好与上下文，论文未对此类持续学习或记忆漂移问题进行评估。
- **语音接口评估较浅**：语音相关实验仅报告了延迟（TTS 首个音频时间），未评估语音识别错误率、对话打断处理、多轮语音交互的自然度等关键指标；语音原型（ASR + VAD + TTS 的组合）更偏向演示性质。
- **干预策略固定**：论文使用固定的“轻量干预”策略评估所有配置，未系统地探索不同干预策略（如提前询问 vs 边界询问、主动建议 vs 被动确认）对结果的影响；因此基准对策略空间的覆盖仍有限。

## 九、对未来研究的启示与展望

- **JarvisBench 可作为“插槽式”评测协议**：由于它分离了执行与协调，未来工作可以在同一任务集上替换更强的工作智能体、更复杂的协调策略、不同的交互模态（文字、语音、多模态），从而持续追踪注意力协调能力的演进。
- **注意力效率应成为核心优化目标**：论文提出的效率指标（每次请求获得的分数增益）提示研究者，目标不应是“尽可能多地询问用户”，而是在“最少打扰”与“最大价值”之间找到自适应最优策略——这将是未来 agent 系统设计的重要方向。
- **需要更细粒度的用户模型**：论文中的模拟用户使用冻结的用户配置文件，未来可引入动态变化的用户状态（疲劳、分心、偏好漂移），以更真实地模拟间歇性可用的场景。
- **可扩展到团队场景**：当前多智能体任务仍由 Jarvis 作为单一协调中点；未来可探索多个 Jarvis 实例、分层协调或多用户共享协调器等更复杂的组织结构。

## 十、总结

JarvisBench 是首个系统性地将“人类注意力协调”作为独立评估维度的智能体基准。它通过引入一个常驻协调层 Jarvis，明确分离了任务执行与注意力管理，并设计了双向评估轨道（智能体→用户、用户→智能体），覆盖 45 个精心构建的任务实例与 19 个领域。实验表明：Jarvis 能在不修改底层 worker 的情况下稳定提升任务结果，效果跨模型迁移但幅度依赖具体模型；同时，注意力请求的成本与收益之间存在明确的权衡，且“最强模型”与“最注意力高效模型”并不重合——这为智能体系统设计提供了重要的量化依据。尽管在样本量、统计检验、真实用户评估和语音深度测试等方面仍有不足，JarvisBench 的协议化设计使其有望成为未来 agent 协调能力评测的参考框架，推动该领域从“任务完成能力”向“人机共生中的注意力管理能力”拓展。
