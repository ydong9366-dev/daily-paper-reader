## 摘要
在自动化Web测试中，利用自然语言的功能描述生成测试用例并执行测试对于提升效率至关重要。这些任务要求测试智能体能够在目标应用上自主执行任务并生成测试。我们提出HxAgent，一种基于LLM的迭代式规划智能体，采用主动修正策略。在每一步之后，HxAgent重新评估Web状态，以基于(1)当前观察、(2)过去动作的短期记忆以及(3)从过去(不)正确动作序列中提取的长期经验来决定下一个动作。HxAgent在MiniWoB++上达到97.4%的精确匹配准确率，与不使用人工演示的最佳基线相当，并比最近的WALT高出10.5%。在包含350个Web任务的数据集上，它取得83.8%的精确匹配和91.8%的前缀匹配，超过WALT 13.4%。在OnlineMind2Web上，它进一步比WALT提升4.6%。

## Abstract
In automated web testing, generating test cases and performing testing using functionality descriptions in natural-language is crucial for improving efficacy. These tasks require such a testing agent to carry out tasks on the target application and generating tests autonomously. We introduce HxAgent, an iterative LLM-based planning agent with a proactive correction strategy. After each step, HxAgent reassesses the web state to determine the next action using (1) current observations, (2) short-term memory of past actions, and (3) long-term experience extracted from past (in)correct sequences of actions. HxAgent achieves 97.4% Exact-Match accuracy on MiniWoB++, comparable to the best baselines without human demonstrations and surpassing the recent WALT by 10.5%. On a dataset of 350 web tasks, it attains 83.8% Exact-Match and 91.8% Prefix-Match, exceeding WALT by 13.4%. On OnlineMind2Web, it further improves over WALT by 4.6%.

# HxAgent：面向端到端Web应用测试的迭代式智能体规划 —— 论文详细总结

## 一、核心问题与整体含义（研究动机与背景）

- **研究背景**：Web UI 测试大量依赖人工操作，测试人员使用 Selenium、Katalon 等工具手工录制用户交互并生成动作序列（SoA）作为测试脚本。该过程耗时、易错，自动化程度低。
- **核心问题**：如何让测试智能体仅根据自然语言任务描述，自动在目标 Web 应用上执行操作，并生成**可执行、可回放**的测试脚本（而非一次性任务完成）。
- **现有方法的四大局限**：
  1. 现有 UI 智能体（如 WebArena、WebLINX）只关注任务是否完成，不生成可执行的 SoA，难以用于测试脚本生成；
  2. 视觉/多模态规划器（如 SeeClick、UI-TARS、SeeAct、CogAgent）将动作表示为绝对屏幕坐标或文本描述，UI 变更时脆弱且难以转为可执行脚本；
  3. 基于模式/提示的智能体（如 MindAct、RCI、AdaPlanner、Synapse）高度依赖人工演示，扩展性差；
  4. 无演示的自我反思方法（如 Li et al.）容易陷入无引导的试错循环，缺乏对历史状态–动作对的推理。
- **论文提出 HxAgent**：一种迭代式 LLM 规划智能体，每一步重新评估 Web 状态，综合当前观察、短期动作记忆和长期经验来选择下一个动作，并采用**主动修正（proactive correction）**策略，从而自动生成端到端 Web 测试脚本。

## 二、方法论：核心思想、关键技术细节、公式与算法流程

### 1. 形式化建模
- 将 Web 任务执行建模为**部分可观测马尔可夫决策过程（POMDP）**：`M = (S, A, O, T, R, γ)`。
- **多模态观察**：`o_t = Ω(s_t) = (o_t^txt, o_t^img, o_t^elm)`，分别包含文本 DOM 信息、网页截图和可交互元素集合。
- **可行动作集合**：`A(o_t) = {(op, e, v) | e ∈ o_t^elm, op ∈ O, v ∈ V ∪ {∅}}`，其中 `op` 为操作（如 click、input），`e` 为网页元素，`v` 为可选输入值。

### 2. 记忆机制
- **短期记忆（Sequence Action Memory, SAM）**：`M_t = {(ŝ_{t−k}, a_{t−k}), ..., (ŝ_{t−1}, a_{t−1})}`，k 为窗口大小，保留最近的状态–动作交互历史，避免重复动作。
- **长期经验记忆（Experience Memory）**：`E = {(τ⁽ⁱ⁾, y⁽ⁱ⁾)} ∪ K⁽ʲ⁾`，存储完整轨迹、成功/失败标签以及抽象的规则 `K⁽ʲ⁺¹⁾ = φ(τ⁽ⁱ⁾, E)`。规则由 LLM 从轨迹中提炼（如“点击前先验证标签”），以纯文本形式与源 SoA 一起保存。

### 3. 动作接地与主动修正
- **动作选择**：`a_t ~ π(· | o_t, A(o_t), M_t, E)`，由 LLM 实现，受限于当前可行动作集合。
- 每一步执行动作后，**状态评估器** `G(τ_t, M_t, E)` 判断任务是否成功完成、是否需要提前终止。
- 与 ReAct 类似，但不同点在于：
  - 每一步都做状态评估并**主动调整计划**，而非像 Reflexion 一样在整个轨迹失败后才修复；
  - 长期经验以**增量抽象的规则**形式参与决策，而非仅回放原始轨迹。

### 4. 算法流程（Algorithm 1）
1. 加载起始 URL，初始化经验库 E 和短期记忆 M_t 为空；
2. 循环至最大步数 `MAX_t`：
   - `ContentExtractor` 提取当前状态 ŝ_t 和可行动作集合 A(o_t)；
   - `StateEvaluator` 通过 LLM 判断 success/stop，是则记录轨迹到经验库并跳出；
   - `ActionGrounding`（π_LLM）选择下一动作 a_t；
   - 若动作重复（count>1），则借助网页截图（o_t^img）再次调用 LLM 消除歧义；
   - 若动作需要输入，LLM 生成 input value；
   - 将（状态，动作）加入短期记忆 M_t；
   - 在测试环境中执行动作，进入下一状态；
3. 若达到最大步数仍未完成，训练阶段则记录为失败轨迹；
4. 通过规则提取器 φ_LLM 更新经验库中的规则。

### 5. 测试用例生成
- 成功完成任务的 SoA 可自动转换为回归测试脚本，每个动作定义为“操作类型 + 输入值 + 目标元素 + 网页状态”，无需 LLM 参与回放，可直接在 Selenium 环境中执行。

### 6. 视觉增强
- 针对真实网站 HTML 过长、复杂布局（如日期选择器）导致上下文窗口溢出或语义歧义的问题，HxAgent 在文本 DOM 之外提供**网页截图**辅助选择动作，利用 LLM 的多模态能力进行视觉接地。

1. **主结果显著优于基线**：

6. **成本优势**：HxAgent 的 token 消耗远低于 WALT，尤其输出 token 仅为后者的 8.9%，更适用于大规模测试。

## 七、优点

- **迭代式主动修正**：相比“事后反思”类方法，每步都做状态评估和计划调整，能避免错误累积，适应动态页面；
- **可执行的输出**：动作显式表示为“操作 + 元素 + 值”，可直接生成可回放测试脚本，无需 LLM 介入回放过程；
- **短时与长期记忆结合**：SAM 解决重复动作问题，经验规则从成功和失败轨迹中持续提炼，兼顾即时上下文与长期泛化；
- **多模态接地降低幻觉**：文本 DOM + 截图双重证据，缓解了上下文超限与复杂元素（如日期选择器）歧义问题；
- **无需人类演示**：在 MiniWoB++ 上追平甚至超越强演示基线，显著提升现实实用性；
- **成本分析透明**：提供了 token 消耗细化分解，有助于实际部署成本估算。

## 八、不足与局限

- **数据集覆盖仍有限**：
  - 只有 3 个数据集，其中 MiniWoB++ 属于受控模拟环境，真实网站数量有限（7 个；OnlineMind2Web 虽广但任务数偏少）；
  - 对大量现代 Web 组件（复杂日期时间选择器、大规模动态弹窗、反爬机制等）处理仍不稳定；
- **测试脚本回放成功率不高**：OnlineMind2Web 上仅 77.3%，真实网站动态布局、网络波动、XPath 变化等导致脚本脆弱，未在生成更健壮定位器（如 Robula+、相似性定位）方面做进一步优化；
- **对 LLM 的依赖与幻觉风险**：依赖 GPT-4o，且只设置了温度 0 来缓解不确定性，未做多种 LLM 的稳定性对比；LLM 输出仍可能产生幻觉或错误动作；
- **评估公平性存在偏置风险**：某些强基线（Synapse、WebGUM、CC-Net）依赖大量人工演示，与 HxAgent 不构成公平对比；而对 SeeAct 等仅选取“choice”变体，可能未能反映其完整能力；
- **跨平台泛化未经验证**：论文自称架构上平台无关（可扩展到 Android、桌面），但未提供任何移动/桌面端实验数据；
- **经验规则维护策略简单**：仅增量添加规则，无剪枝、合并或定期重新验证机制，长期大规模运行下可能积累冗余或过期规则；
- **最长屏幕动作数量分析存在离群点**：部分复杂任务（如 flight-Alaska-auto、Expedia 日期选择）Exact-Match 仅约 20%–32%，说明对高度动态交互仍不够鲁棒。
