## 摘要
长时域复杂任务要求智能体在持续变化的环境中反复观察状态、制定计划、调用工具、验证结果并从失败中恢复。然而，这类控制经验往往局限于单一情境或固定提示，难以在历史轨迹中积累和复用。本文提出OpenLoopEvolve (OLE)，一种以循环策略为中心的自进化框架。OLE将智能体的观察、规划、记忆、动作、验证、恢复、停止和预算控制表示为具有版本和谱系的可移植策略资产，并提供可根据实际需要选择的在线和离线进化模式：在线模式基于连续运行的反馈触发候选生成，而离线模式从存档轨迹和失败证据中搜索候选策略。两种模式共享一个进化机制，包括大语言模型的自主提案、冠军-挑战者成对评估和稳健发布。在线发布的策略在后续任务边界被激活，使用后续反馈进行监控，并在满足退化条件时回滚到其父版本。在模拟业务基准YC-Bench上，两种模式相对于固定的初始循环策略都提升了综合任务性能、任务成功率和风险指标。结果表明，将循环策略视为可管理资产能够支持控制经验的积累、比较、发布和复用，并提升智能体在长时域复杂任务上的性能。

## Abstract
Long-horizon complex tasks require agents to repeatedly observe states, formulate plans, invoke tools, verify results, and recover from failures in continuously changing environments. However, such control experience often remains confined to a single context or a fixed prompt, and is difficult to accumulate and reuse across historical traces. This paper presents OpenLoopEvolve (OLE), a self-evolution framework centered on the Loop Policy. OLE represents an agent's observation, planning, memory, action, verification, recovery, stopping, and budget control as portable policy assets with versions and lineages, and provides online and offline evolution modes that can be selected according to practical needs: the online mode triggers candidate generation based on feedback from continuous operation, whereas the offline mode searches for candidate policies from archived traces and failure evidence. Both modes share an evolution mechanism consisting of autonomous proposals by a large language model, Champion--Challenger paired evaluation, and robust release. Policies released online are activated at a subsequent task boundary, monitored using subsequent feedback, and rolled back to their parent versions when degradation conditions are met. On the simulated business benchmark YC-Bench, both modes improve aggregate task performance, task success rate, and risk metrics relative to a fixed initial Loop Policy. The results indicate that treating the Loop Policy as a governable asset can support the accumulation, comparison, release, and reuse of control experience and improve agent performance on long-horizon complex tasks.

  2. 如何利用历史轨迹和当前反馈自主改进该资产，同时保证只有通过候选验证、正式发布并在任务边界激活的策略才能影响后续运行？

## 2. 方法论

### 核心思想
- 将执行循环外部化为 **Loop Policy（循环策略）**，作为独立于具体模型和宿主实现的策略资产，可被读取、比较、替换和复用。
- 所有策略更新都遵循统一边界：**“证据 → 候选生成 → 候选验证 → 发布 → 任务边界激活”**。候选生成属于搜索过程，通过验证且正式发布的策略才能进入执行路径。
- 采用 **Champion–Challenger（冠军–挑战者）** 配对评估机制，并引入“稳健发布门控”，避免临时候选直接干扰运行。

### 关键定义
- 长期复杂任务以可执行合同表示：`g = ⟨d, U_g, M_g, S_g, V_g, β_g⟩`，分别表示目标、允许执行器、评估指标、证据来源、验证协议、资源预算。
- 循环交互过程：
  - `x_{t+1} = f_π(x_t, o_t, a_t, e_t)`
  - `a_{t+1} ∼ h_π(x_{t+1})`
  - 其中 `π` 为循环策略，`f_π` 控制状态更新，`h_π` 控制动作选择。
- 轨迹：`τ_i = (g_i, π_{v(i)}, H_i, y_i)`，保存任务、策略版本、交互历史和结果，保证性能可归属到具体策略版本。
- 进化证据：`E = Φ(D) = {ε_j = (ρ_j, δ_j, u_j, I_j)}`，包含方向、指标变化、策略组件、支撑轨迹索引。
- 循环策略的八分量结构：`π = ⟨π_obs, π_plan, π_mem, π_act, π_ver, π_rec, π_stop, π_bud⟩`。
- 资产表示（Bundle）：`B_v = ⟨π_v, χ_v, ℓ_v⟩`，即策略、适用条件、版本谱系（父版本和依据证据）。

### 算法流程
- **在线进化**（Algorithm 1）：
  1. 持续接收可归属轨迹；
  2. 通过 CANARYMONITOR 监控当前版本，若退化则回滚到父版本并隔离相关轨迹；
  3. 满足触发条件后，从近期轨迹提取证据 `E`；
  4. 大语言模型生成一个候选 Bundle `B′ = G^on_LLM(B, E, R^on)`；
  5. 在适用条件交集内进行 Champion–Challenger 配对评估得到 `P`；
  6. 通过稳健发布门 `Gate(P, Θ)` 后才记录为发布版本，并在**后续任务边界**激活为新 Champion。
- **离线进化**（Algorithm 2）：
  1. 从存档轨迹 `D_off` 提取证据 `E`；
  2. LLM 生成初始候选集 `C_1`；
  3. 对每代候选分别与固定 Champion 配对评估；
  4. 精英保留（Select）后，LLM 对保留 Bundle 进行变异/重组生成下一代候选；
  5. 经过 `K` 代后，收集通过门控的候选，用 ValueSelect 选出最高得分者作为继任 Champion；若无可发布候选则保留原 Champion。
- 统一释放门控：`Gate(P, Θ) = accept ⇔ ∏_{α∈{b,e,t,c}} Γ_α = 1`，约束类别为**收益、证据质量、尾部风险、资源成本**，且阈值不得放宽任务合同中的验证和资源边界。

## 3. 实验设计

- **Benchmark**：YC-Bench，模拟持续一年的企业经营，以最终资金衡量长期决策的累积效果。
- **场景/任务**：官方 medium 配置，20 轮上下文，官方种子 1/2/3，从相同初始状态开始年度评估。
- **对比方法（共 4 种设置）**：
  - **Baseline（Native agent）**：使用官方 YC-Bench Agent Loop，不集成 OLE，也不加载额外循环策略。
  - **Fixed-π0**：加载与 OLE 相同的初始循环策略，但全年保持不变，用来分离“引入策略”和“进化策略”的贡献。
  - **OLE-online**：从 π0 出发在线进化，共进行 12 次候选更新尝试。
  - **OLE-offline**：实验前通过离线进化获得固定策略，评估期间不更新。
- **模型**：deepseek-v4-flash，固定模型与基准配置。
- **主要指标**：最终资金均值、任务成功率、年存活率、最大回撤，另外统计 token 消耗。

## 6. 主要结论与发现

- 相比 Fixed-π0，OLE-online 和 OLE-offline 分别将最终资金提升 **140.07%** 和 **166.31%**，任务成功率提升 **13.98** 和 **17.92 个百分点**。
- 年存活率由 Fixed-π0 的 1/3 提升至 OLE-online 的 2/3 和 OLE-offline 的 3/3；最大回撤分别降低 10.77% 和 38.30%。
- 两种进化模式都支持更长的有效执行时长（平均存活天数 294 和 365，均高于基线），且每次调用平均 token 消耗更低（相对 Baseline 降低 11.89% 和 25.30%），说明循环策略在扩大执行规模的同时控制了单次交互成本。
- 总体结论：将循环策略作为可治理的版本化资产，能够支持控制经验的积累、比较、发布和复用，并带来长期复杂任务性能的持续提升。

## 10. 综合评价

OpenLoopEvolve 的核心贡献在于**抽象层的创新**：它将智能体完整执行循环封装为可版本化、可追溯、可比较、可复用的策略资产，并首次将 Champion–Challenger 发布机制系统性地引入循环策略的在线与离线自进化中。这一思路有效解决了以往控制经验"一次性使用、难以治理"的问题，四重发布门控与任务边界激活机制也体现出对运行稳健性的认真考量。实验初步证明了该框架在长期复杂任务上的潜力：在资金收益、成功率、存活率三个维度均大幅超越基线，同时 token 效率更优。

然而，论文目前仍停留在**初步验证阶段**：单一基准、单一模型、3 个种子、无消融、无显著性检验，使得结论虽亮眼但说服力有限。此外，关键实现细节的缺失削弱了可复现性。总体而言，该论文的价值在于提出了一个框架完整、思想清晰的新范式，为后续研究提供了良好的起点；但若要宣称"显著优于既有方法"，还需要在实验广度、统计严谨性和实现透明度上大幅加强。

## 11. 一句话概括

OpenLoopEvolve 将智能体完整执行循环外部化为带版本与谱系的可治理策略资产，通过在线/离线两种自进化模式和 Champion–Challenger 四重发布门控，在 YC-Bench 长期经营任务中验证了控制经验可积累、可进化、可复用，并显著提升收益、成功率与存活率，但实验规模与细节披露仍有待加强。
