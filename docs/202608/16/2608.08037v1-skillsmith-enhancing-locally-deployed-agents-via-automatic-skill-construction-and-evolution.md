## 摘要
基于大语言模型（LLM）的智能体框架如今可作为个人助理处理多步任务。现有智能体框架（如OpenClaw）通常采用云端智能体部署模式，使用闭源云LLM作为骨干模型，这可能暴露用户隐私信息并产生重复的LLM调用成本。本地智能体通过在用户控制的设备上部署前沿开源小型语言模型（SLM）来解决这些部署问题，但其任务效果仍远逊于云端智能体。通过诊断分析，我们发现使用前沿SLM作为骨干的本地智能体效果有限，主要源于骨干模型规模受限导致的环境知识缺失，包括环境规则和操作流程。为了以非参数化、上下文高效且无需专家编写的方式提供此类知识，我们提出了SkillSmith，一个云端-本地智能体协作框架，将技能（Skill）作为上下文高效的知识载体，从云端智能体任务探索中自动构建技能，并利用本地智能体执行反馈进化技能，以增强冻结的本地智能体。在每日智能体任务数据集AppWorld和WorkBench上的实验表明，自动生成的技能使搭载Qwen3.6-27B（SLM）的本地智能体达到与使用前沿LLM的云端智能体相当的任务效果，超越最强的非参数基线，在AppWorld-Normal上将每任务平均动作数从36.1降至9.9，并且无需重新运行技能构建即可泛化到其他SLM骨干模型。

## Abstract
LLM-based agent frameworks now act as personal assistants for multi-step tasks. Existing agent frameworks such as OpenClaw commonly follow the Cloud Agent depolyment mode using closed-source cloud LLMs as backbone model, which may expose private user information and incur repeated LLM-calling costs. Local Agents address these deployment concerns by depolying frontier open-source SLMs on user-controlled devices, but their task effectiveness still lags far behind Cloud Agents. Through diagnostic analysis, we reveal that the limited effectiveness of Local Agents with frontier SLM backbones mainly comes from missing environment knowledge caused by limited backbone model scale including environment rules and operation procedures. To supply such knowledge non-parametrically, context-efficiently, and without expert authoring, we present SkillSmith, a Cloud--Local Agent collaboration framework that uses Skill as a context-efficient knowledge carrier, automatic constructs Skill from Cloud Agent task exploration and evolves Skill using Local Agent execution feedback to enhance a frozen Local Agent. Experiments on daily agent task datasets AppWorld and WorkBench show that the automatically generated Skill enables the Local Agent with Qwen3.6-27B(SLM) to achieve task effectiveness comparable to Cloud Agents with frontier LLMs, outperform the strongest non-parametric baselines, reduce average actions per task from 36.1 to 9.9 on AppWorld-Normal, and generalize to other SLM backbone models without rerunning Skill construction.

## 2. 论文提出的方法论：核心思想、关键技术细节

### 2.1 核心思想
- 提出 **SkillSmith**——一个**云端-本地智能体协作框架**，利用云端 LLM 的丰富环境知识与强反思能力，自动构建并进化"技能（Skill）"，以非参数方式增强冻结的本地 SLM 智能体。
- 满足三个设计需求：**(R1)** 合适的知识载体以避免上下文低效；**(R2)** 无需专家编写即可自动构建高质量初始知识；**(R3)** 利用本地智能体执行反馈进行自动迭代进化、验证与修正。

### 2.2 关键技术细节

**（1）技能定义**：S = (M, R, C)，其中 M 为主 Markdown 文件（含通用指令），R 为参考文件集合（存储环境规则与操作流程），C 为各参考文件的加载条件。技能支持**渐进式披露**，即智能体仅在条件满足时加载相关参考文件，从而节省上下文。

**（2）问题形式化**：将离线技能学习建模为黑盒优化问题，目标是找到一个长度受限（Lmax）的技能，最大化冻结本地智能体的期望任务通过率：S⋆ = arg max E[pass rate]。由于该目标不可微，使用云端智能体 Gc 作为文本优化器，以 LLM 生成的反馈作为梯度信号。

**（3）离线学习两阶段流程**（见 Algorithm 1）：

- **阶段一：技能创建（Skill Creation）**
  - *探索与反思*：云端智能体执行训练任务，结合评估器反馈撰写"反思报告"（含任务、压缩轨迹、评估结果、更优路径、陷阱、工具使用等）。
  - *创建初始技能*：通过三种云端智能体角色协作——**聚类智能体**（按任务/应用/工具对报告分组）、**蒸馏子智能体**（提取可复用的步骤序列、代码模板、陷阱及补救方法、规则、触发关键词）、**合并智能体**（将跨簇通用知识提升至主手册，场景特定细节写入带触发条件的参考文件，受 Lmax 约束）。

- **阶段二：技能进化（Skill Evolution）**——迭代循环
  - *执行与压缩*：本地智能体加载当前技能执行任务，将失败轨迹与评估器反馈压缩为"失败报告"。
  - *进化技能*：通过三类云端智能体角色——**聚类智能体**（按任务与失败断言分组）、**归因子智能体**（对照技能归因失败：是技能未被加载、内容不完整/错误、还是接近成功的粗心错误，并撰写带优先级的修改笔记）、**合并智能体**（解决冲突、按优先级应用编辑、超出长度预算时压缩）。

- **部署阶段**：离线学习完成后，冻结的本地智能体携带最终技能 S⋆ 在本地运行，**全程无云端 LLM 调用、用户数据完全本地化**。

## 6. 论文的主要结论与发现

### 6.1 主结果
- 加载 SkillSmith 生成的技能后，本地智能体（Qwen3.6-27B）在 AppWorld-Normal、AppWorld-Challenge、WorkBench 上的通过率分别达 **78.6%、74.9%、89.0%**，相对于无技能基线分别提升 **+42.3、+46.8、+37.9 个百分点**。
- 相比最强非参数基线，SkillSmith 在每个数据集上至少提升 **11.3 个百分点**（11.3～26.2 点）。

### 6.2 云端对比
- 与云端智能体差距大幅缩小：AppWorld-Normal 从 57.7 点缩小至 15.4 点；AppWorld-Challenge 从 61.1 缩小至 14.3 点；**WorkBench 上甚至反超最强云端智能体 13.6 点**。

### 6.3 效率提升
- AppWorld-Normal 上每任务平均动作数从 **36.1 降至 9.9**，累计上下文 token 从 450.7k 降至 200.6k，输出 token 从 6.3k 降至 3.7k——技能知识帮助智能体避免试错，**压缩了执行过程**。

### 6.4 阶段贡献
- 技能创建阶段贡献主要增益（+30.0 ～ +43.5 点），技能进化阶段提供额外细化（+1.2 ～ +12.3 点）；
- 完整创建的初始技能比简化版初始技能能支撑更持续的进化提升。

### 6.5 泛化能力
- 无需重新运行技能构建，同一个 Qwen3.6-27B 生成的技能即可提升其他 SLM 骨干的表现：Qwen3.6-30B-A3B +20.1～+30.8 点，Gemma-4-31B +7.8～+48.2 点。

## 7. 优点

- **问题诊断精确**：将"模型规模导致效果差"泛化归因具体化为"环境知识缺失"，并通过三个严格递进的实证发现支撑，逻辑链清晰。
- **框架设计优雅**：以"云端构建 + 本地进化 + 离线部署"的协作模式，同时满足上下文高效、自动构建、自动进化三个此前难以兼得的需求；云端智能体在前台工作、本地智能体在后台驱动进化，角色分工合理。
- **方法可扩展**：采用多智能体流水线（聚类→蒸馏/归因→合并），不依赖特定提示词或模型，各组件可替换；技能格式遵循 Anthropic Agent Skills 标准，具有生态兼容性。
- **实验严谨**：将对比方法分为四个技术家族；所有非云端方法使用相同框架与骨干，控制变量得当；跨骨干迁移实验验证了技能的模型无关性。
- **实际应用价值强**：离线一次性成本明确，部署后零云端依赖且数据不出本地，在隐私敏感场景下具有实际部署潜力。

## 8. 不足与局限

- **实验覆盖有限**：仅覆盖两个数据集（AppWorld、WorkBench），且任务类型集中于 API 调用式的工具操作场景，未涉及网页导航、GUI 操作或具身智能等更复杂的环境；多样性有限。
- **训练/测试划分稳健性不足**：训练集仅采样一次（180/207 个任务），未报告多次随机采样的方差，结果的统计显著性存疑。
- **超参数敏感性未知**：进化轮数（固定 5 轮）、簇数量上限、技能长度预算等关键超参数未做敏感性分析，难以判断方法对超参数选择的稳健性。
- **未与参数更新方法对比**：虽然论文论证了非参数方法的必要性，但未将与微调型方法（如 Agent Distillation）在同一条件下的对比实验，无法量化"非参数"方法的相对优势。
- **对云 LLM 能力的依赖**：技能质量高度依赖云端智能体的执行与归纳能力，若云端 LLM 能力不足或任务领域极度垂直化，构建出的技能可能引入幻觉规则；论文未评估这一风险。
- **技能长度预算的固定性**：Lmax 设定为固定值（主手册 400 行、参考 250 行），未探讨不同 SLM 上下文长度下的最优预算配置。
- **安全性维度缺失**：文中未讨论云端智能体在探索过程中处理敏感用户数据时如何避免隐私泄漏（虽然部署后本地化，但离线构建阶段仍有数据上云环节）。
