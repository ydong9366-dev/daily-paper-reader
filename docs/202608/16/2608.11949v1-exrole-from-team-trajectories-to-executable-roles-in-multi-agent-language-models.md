## 摘要
角色为组织语言模型智能体提供了可解释的接口，然而大多数多智能体系统将其视为与学习行为和参数更新脱节的手写提示标签。我们认为，有用的角色应当是一个可执行的控制变量：它应当总结对未来效用具有预测性的行为，指导后续交互，并识别负责该行为的可训练能力。我们引入了ExRole，一个从轨迹到角色的框架，它从前缀局部的团队轨迹中学习未来感知的角色原型，将其解析为可读指令和令牌对齐的角色标记，并可选地利用回合对齐的信用来路由共享的LoRA秩槽。在MuSiQue和2WikiMultiHopQA上，ExRole相较于单智能体搜索分别提升了15.0/14.4和13.5/16.1的EM/F1分数。与最强的非ExRole对照相比，相应增益仍为11.5/11.6和7.7/9.7点。在两个基准测试中，受控结果一致地倾向于轨迹诱导的角色条件化，而非无角色、手动、随机及洗牌替代方案。角色-智能体-回合干预进一步表明，诱导角色捕获了超越固定智能体身份或回合位置的可转移行为专业化。

## Abstract
Roles provide an interpretable interface for organizing language-model agents, yet most multi-agent systems treat them as hand-written prompt labels disconnected from learned behavior and parameter updates. We argue that a useful role should instead be an executable control variable: it should summarize behavior predictive of future utility, guide subsequent interaction, and identify the trainable capacity responsible for that behavior. We introduce ExRole, a trajectory-to-role framework that learns future-aware role prototypes from prefix-local team traces, resolves them into readable instructions and token-aligned role markers, and optionally routes shared LoRA rank slots with turn-aligned credit. Across MuSiQue and 2WikiMultiHopQA, ExRole improves over single-agent search by 15.0/14.4 and 13.5/16.1 EM/F1 points, respectively. Against the strongest non-ExRole controls, the corresponding gains remain 11.5/11.6 and 7.7/9.7 points. Across both benchmarks, the controlled results consistently favor trajectory-induced role conditioning over role-free, manual, random, and shuffled alternatives. Role-Agent-Turn interventions further show that the induced roles capture transferable behavioral specialization beyond fixed agent identities or turn positions.

**整体含义：**
- 这项工作旨在填补多智能体系统中“角色发现/归纳”与“角色执行/优化”之间的鸿沟。传统方法要么只做行为的聚类（如 MARL 中的角色发现），要么只设计固定的提示词（如 CAMEL）。
- ExRole 的定位是：**让角色从团队协作轨迹中自动涌现，并被显式绑定到提示指令、模型内部的 token 标记以及可训练的 LoRA 参数路径上**，从而实现“角色归纳—角色提示—策略优化”三者的一体化闭环。

### 2. 论文提出的方法论：ExRole 框架

**核心思想：**
将角色视为贯穿三个层面的统一身份标识：
1. **交互层**（Interaction level）：提供可读的指令和 token 对齐的角色标记。
2. **参数层**（Parameter level）：作为路由器输入，在共享 LoRA 的秩槽（rank slots）上做稀疏放行（sparse-delta gating）。
3. **优化层**（Optimization level）：利用回合对齐的信用分配，将学习信号传递给产生有用行为的角色回合及其选择的容量路径。

**技术细节与公式流程（文字说明）：**

1. **未来感知的角色归纳（Future-Aware Role Induction）**：
   - 从已有的团队轨迹中，为每个智能体回合构建**前缀局部（prefix-local）行为特征向量 φ_obs ∈ R^30**，包含动作倾向、回合位置、团队上下文、证据使用和答案行为五类统计信息。
   - 使用一个角色编码器 f_θe 将特征向量映射为嵌入 ξ_t，并设置三个**预测目标**：预测当前智能体的下一次动作、未来证据效用以及最终回合回报。损失函数 L_role 包含交叉熵、二元交叉熵和平方误差项。
   - 对学到的嵌入执行 K-means 聚类（多次初始化），并通过**分离度-稳定性准则**选择最优簇数 K；每个簇被汇总为一个源原型 p_k（含质心 ξ̄、特征均值 φ̄、元数据分布 η）。
   - 通过一个**确定性解析器**，将原型映射到固定的角色类型（Researcher、Coordinator、Verifier、Analyst），并生成可读指令 ψ_k 和 token 对齐的角色标记 χ_k，无需额外的 LLM 参与命名。

2. **可执行角色绑定（Executable Role Binding）**：
   - 从源原型库 P 中解析出至多 N 个运行时角色，将角色标记（marker）嵌入到观测文本中，每个 token 通过“继承最近的标记”对齐到对应的角色段。
   - 这使得**提示中使用的角色与模型内部路由器消费的角色保持严格一致**。

3. **角色条件化的稀疏路由（Role-Conditioned Sparse Routing，ExRole-Routed）**：
   - 在共享 LoRA 更新上引入幂等调节因子 γ，通过**稀疏增量门控（sparse-delta gating）**只修改选中的 top-S 秩槽（默认从 1568 个槽中选 392 个）。
   - 路由器输入为：角色特征向量、离散角色 ID、以及池化的语义前缀（token embedding 均值）。
   - 引入**中心化（centering）平衡机制**，确保被选槽位的增益偏移在全局总和中保持平衡，避免路由退化。

4. **回合对齐的优化（Turn-Aligned Optimization）**：
   - 保留 GRPO 的组内相对优势 Adv(g)，同时增加**折扣的局部回合回报** U_turn：每个回合的 token 获得“轨迹优势 + 加权回合回报”的组合信用。
   - 路由器一边学习预测标准化的回合信用值（L_future 回归损失），一边最大化选中槽位上的对数概率加权信用（L_credit 策略损失）。
   - **关键设计**：ExRole-Shared（无路由，统一共享 LoRA）与 ExRole-Routed（带稀疏路由）共享同样的角色库、交互协议、奖励设计及回合对齐策略目标，从而隔离出“角色条件化稀疏路由”的独立贡献。

### 6. 论文的主要结论与发现

1. **轨迹诱导角色带来显著收益**：在 MuSiQue 上，ExRole-Shared 达到 31.5 EM / 43.2 F1，较单智能体搜索提升 15.0/14.4 点；在 2WikiMultiHopQA 上，ExRole-Routed 达到 50.0 EM / 59.7 F1，较单智能体搜索提升 13.5/16.1 点。
2. **诱导角色优于人工/随机/无角色**：与最强的非 ExRole 对照相比，增益仍有 11.5/11.6（MuSiQue）和 7.7/9.7（2Wiki）点。
3. **角色编码了可转移的行为特质**：角色-智能体-回合干预证明，角色身份在包含智能体身份和回合阶段之后，仍能降低 19% 左右的行动对数损失；不同角色间的 JS 距离是同角色跨智能体的 48–60 倍。
4. **路由的相对价值基于基准而异**：在 2Wiki 上 Routed 略优于 Shared（+1.0 EM），在 MuSiQue 上 Routed 略差（-1.5 EM），且差异在统计上并不稳健（CI 均跨越 0）。
5. **局限性暴露点**：在 HotpotQA 全 Wikipedia 检索压力测试中，角色专业化无法超越无角色的随机提示 MAS（EM 低至 30.0 vs. 34.5），说明当检索本身是主导瓶颈时，角色带来的收益不足以克服检索难度。

### 7. 优点

1. **统一的角色本体论**：将“角色的语义（指令）、角色的模型侧身份（token marker）和角色的学习能力（路由路径）”绑定在同一个概念下，解决了传统角色学习/角色提示/策略优化之间割裂的问题。
2. **未来感知的归纳方式**：通过学习嵌入预测未来动作、未来证据效用和最终回报，角色不再只是“过去行为的统计摘要”，而是对协作未来价值的编码。
3. **无需外部 LLM 的可扩展设计**：确定性解析器和模板映射避免了对额外角色命名模型或人工标注的依赖，可复现性强。
4. **严谨的受控测试**：基线的选择覆盖全面（无角色、人工、随机、错配），内部对照设计（Shared vs. Routed）干净利落，能够准确分离不同机制的贡献。
5. **坦诚面对失败**：HotpotQA 压力测试明确报告了方法的边界，增强了论文的客观性。

### 8. 不足与局限

1. **泛化性有限**：主实验集中在多跳问答上。未覆盖软件工程、网页导航、长周期工具使用或超过 3 人的更大团队。作者自述也承认此局限性。
2. **HotpotQA 压力测试的负结果**：在全 Wikipedia 检索场景中，诱导角色未能超越随机提示 MAS。这说明角色诱导带来的收益可能在检索困难的环境中被完全淹没，作者也承认“角色专业化本身无法克服此配置下的检索和答案选择约束”。
3. **角色库为离线静态资产**：角色归纳是在训练前完成的，来自固定批次的轨道数据；面对分布偏移或工具接口变化需要重新归纳。且运行时角色分配固定在循环调度中，角色-任务匹配的柔性不足。
4. **奖励设计依赖人工加权**：回合奖励包含多达十多个手动设置权重的成分（如 r_ans、r_sup、r_nov、r_ver 和 7 种惩罚项），其泛化性存在不确定性。
5. **路由器提升不稳定**：从配对比较（表10）来看，Routed 相对 Shared 的提升在统计上不可靠（置信区间横跨零），路由在 2Wiki 略微有益而在 MuSiQue 略有害，没有一致的正面证据支持稀疏路由本身的必要性。
6. **评估集规模偏小**：所有核心评估均为 200 题的 held-out 集。对于 7B 模型的微调评估来说，统计效力有限；虽然使用了 bootstrap CI，但 200 题对测试复杂问答系统来说仍属中等规模。
