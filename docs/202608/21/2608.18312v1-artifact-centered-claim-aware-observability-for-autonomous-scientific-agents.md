## 摘要
自主科学智能体如今越来越多地提出想法、编写代码、运行实验、分析结果，甚至撰写论文。观察和审计这些智能体是必要的，但仅记录每一次模型调用并不足够，科学家还需要检查系统产生的工件和声明及其相互关系。这是因为科学智能体系统中的故障往往分布在多个对象之间。一份手稿声明可能引用了错误的证据，一个搜索过程可能选择了退化的候选方案，一项实验室新颖性声明可能依赖于未说明的规则，或者多智能体计划可能在无明显触发因素的情况下发生变化。现有的追踪、实验跟踪和归档溯源工具很有价值，但其原生对象并未将这些科学审计关系作为一等公民。我们认为，自主科学系统应发出可移植的、声明感知的工件谱系作为最低审计层。我们提出一个围绕个体、操作者、适应度记录、谱系、归档、运行、流和引导命令的紧凑可观测性配置文件。在该配置文件中，科学声明是带有明确证据绑定和验证记录的普通个体。该配置文件旨在作为补充当前遥测和溯源标准的语义层。执行细节可保留在OpenTelemetry中。最终包可导出为PROV-O或RO-Crate标准。

## Abstract
Autonomous scientific agents now increasingly propose ideas, write code, run experiments, analyze results, and even draft papers. Observe and audit those agents are necessary but logging every model call is not enough, scientists also need to inspect the artifacts and claims that the systems produced and their relations. This is driven by the fact that failures in scientific agent systems are often distributed across several objects. A manuscript claim may cite the wrong evidence, a search process may select a degenerate candidate, a laboratory novelty claim may depend on an unstated rule, or a multi-agent plan may change without a visible trigger. Existing tracing, experiment tracking, and archival provenance tools are valuable, but their native objects do not make these scientific audit relations first-class. We argue that autonomous scientific systems should emit portable, claim-aware artifact lineage as a minimum audit layer. We propose a compact observability profile organized around individuals, operators, fitness records, lineage, archives, runs, streams, and steering commands. In this profile, scientific claims are ordinary individuals with explicit evidence bindings and verification records. The profile is intended as a semantic layer that complements current telemetry and provenance standards. Execution details can remain in OpenTelemetry. Final packages can export to PROV-O or RO-Crate standards.

# 论文总结：面向自主科学智能体的以工件为中心、声明感知的可观测性

## 1. 核心问题与整体含义

- **背景**：自主科学智能体已能够自动提出想法、编写代码、运行实验、分析结果，甚至撰写论文。传统观测手段（如记录每一次模型调用的日志）已不能满足科学审计需求。
- **核心问题**：科学智能体系统中的故障往往分布在不同对象之间，且不易被单一调用日志捕获。例如：
  - 手稿声明可能引用了错误证据；
  - 搜索结果可能选择退化（degenerate）的候选方案；
  - 新颖性声明可能依赖未言明的规则；
  - 多智能体计划可能在无明显触发因素的情况下发生变化。
- **关键论点**：现有 Trace（跨度树）、实验跟踪（Experiment Tracking）、PROV-O/RO-Crate 溯源等基础设施都非常有价值，但其"原生对象"不是科学审计关系（如声明→证据→评估者→谱系），因此无法回答科学审计的核心问题。作者主张**自主科学系统应发出可移植的、声明感知（claim-aware）的工件谱系（artifact lineage）作为最低审计层**，并以此为核心提出了一个可观测性配置文件，作为现有遥测与溯源标准的语义补充层。

## 2. 方法论

- **核心思想**：以"工件"（artifact）而非"模型调用"为审计单元。审计对象包括候选工件、推导工件的操作者、附着于工件的评估输出、归档/选择决策、人类引导事件，以及带证据绑定（evidence binding）的声明。
- **事件配置文件的五大科学抽象**：
  - **个体（Individual）**：任何候选工件，包括程序、手稿草稿、表格、协议、计划、样本、分子、图、声明或智能体版本；
  - **操作者（Operator）**：从零个或多个父个体派生一个或多个子个体的事件；
  - **适应度记录（Fitness Record）**：附着于特定个体的评估器输出（标量分数、通过/失败结果、结构化评审、证明检查状态、湿实验测量、新颖性分类等）；
  - **谱系（Lineage）**：由操作者诱导出的父子图；
  - **归档（Archive）**：可选的精选集合（精英集、Pareto 前沿、已接受声明集、保留样本列表等）。
- **三大结构记录**：
  - **运行（Run）**：一次自主过程的框架；
  - **流（Stream）**：工作节点、智能体角色、仪器、工具子系统或人机界面的标识；
  - **引导命令（Steering Command）**：记录人类或外部干预，并在应用时链接到改变运行的操作者。
- **把声明（Claims）作为普通个体**：
  - 声明有文本内容、证据引用、可选证据绑定（读哪个字段、提取什么值、做什么比较）、以及验证器产生的适应度记录（supported / unsupported / contradicted / needs_human_review）；
  - 后续手稿草稿通过普通操作者继承、修改或拒绝声明，使"论文写作失败"可查询：审稿人可以查找所有证据不存在的声明、提取值与引用指标不符的声明、或验证失败的声明。
- **事件契约和结构不变量（附录A）**：每个引用须指向更早事件对象或标记为外部导入；按工件版本的派生边无环；每个最终科学声明必须有证据绑定、失败验证记录或显式 unsupported 状态；评估输出须注明评估器版本和所判个体；编辑（redaction）只移除负载访问权，不删除事件存在性。
- **互操作性而非替代**：
  - 执行细节保留在 OpenTelemetry GenAI 语义约定中；
  - 最终派生图可导出为 PROV-O；
  - 研究包可通过 RO-Crate 序列化；
  - 工作流数据可通过 OpenLineage 导出；
  - git/DVC 等版本控制系统可作为底层存储基质，该配置只是加上了可移植的标准模式。
- **面向社区的五大最低要求**：①发出工件 ID（而非仅有 span ID）；②将操作者作为谱系事件发出；③将评估器输出附着到工件（而非浮动在运行级别）；④显式表示声明与证据；⑤将人类引导与归档决策保留在日志中。

## 6. 主要结论与发现

- **自主科学需要工件级别的可观测性**：相关审计对象往往不是某个 prompt、span 或 run，而是候选工件及其周围声明、证据、评估之间的关系。
- **配置文件应小而精**：个体、操作者、适应度记录、谱系、归档、运行、流、引导命令这八个元素构成的最小契约，已足以覆盖从线性撰写到进化搜索、从自修改智能体到闭环实验室的多种追踪形状。
- **声明必须成为一等公民**：把声明作为普通个体，配以显式证据绑定和验证记录，可使"无支持声明""错误数值引用""验证器不一致"等问题变成可机械查询的对象，无需重放整个运行。
- **互操作是可行路径**：该语义层可与 OpenTelemetry、PROV-O、RO-Crate、OpenLineage 等标准共存，事件流可以 git 等版本控制系统为底层存储，实现跨实验室的可移植性。
- **观测不能替代验证质量**：它使失败可检测、可调查，但不会阻止幻觉、伪造、不安全实验或基准过拟合；评估器的质量仍然是根本因素。

## 7. 优点

- **问题识别精准**：抓住了自主科学智能体与传统日志基础设施之间的语义鸿沟——"哪些调用发生了"不等于"哪个声明由什么证据支持"。
- **配置简洁且可扩展**：只用少量抽象即可覆盖六种控制结构（线性、流水线、树搜索、进化、自修改、闭环），设计克制。
- **强调互操作而非另起炉灶**：不是取代 OpenTelemetry/PROV-O/RO-Crate，而是作为语义桥梁，落地阻力更小。
- **从审计问题倒推需求**：以科学家、审稿人、安全监控者真正要问的问题为出发点推导记录需求，实用导向强。
- **对"声明"的处理有洞察力**：把声明当作普通个体而非嵌在文本里的注释，使声明可被追踪、修订、归档、验证，同时保留历史（不重写历史，而是追加新的适应度记录）。
- **对自修改系统的处理优雅**：把提示词、策略、评估器定义本身当作个体，通过版本保持事件日志无环，同时保留"系统改变自身生成过程"的可追溯性。
- **对未来社区提出可操作的最低要求**，为工具建设者和基准设计者提供了明确指引。

## 8. 不足与局限

- **缺少实证验证**：全文没有系统实验，未证明该配置在实际运行中能降低审稿负担或比现有记录方式更好。作者提出的审计覆盖率、审稿人效用和追踪基准仍是"该做"的计划，而非"已做"的结果。
- **粒度问题被视为最大开放难题**：不同领域需要约定什么算"实质性个体"（material individual），而声明提取既可能部分是自动化、部分是事后补充，界限模糊。
- **可伸缩性忧虑**：论文承认高频率工具调用下不应让每个 token 或临时文件进入谱系图，但"分层日志"（tiered logging）仅为粗略思路，没有明确的降采样策略或开销分析。
- **采用成本未量化**：对现有系统进行改造需要多大的工程投入、如何与已有编排运行时集成、迁移路径是什么，论文没有涉及。
- **安全和隐私风险**：追踪数据可能暴露敏感的实验室信息、人员信息或专有数据，论文只提了访问控制、编辑和签名策略，但未给出具体机制。
- **不能替代领域的语义验证**：配置只保证"声明有证据绑定、验证有结果"，不能保证评估器本身正确。一个坏的新颖性标准或偏置基准仍会被如实记录——只是变得可见。
- **审查与标注可行性未验证**：声明自动提取的可靠性、跨团队/跨领域时证据绑定语义的一致性等关键问题，论文未能给出令人信服的答案。
