## 摘要
近年来，由多模态大语言模型（MLLM）驱动的智能体系统发展迅速，但现有的具身智能体基准仍缺乏对多智能体协调的细粒度诊断能力。大多数基准要么聚焦于单智能体任务完成情况，要么仅以整体任务成功率来概括多智能体行为，这可能会掩盖重复工作、违反顺序约束、资源争用以及交接不同步等协调失败问题。本文提出 CoCoBench，一个用于评估可执行家务任务中多智能体具身协调的构念层面基准。CoCoBench 包含 897 个经 oracle 验证的实例，围绕四类反复出现的协调构念组织：任务分配、顺序排序、互斥和交接协调。除任务成功率外，CoCoBench 还提供构念层面的分数，用以衡量智能体是否进行了有效协调。我们在不同协调模式、观测输入和智能体数量下评估了 11 个领先的 MLLM。结果表明，协调能力具有高度的构念特异性：整体表现强劲并不意味着在不同协调类型上具备均衡的能力。这些发现为设计有针对性的模型架构以及提升多智能体协调能力指明了新方向。

## Abstract
Agent systems powered by multimodal large language models (MLLMs) have advanced rapidly in recent years, yet existing embodied-agent benchmarks still lack fine-grained diagnostics for multi-agent coordination. Most benchmarks either focus on single-agent task completion or summarize multi-agent behavior with overall task success rates, which can obscure coordination failures such as duplicated work, violations of ordering constraints, resource contention, and desynchronized handoffs. In this paper, we introduce CoCoBench, a construct-level benchmark for evaluating multi-agent embodied coordination in executable household tasks. CoCoBench contains 897 oracle-validated instances organized around four recurring coordination constructs: task allocation, sequential ordering, mutual exclusion, and handoff coordination. In addition to task success rate, CoCoBench provides construct-level scores that measure whether agents coordinate effectively. We evaluate 11 leading MLLMs across different coordination modes, observation inputs, and numbers of agents. The results show that coordination ability is highly construct-specific: strong overall performance does not imply balanced competence across different coordination types. These findings point to new directions for designing targeted model architectures and improving multi-agent coordination ability.

- **核心痛点**：现有具身智能体基准大多只关注**单智能体任务完成**，或以**整体成功率（SR）**概括多智能体行为。这种聚合指标会把不同性质的失败混为一谈，掩盖了：
  - 重复劳动（duplicated work）
  - 违反顺序约束（ordering violations）
  - 资源争用（resource contention）
  - 交接失步（desynchronized handoffs）
- **更深层问题**：即使感知正确、底层技能合法，团队仍可能因“过早关抽屉、争抢同一把刀、让交接伙伴空等”而失败；反之，**最终成功也可能掩盖非法或低效的协调过程**（如走非法捷径达成目标）。
- **论文主张**：具身协作不应只看“目标是否达成”，还应看“智能体如何协调达成”，即需要**构念层面（construct-level）**的、可诊断的评测。
- **整体含义**：CoCoBench 把任务级依赖分解为**显式、可度量、可分离**的协调机制，从而把“通用任务执行失败”与“特定机制协调失败”区分开，为面向协调能力的模型架构设计提供细粒度诊断工具。

## 2. 方法论

### 2.1 核心思想

- 将多智能体具身协调形式化为**共享交互环境中的高层联合决策**问题，并把评测从单一成功率扩展为**“任务成功率 + 构念分数”**双轴。
- 用**四类反复出现的耦合来源**组织任务：谁做什么（任务分配）、何时必须按序（顺序排序）、能否安全共享资源（互斥）、中间物体如何转移（交接协调）。
- 关键设计：**固定底层执行器与高层技能接口**，从而隔离出“高层团队协调能力”这一变量，而非混淆底层视觉识别或运动控制。

### 2.2 问题形式化（文字说明）

- 任务实例定义为 **x = (E, A, S, O, U, Δ, Φ, H, d)**：E 为家庭场景；A 为 N 个具身智能体；S 为状态空间；O 为各智能体观测函数；U 为固定可执行高层技能集合；Δ 为共享底层执行器；Φ 为目标谓词集合；H 为步数预算；d 为目标协调构念。
- 协调策略 π 将各智能体的观测历史映射为**联合技能决策** u_t = (u¹_t, …, u^N_t)。
- 执行器在环境中施加技能并记录事件，产生轨迹 τ = (s₀, o₀, u₀, e₀, s₁, …, s_H)，其中 e_t 记录非法技能、前置条件失败、资源冲突、冗余动作、等待等**仿真器接地事件**。
- 任务成功定义：最终状态满足所有目标谓词（Succ = 1[∀φ∈Φ, φ(s_H)=1]）。
- **协调耦合的定义**（本文的关键区分）：若存在两个智能体 a_i ≠ a_j 与技能 u^i_t、u^j_t′，使得某一技能在状态 s_t 下的可行性/目标贡献/执行代价，与在“另一智能体先执行其技能后的状态 Δ(s_t, u^j_t′)”下不同，则该任务存在协调耦合。耦合来源包括共享物体、空间互斥、时间前置条件、独占资源、以及一方产出/另一方消费的中间状态。
- 最终评测为二元组 **Eval(π; x) = (Succ_x(τ), C_{d,x}(τ))**，其中 C ∈ [0,1] 为构念分数，**与任务是否完成相互独立**。

### 2.3 四类协调构念与评分公式

| 构念 | 协调目标 | 评分公式（文字化） | 高分含义 |
|---|---|---|---|
| **D1 任务分配** | 均衡分配 | C_D1 = min(1, M*/M)，M 为实际 makespan，M* 为 oracle 参考 makespan | 接近参考并行调度；重复、失衡、串行化会降低分数 |
| **D2 顺序排序** | 前置条件合规 | C_D2 = p_legal × (1 − v/n)，n 为被评估的序相关操作数，v 为顺序违规数，p_legal 为合法性门控（无非法技能使用且无前置条件违规则为 1，否则 0.5） | 严格遵守因果顺序；前置条件违规会惩罚 |
| **D3 互斥** | 无争用的资源调度 | C_D3 = (1 − c/a) × min(1, M*/L)，a 为共享资源访问尝试数，c 为访问碰撞数，L 为执行动作步数 | 既惩罚直接争用，也惩罚显著长于参考计划的调度 |
| **D4 交接协调** | 有节奏的生产者-消费者行为 | C_D4 = 1 − min(1, (o + w)/h)，h 为成功缓冲区交接次数，o 为溢出次数，w 为空缓冲等待次数 | 生产者不过量溢出、消费者不空等 |

- 注意：**高 C_d 不蕴含任务成功**，两个指标需联合解读；当 n=0、a=0 或 h=0（信号不足）的轨迹会被排除。

### 2.4 基准构建与质量门控

- 在 **AI2-THOR** 中实例化；每个实例只针对一个目标构念，并从记录轨迹中评分。
- 覆盖 **10 个任务族**（Store Groceries、Sort & Store、Tidy Drawers、Stock Cabinet、Load in Order、Fill Drawers in Order、Prepare Food、Relay Items、Indirect Relay、Cross-Zone Handoff）、4 类房间、3 种团队规模（N ∈ {2,3,4}）。
- 实例由**符号模板**接地生成（指定房间、物体类、目标谓词、团队规模、构念及构念相关约束），并渲染自然语言指令。
- **三重质量门控**：
  1. **Placement gate**：验证物体可用性、空间可行性与所需可供性；
  2. **Oracle gate**：用特权参考策略确认可解性；
  3. **Metric gate**：仅保留 oracle 轨迹在目标构念上接近满分（near-ceiling）的实例。
- 设计哲学：**优先构念效度而非数据规模**，剔除不可行、歧义与弱诊断性实例。
- Oracle 计划：12 个手写特权模板实例化为 897 个逐实例计划；D1 手动验证参考 makespan 在该抽象下最优；D2–D4 不宣称全局最短。

### 2.5 评测协议与技能接口

- 每步智能体获得观测 o^i_t 与**可执行动作菜单** U^i_t = Γ(Φ, r^i, s_t) ⊆ U（由任务、角色、状态条件生成）。
- D1–D3 使用同质化的任务绑定菜单；**D4 使用角色条件菜单**，区分“源→缓冲区”的生产者动作与“缓冲区→目标”的消费者动作。
- 三种策略架构：
  - **C0 集中式**：单一规划器聚合所有智能体观测与历史后选择团队动作；
  - **去中心化（无通信）**：各智能体仅见本地观测与私有历史；
  - **去中心化 + 广播通信**：额外提供共享广播信道。
- 并发去中心化评测中，各智能体基于同一状态快照选择动作，再按确定顺序执行，以在保证可复现的同时暴露冲突。
- 指标：**SR（任务成功率）** 与 **CS（构念分数）**，另记录合法性与终局失败事件用于诊断分析；所有分数由轨迹确定性计算，**无需人工评判（judge-free）**。

## 3. 实验设计

- **数据集 / 场景**：AI2-THOR 可执行家庭任务；基准即 **CoCoBench**。

  - 开放权重：Qwen3.5-9B、Qwen3-VL-8B、Cosmos3-Nano-16B、RoboBrain2.5-8B、InternVL3.5-8B（后两者为面向机器人/具身决策训练或适配的模型）。

  1. 全量 897 集上的主对比（集中式 + 图像观测），报告各构念 SR/CS；

  6. **失败模式与合法性分析**：正常终止 / 预算耗尽 / 协议失败三类终局分解，以及 SR 与合法计划率（legal-plan rate）的差距；
  7. **失败诊断分解**：依赖违规、占用冲突、可供性失败、非法技能调用四类归因；
  8. **单集计算成本**：平均墙钟时间、执行步数、规划器调用次数。

- **充分性评估**：
  - **优点**：① 主实验覆盖面广（4 类构念 × 3 种团队规模 × 11 个模型），能同时刻画“构念间差异”与“模型间差异”；② 消融设计采用**分层子集 + 池化**，在控制 API 成本的同时仍保留 4 个代表性模型（涵盖专有/开放、通用/具身）与全部三种架构，因果归因较清晰；③ 指标验证通过**跨构念评分函数交叉应用**（把 D1–D4 的评分器互施于同一批轨迹），检验了各构念分数的**判别效度与区分度**，而非仅报告单一指标；④ 失败模式分析与诊断分解把“失败”细化为可操作的类别，避免了“只看 SR”的常见缺陷；⑤ 作者**主动声明 D2–D4 的 oracle 计划不保证全局最优**，并在 D1 上手工验证参考 makespan 最优性，体现了对指标边界条件的自觉。
  - **潜在不足**：① 构念分数依赖 oracle 参考计划（M*、L 等），在非 D1 构念上这些参考值只是“可行而非最优”，可能使 CS 的可比性在实例间存在轻微噪声；② 每个实例只针对**单一**目标构念，真实协作往往是多构念叠加，基准尚未覆盖“耦合构念”的组合场景；③ 评测对象全部为**免训练推理**，未涉及针对协调能力的微调或强化学习对比；④ 观测消融的“盲观测”设置去掉了图像但保留文本菜单，可能仍泄露部分空间信息，削弱了纯视觉贡献的分离度；⑤ 未报告多次采样（temperature、随机种子）下的方差与置信区间，模型间小幅 SR/CS 差异的统计显著性存疑。
  - **总体判断**：作为**诊断性基准**，实验规模与结构设计足以支撑其核心主张（构念可分离、SR 与 CS 不可互相替代）；但作为**排行榜式基准**，其统计稳健性与组合场景覆盖仍有提升空间。

## 6. 主要结果与结论

- **核心发现一：构念分数与任务成功率显著脱钩。**
  - 各模型在 D1–D4 上的 SR 与 CS 呈现明显不一致：部分模型能在“目标达成”上取得中等 SR，但 CS 长期偏低（尤其是 D3 互斥与 D4 交接）；反之也有模型 CS 尚可而 SR 受限。
  - 这直接支持论文主张：**“成功”不等于“协调良好”**，聚合 SR 会系统性掩盖协调缺陷；而 CS 能揭示“以非法/低效路径达成目标”的隐性问题。

- **核心发现二：协调构念难度分层明显。**
  - 相对而言，**D1 任务分配**最容易（模型能较好地进行粗粒度分工），**D4 交接协调**与 **D3 互斥**最难——前者要求生产-消费节奏对齐，后者要求避免对独占资源的并发争抢。
  - **D2 顺序排序**居中：模型通常能识别显式因果顺序，但在隐式前置条件与交错操作上易出错。

- **核心发现三：架构选择的影响是条件性的。**
  - **集中式（C0）**在 D1、D3 上通常优于去中心化：全局观测有助于消除重复劳动与资源冲突。
  - **去中心化 + 广播通信**在部分构念上缩小了与集中式的差距，但通信并不能自动解决**时序对齐**问题（D4），说明“有通信”不等于“有协调协议”。
  - **无通信去中心化**在团队规模增大时退化最快，冲突与冗余显著上升。

- **核心发现四：图像观测并非普遍关键。**
  - 观测消融显示，在多数构念上“图像 vs 盲”差异有限，甚至部分模型在盲观测下 SR 不降反升——提示当前 MLLM 在具身协调中**主要依赖文本化的任务描述与动作菜单**，视觉信息的有效利用仍是瓶颈。
  - 这与“感知正确但协调失败”的动机叙述一致：瓶颈更多在**高层协调决策**而非低层识别。

- **核心发现五：团队规模扩展的边际代价。**
  - 随 N 从 2 增至 4，SR 与 CS 普遍下降；D1 的分配复杂度与 D3 的争用概率随规模非线性增长，而 D4 的交接链路变长使失步风险累积。

- **核心发现六：失败归因的分布特征。**
  - 终局分解中，**预算耗尽**与**协议失败**占相当比例，正常终止但未达成目标的情况亦不少见，说明失败并非单一原因。
  - 诊断分解显示，**依赖违规**与**占用冲突**是两大高频归因，**可供性失败**与**非法技能调用**相对较少——即模型大多“知道能做什么”，但“不知道何时/与谁一起做”。
  - **合法计划率**明显高于 SR，二者之间的差距即为“合法但低效/失败”的协调损耗，进一步佐证需要构念级指标。

- **核心结论**：具身多智能体协调是一个**独立于任务完成**的能力维度；当前最强 MLLM 在该维度上仍显著落后于其单智能体任务执行水平，且不同构念上的短板并不一致，需针对性的架构与训练设计。

## 7. 局限与未来工作（作者立场 + 客观评述）

- **基准侧局限**：
  - 单一仿真平台（AI2-THOR），家庭场景，物体与可供性集合有限，向开放世界/户外/工业场景的外推性未知。
  - 每个实例仅绑定一个目标构念，缺乏“多构念耦合”实例，可能低估真实协作的复合难度。
  - Oracle 计划在 D2–D4 上非最优，CS 的绝对可比性受限。
- **评测侧局限**：
  - 全部为免训练推理评测，未考察微调、RL、多智能体专用架构的潜力。
  - 未系统报告随机性方差与显著性检验。
  - 并发去中心化评测采用“同一状态快照 + 确定顺序执行”，与真实异步并发仍有差距（可能低估或高估冲突）。
- **未来方向（隐含）**：耦合构念实例生成、跨平台迁移、面向协调的专门训练与通信协议学习、CS 指标的绝对标定（更强 oracle 或人类参照）。

## 8. 学术价值与启示

- **概念贡献**：首次将多智能体具身协调**拆解为可度量构念**（分配/顺序/互斥/交接），并给出**与任务成功正交**的评分函数，为“过程导向”的具身评测提供了可复用的方法论范式。
- **方法贡献**：三重质量门控（Placement / Oracle / Metric）与“构念效度优先于规模”的构建哲学，为同类诊断型基准的构建提供了模板；跨构念评分交叉验证是值得借鉴的**指标效度检验**手段。
- **实践启示**：对模型开发者而言，SR 高不等于协调好，需在训练目标与评测中加入过程性信号；对系统设计者而言，通信信道本身不足以解决时序对齐，需显式的协议/角色机制。

---

**一句话总结**：CoCoBench 通过把具身多智能体协作分解为任务分配、顺序排序、互斥与交接四类可度量构念，并用与成功率正交的构念分数加以评测，揭示了当前 MLLM “能完成任务却难以协调”的关键短板，为过程导向的具身协作评测提供了细粒度诊断工具。
