## 摘要
基于大型语言模型的多智能体系统正从固定交互拓扑向动态编排的智能体集群演进。然而，现有基准仍主要基于单智能体或通用智能体任务，难以系统评估关键编排能力。我们提出 SwarmBench，一个从准确率、效率、成本和过程质量等多个角度评估模型性能的基准。实验结果表明，当前模型在编排能力上存在显著差异。这些差异不仅体现在最终准确率、效率和成本上，也体现在编排过程本身的整体质量上。基于这些发现，我们进一步提出 SwarmExp，一种简单而有效的基于经验提取和经验回放的方法，能够持续提升大型语言模型的编排性能。

## Abstract
Large language model-based multi-agent systems are evolving from fixed interaction topologies toward dynamically orchestrated Agent Swarms. However, existing benchmarks are still largely based on single-agent or general-purpose agent tasks, making it difficult to systematically evaluate key orchestration capabilities. We propose SwarmBench, a benchmark that evaluates model performance from multiple perspectives, including accuracy, efficiency, cost, and process quality. Experimental results show that current models exhibit substantial differences in orchestration capability. These differences are reflected not only in final accuracy, efficiency, and cost, but also in the overall quality of the orchestration process itself. Based on these findings, we further propose SwarmExp, a simple yet effective method based on experience extraction and experience replay, which consistently improves the orchestration performance of large language models.

## 1. 核心问题与整体含义（研究动机与背景）

- **范式转变**：基于大语言模型的多智能体系统（LLM-MAS）正从"固定协作范式"（辩论、SOP 流水线、manager-worker 结构）转向**动态编排的 Agent Swarm**——由主智能体在运行时自主拆解子任务、创建子智能体、协调并行执行并汇总结果。
- **核心问题**：关键挑战已从"如何设计固定团队"转为"LLM 能否胜任集群编排器（orchestrator）"。
- **现有基准的两大缺口**：
  - 多数 MAS 研究仍沿用为单智能体或通用智能体设计的基准（如 GAIA、SWE-bench、Terminal-bench），**无法系统暴露 Agent Swarm 的关键能力**。
  - 即便任务适合多智能体协作，现有评测也**只看最终答案质量**，忽视编排过程本身（任务分解是否合理、子智能体创建是否有效、结果聚合是否完整）。
- **整体含义**：论文主张评测维度应从"结果准确率"扩展到"编排过程质量 + 效率 + 成本"，并提出过程导向的能力诊断工具与经验驱动的改进方法。

## 2. 方法论

### 2.1 Agent Swarm 的形式化定义

- 将 Agent Swarm 刻画为一种特定多智能体工作流，具备三性质：**(1) 层级编排**（单一编排器负责规划、创建、协调、综合）；**(2) 动态异构子智能体实例化**（运行时按需指定角色、骨干模型、工具、局部上下文）；**(3) 并行执行**。
- 形式化：`S(x) = (o, H, Πo, Πh, U, B)`，其中 `o` 为编排器，`H` 为可用子智能体配置集合，`Πo` 为编排策略，`Πh` 为子智能体执行策略，`U` 为工具/环境，`B` 为预算（步数、智能体数、时延、金钱）。
- 编排动作：`a_o^t ~ Πo(· | s_t)`；当动作为 `spawn agent` 时，创建子智能体 `h_i` 并指定配置 `φ_i = (r_i, m_i, τ_i, c_i)`（角色描述、骨干模型、工具子集、局部上下文）。
- 并行度定义：`ρ_t = |H_t|`（当前运行智能体数）；当存在 `ρ_t > 1` 阶段且任务受益于可并行子任务时，视为具备 swarm 行为。

### 2.2 SwarmBench 的构建

- **三大任务类别、8 个任务类型**，按所考察的编排能力划分：
  - **分解导向**：Batch Download（BD）、Multi-Text Understanding（MTU）、MATH。
  - **委派导向**：Multi-Perspective Analysis（MPA）、Root Cause Analysis（RCA）、Treasure Hunt（TH）。
  - **聚合导向**：Long-Text Generation（LTG）、Wide Search（WS）。
- **数据规模**：每任务 50 样本，共 **400 样本**；数据来源包括 Omni-MATH、Loong、DeepReview、OpenRCA、LongInOutBench、WideSearch；BD 与 TH 为本文全新合成任务（BD 平均每样本需下载 11.44 个文件；TH 为 9×9 部分可观测网格世界，含铜/银/金钥匙与宝箱，分值 100/200/300）。
- **Agent Swarm 框架设计要点**：
  - 主智能体负责分解、创建、委派、聚合，**不允许调用工具或独立答题**，且部分任务上下文对其隐藏，以抑制其自身知识对结果的干扰。
  - 子智能体骨干模型从**可配置模型池**中选择，池中每个模型附带基于公开信息撰写的 model description，主智能体需动态选型。

### 2.3 SwarmExp：经验驱动的编排增强

- **核心思想**：编排经验可从任务执行轨迹中沉淀并复用，通过"经验提取 + 经验回放"提升编排能力。
- **两阶段流程**：
  1. **轨迹生成与经验总结**：用初始 Agent Swarm 跑推理，收集完整轨迹，提炼三类知识——
     - **Skill**：高层工作流模板（SKILL.md），描述某类任务如何分解、组织子智能体、聚合结果，经"按工作流分组 → 质量过滤"生成；
     - **Trick**：细粒度可操作规则（`条件 → 动作` 形式），组织为 trick library，执行中按需检索；
     - **Model Card**：子智能体骨干模型在具体任务上的实际表现画像（适用场景、强项、弱项），辅助选型。
  2. **经验回放**：推理时将三类经验注入主智能体上下文，供其在规划、委派、聚合时参考。

## 6. 主要结论与发现

- **模型能力分布高度不均**：GPT-5.4 是最强且最均衡的编排器，8 个任务中 6 个最优；Claude-Sonnet-4-6 为最接近的专有竞争者，优势集中在 MPA、LTG 等偏角色组织与内容综合的任务。
- **开源模型能力碎片化**：Kimi-k2.5 在委派类任务（RCA、TH）最稳；Qwen3.5-397b-a17b 在聚合类任务（LTG、WS）更强；Deepseek-v3.2、GLM-5.1 表现稳定但无一致优势；Qwen3-30b-a3b 受规模限制在委派/聚合上明显偏弱。
- **成本与性能非线性**：MATH、BD 上性能随成本上升；而 MPA、LTG、MTU、RCA、WS 上高成本未必带来高收益，低成本设置即可接近最优。同族对比中 Qwen3.5-397b-a17b 更常处于 Pareto 前沿，Qwen3-30b-a3b 则常"花更多、效果更差"。
- **并行率 ≠ 并行收益**：Kimi-k2.5 与 Qwen3.5-397b-a17b 并行率最高，但并行增益并非最高；Gemini-3-flash 以中等并行率取得最高增益。决定时延收益的是**并行结构是否有效**（减少冗余等待、避免重复执行）。
- **聚合是最难稳定的能力**：任务视角下 MATH 分解最难、MPA/RCA/TH 委派最难、LTG/WS 聚合最难；模型视角下聚合维度得分普遍低于分解与委派。
- **SwarmExp 一致有效**：在 MTU、RCA、LTG、WS 上分别提升 +0.25、+6.42、+6.46、+2.92；跨模型迁移 16 个设置中 14 个提升；消融显示 **Model Card 贡献最大**（平均 -2.49），Trick 次之（-1.75），Skill 再次（-1.22）。
- **增益来源不止于算力**：成本匹配的单智能体基线虽有提升，但在 MTU、LTG、WS 上仍不及 Agent Swarm，说明收益来自**编排结构本身**（分解、互补模型利用、局部上下文隔离）。
- **跨任务经验迁移是任务依赖的**：LTG 可受益于其他任务的高层编排模式，而 WS 主要只受益于 WS 自身经验，多数跨任务注入反而有害。

## 7. 优点

- **问题定位精准**：明确区分"静态多智能体工作流"与"动态 Agent Swarm"，并给出可操作的形式化定义（含 spawn 动作、配置元组、并行度），填补了该范式的评测空白。
- **评测维度多元且互补**：把准确率、效率（并行率/并行增益）、成本（真实美元）与过程质量（三维 LLM 评分）结合，突破了"只看最终答案"的惯例。
- **过程质量评测框架细致**：给出了明确的评分 rubric、各维度的优秀行为与典型失败模式，并做了人工一致性验证。
- **任务设计有针对性**：三类任务分别施压分解、委派、聚合，且新构造的 BD 与 TH 强制"结果与环境状态一致"（校验和、宝箱实际送回），避免纯文本猜测。
- **对照实验严谨**：包含成本匹配单智能体基线、五次重复运行方差、多基线（Best-of-N、Multi-Model Voting、AOrchestra），能较有效分离"算力增加"与"结构增益"的贡献。
- **方法轻量可迁移**：SwarmExp 不训练模型、仅靠经验提取与上下文回放，跨模型、跨任务均有实证，工程落地成本低。
- **开源与可复现承诺**：提供代码仓库链接，数据来源多为公开数据集。

## 8. 不足与局限

- **任务覆盖有限**：作者自陈仅 8 个任务，可能无法覆盖真实 Agent Swarm 场景的多样性（如长周期、超大规模集群、异构工具生态）。
- **脚手架单一**：所有结论基于统一轻量级 swarm scaffold 与固定子智能体模型池，提升了可比性但限制了结论的泛化性；换脚手架或换模型池后结论是否成立未知。
- **过程评测依赖 LLM 裁判**：虽有人工一致性分析（相关系数 0.684–0.801），但仅为趋势级一致，仍可能引入系统性偏差；且过程评分与最终正确性解耦，可能出现"过程好但结果差"的评分争议。
- **绝对分数偏低、区分

度有限**：RCA、TH 等任务上多数编排器得分接近下限，存在明显的地板效应，模型间差异被压缩；部分任务指标也可能因评测方式而区分度不足，难以支撑细粒度排名。

- **模型描述与选型偏差风险**：子智能体模型池依赖人工撰写的 model description，主智能体据此动态选型。若描述存在偏差、过时或不完整，可能引入非能力性差异，使结果部分反映“描述质量”而非模型真实适配度。
- **成本口径受外部因素影响**：美元成本按 API 定价累计，随供应商价格、折扣、区域和缓存策略变化而波动，跨时间复现性较弱；同时未拆分子智能体创建、协调、重试等开销占比。
- **并行效率测量受环境噪声影响**：Parallelism Rate / Gain 依赖 wall-clock 时间，易受 API 限流、网络延迟、服务端排队影响；不同运行环境或不同时间点的效率结论可能不可直接比较。
- **SwarmExp 的鲁棒性证据有限**：经验提取依赖初始轨迹质量，若初始执行存在系统性错误，可能固化错误模式；经验库的更新、冲突处理、检索精度与长期维护机制讨论不足。
- **可复现性细节不完整**：未报告 GPU/集群规模、随机种子、温度、最大步数、超时阈值、重试策略等关键超参，虽提供代码链接，但精确复现仍存在障碍。
- **安全与治理讨论较少**：动态创建异构子智能体涉及权限继承、工具滥用、成本失控、审计追踪与沙箱隔离等问题，论文未系统展开；在真实生产环境中部署时，这些风险可能比基准分数更关键。

## 9. 总体评价与启示

- **定位贡献**：SwarmBench 是目前较少见的、专门面向“LLM 作为 Agent Swarm 编排器”的系统性评测基准，明确将研究焦点从固定协作范式推向动态编排，并给出可操作的形式化定义与过程质量框架。
- **方法价值**：其四维评测（准确率、效率、成本、过程质量）较全面地刻画了编排器能力；SwarmExp 以“经验提取 + 回放”实现免训练增强，跨模型、跨任务均有正向证据，工程可落地性较强。
- **核心启示**：
  - 单智能体能力不能直接等价为编排能力，强模型未必是强编排器；
  - 聚合阶段是当前最薄弱环节，应成为框架与训练优化的重点；
  - 并行率不等于并行收益，有效并行结构比单纯增加并发更重要；
  - 高成本不一定带来高准确率，成本感知编排具有现实必要性；
  - 经验回放是低成本提升编排稳定性的有效路径，但需关注经验质量与任务迁移边界。
- **适用读者**：多智能体系统研究者、Agent 框架与平台开发者、评测基准设计者，以及关注 LLM 编排、成本优化与过程可解释性的工程团队。
- **未来方向**：扩展至更长周期、更大规模、多模态、异构工具与真实企业流程；建立标准化编排协议与过程奖励；加强安全治理、权限隔离与成本控制；在更多脚手架和模型池上验证结论的外部有效性。
