## 摘要
LLM 已从语言生成器演化为能够执行复杂、长时程任务的自主智能体。这一演化催生了多种范式，包括用于激发模型能力的提示工程、用于管理信息访问的上下文工程、用于组织外部工具与资源的 Harness 工程，以及用于支持持续反思与自我改进的循环工程。然而，随着任务日益复杂，个体智能面临根本性限制：许多任务需要异构专长、相互依赖的子任务、并行执行、独立验证以及持久状态，这超出了任何单个智能体的组织能力。增强单个智能体的能力或上下文无法解决这种架构失配；智能必须改为分布在专用智能体之间，并在系统层面加以组织。我们将此称为系统智能（System Intelligence）：即智能体系统将多个智能组件组织并协调为一个追求共同目标的连贯、自适应整体的能力。实现系统智能不仅仅是增加智能体；它需要显式结构来组织工作、协调异构智能体，并维护不断演化的执行状态。我们提出图工程（Graph Engineering），这是一种面向下一代智能体系统的新兴范式。与主要优化个体交互或智能体层面行为的先前范式不同，图工程构建显式的、动态的、不断演化的图结构，用以表示任务、智能体和系统状态。这些抽象为组织复杂目标、编排异构智能体、建模系统动力学以及实现可扩展的智能体演化提供了统一基础。我们系统综述了面向 LLM 智能体的图工程的原理、方法与应用。相关论文、开源数据和项目收集于 https://github.com/DEEP-JLU/Awesome-Graph-Engineering。

## Abstract
LLMs have evolved from language generators to autonomous agents capable of complex, long-horizon tasks. This evolution has produced paradigms including Prompt Engineering to elicit model capabilities, Context Engineering to manage information access, Harness Engineering to organize external tools and resources, and Loop Engineering to support continual reflection and self-improvement. Yet as tasks grow more complex, individual intelligence faces a fundamental limit: many tasks require heterogeneous expertise, interdependent subtasks, parallel execution, independent verification, and persistent state, exceeding any single agent's organizational capacity. Augmenting one agent's capabilities or context cannot resolve this architectural mismatch; intelligence must instead be distributed across specialized agents and organized at the system level. We call this System Intelligence: an agent system's ability to organize and coordinate multiple intelligent components into a coherent, adaptive whole pursuing a shared objective. Achieving it requires more than adding agents; it demands explicit structures to organize work, coordinate heterogeneous agents, and maintain evolving execution states. We introduce Graph Engineering, an emerging paradigm for next-generation agent systems. Unlike prior paradigms that mainly optimize individual interactions or agent-level behavior, Graph Engineering constructs explicit, dynamic, evolving graph structures representing tasks, agents, and system states. These abstractions provide a unified foundation for organizing complex objectives, orchestrating heterogeneous agents, modeling system dynamics, and enabling scalable agent evolution. We systematically review the principles, methodologies, and applications of Graph Engineering for LLM agents. Related papers, open-source data, and projects are collected at https://github.com/DEEP-JLU/Awesome-Graph-Engineering.

## 1. 核心问题与整体含义（研究动机与背景）

- **演进脉络**：论文把 LLM 智能体的发展梳理为一条工程范式的递进链条：
  - **Prompt Engineering**：规定"做什么、怎么做"（指令、示例、约束、思维链、自一致性、ToT/GoT、自动提示优化）；
  - **Context Engineering**：规定"给模型看什么"（检索、压缩、剪枝、重排、层级上下文管理，如 RAG、Self-RAG、MemGPT、ACE）；
  - **Harness Engineering**：为模型接上持久可执行的能力（工具、记忆、技能、运行时编排、权限治理）；
  - **Loop Engineering**：把这些能力组织成有界、有状态、由反馈驱动的持续执行闭环（Loop Architecture / Interaction Paradigm / Environment Feedback）。
  - 前三者共同支撑 **Model Intelligence → Individual Intelligence**。
- **核心痛点（个体智能的结构性上限）**，论文明确提出三条：
  1. **并行与依赖任务难以调度**：单智能体倾向于把本可并行的分支（如日志分析、故障复现、代码检查）压成串行轨迹，丢失并行效率且难以定位错误阶段；
  2. **异构专长与独立验证难以整合**：专家能力与验证器都被塞进同一控制回路，导致角色混淆与确认偏差（写代码和评代码是同一个智能体）；
  3. **持久状态与故障恢复难以维持**：早期小错误被带入后续步骤，长时程任务失败时无法定位最早出错点，也无法只修复受影响部分。
- **核心主张**：上述问题是**架构性失配**，靠"更强的模型 / 更长的上下文 / 更多工具"无法解决；智能必须**分布到多个专用智能体并在系统层组织**。论文将这种能力定义为 **System Intelligence（系统智能）**——智能体系统把多个智能组件组织协调为一个追求共同目标、连贯且自适应的整体的能力。
- **关键澄清**：系统智能 **≠ 智能体数量的堆叠**。多智能体系统完全可能缺少工作组织、责任边界、协调机制与一致状态管理。真正的转变是从"以智能体为中心的执行"转向"系统级的组织"。
- **整体含义**：论文把 **Graph Engineering（图工程）** 定位为承接 Prompt/Context/Harness/Loop Engineering 之后的**下一个工程尺度**，即从"模型行为"→"持久智能体执行"→"系统级关系的显式组织、演化与语义奠基"。

## 2. 方法论：核心思想与关键机制

### 2.1 核心思想

- 用**显式、动态、可演化的图结构**作为系统智能的组织基底，统一表示 **任务、智能体、系统状态** 三类实体及其关系。
- 图的角色发生根本变化：不再是"增强某项能力（推理/记忆/检索/通信）的表示或计算机制"，而是**智能系统的组织基质（organizational substrate）**。
- 系统智能的本质是：**对任务、组件与运行时状态之间关系的系统性治理**。

### 2.2 关键形式化（用文字说明）

- **个体智能体抽象**：
  `Agent = Loop(LLM + Harness)`，更精细地写作 `Ai = Loop(Fi, Hi; sti)`
  - `Fi`：基座模型（内在认知能力）；
  - `Hi`：Agent Harness（决定可访问的资源与动作空间：工具、记忆、技能、权限、执行环境）；
  - `sti`：智能体 i 在时刻 t 的本地运行时状态；
  - `Loop`：决定这些能力如何被持续使用（感知–规划–行动–观察–验证–恢复–终止）。
- **智能体系统抽象**：
  `St = (At, Rt, Et, Πt, xt)`
  - `At`：智能体团队（各自拥有模型、Harness、Loop、本地状态）；
  - `Rt`：共享资源（工具、模型服务、记忆、知识库、验证器、人类支持）；
  - `Et`：外部环境（提供观察与反馈，并因动作而改变）；
  - `Πt`：协调机制（任务分派、信息交换、结果整合、冲突消解、故障处理）；
  - `xt`：系统级状态（任务进度、共享结果、智能体可用性、资源状态、环境变化、失败记录）。
  - 与个体本地状态 `sti` 的关键区别：`xt` 描述**整个系统的运行状况**。

### 2.3 三大支柱 + 演化 + 语义

- **（1）Task Organization（组织"做什么"）**
  - *Goal Decomposition*：把目标表示为子目标与依赖构成的图（节点=子任务/中间目标，边=优先级/数据/逻辑关系），支持并行与依赖分支调度。
    - 代表：HuggingGPT（多模态子任务分解与路由）、ReWOO（变量引用解耦推理与工具执行）、LLMCompiler（把函数调用计划编译为 dataflow DAG，就绪节点并行派发）、Plan-over-Graph（依赖约束下生成可并行调度）、TDAG / Flow（任务图可随中间结果动态细化）。
  - *Workflow Optimization*：把子目标编译为可执行工作流（节点=具体算子：LLM 调用、专用智能体、检索模块、工具、记忆操作、聚合器、验证器）。
    - 静态搜索类：GPTSwarm（把语言智能体系统视为可计算图，同时优化节点行为与边连接）、ADAS、AutoFlow、AFlow、A2Flow、MermaidFlow、VFlow。
    - 执行自适应类：DyFlow（用中间反馈动态生成/调整后续算子子图）、EvoFlow（在线演化多样工作流候选）、QualityFlow（质量检查控制接受/调试/澄清/回滚/继续）、FlowSteer（工作流结构可在执行回路内修改）。

- **（2）Agent Coordination（组织"谁来做"）**
  - *Agent Capability Modeling*：节点=智能体/技能/工具/模型/资源，类型化边=能力归属、资源访问、权限、可靠性。代表：DyLAN、Agent-Oriented Planning、MasRouter、AutoAgents、EvoAgent、AOrchestra、Captain Agent、SkillGraph、MaAS。
  - *Agent Team Organization*：边编码分派、委托、监督、验证、汇报关系；支持链式（MetaGPT 的 SOP 流水线、ChatDev 的聊天链）、路由式（Magentic-One 的编排者、WorkTeam、AgentVerse）、扇出/扇入式（Mixture-of-Agents、MacNet 的 DAG）、动态团队（Puppeteer、AgentNet 去中心化、SwarmAgentic、自组织智能体、Meta-Team）。
  - *Multi-agent Communication*：动态图，节点=智能体或人类，激活的边=谁在何时交换什么信息。既传结果也纠错（MAgICoRe 的生成–评估–修订回路）。结构优化：G-Designer、AMAS、AgentPrune（剪冗余连接）、AgentDropout（动态剔除低贡献智能体）、DyTopo（每轮重建稀疏通信边）、CARD（依据环境信号调整）、QueenBee Planner（从轨迹蒸馏可复用设计规则）；人类作为显式参与者（Collaborative Gym）。

- **（3）Runtime State Management（组织"系统如何运行"）**
  - *State Recording*：结构化表示（Magentic-One 的 Task/Progress Ledger、Graph of States 的信念状态+因果图与状态机）、受治理更新（PatchBoard 的 schema/权限/不变式校验、MemTX 的暂定写入 vs 事务性信念提交）、范围化可见性（Collaborative Memory 的身份与时间投影）、一致性管理（并发异常预防、事件溯源的可重放追加历史）。
  - *Fault Localization*：把"原因"当作假设而非因果既定；Who & When（归因到责任智能体与关键步骤）、MAST（系统设计/协调/验证三类失败）、TraceElephant（完整轨迹可观测下的归因）、TDAD（代码–测试依赖）、Cordon（类型化血缘、影子状态、语义事务边界）。
  - *Failure Recovery*：选择显式**恢复边界**，选择性修复而非全局重算（MAGE、ALAS、CausalFlow、ReflexGrad）；重放/回滚/分支（事件溯源、AgentGit、Shepherd、DART）；不可回滚外部效应的补偿（SagaLLM、RAC、Atomix、Aegis）。

- **（4）System Evolution（跨执行的持久改进）**
  - 任务组织演化：TDAG、Flow、DynTaskMAS、DyFlow、EvoFlow、QualityFlow（并警示 FlowSteer 表明规划信号可被操纵）。
  - 智能体协调演化：SwarmAgentic、AgentNet、自组织智能体、Meta-Team、DyTopo、CARD、QueenBee Planner。
  - 运行时状态演化：ReCreate（从成败历史提炼领域模式）、SkillGraph（失败案例蒸馏为推理启发式，维护演化中的 Skill Bank）、Swarm Skills（把成功轨迹抽取为可复用协调技能）、MemTX（暂定写入与已验证提交分离 + 级联修复）、ActiveGraph（事件溯源支持确定性重放与分叉）。
  - 核心闭环：**执行 → 经验 → 演化**，且必须支持验证与回滚，只让可靠改进留存。

- **（5）Ontology Engineering（作为下一代的语义基础）**
  - 分层模块化本体：核心本体 + 目标与价值、智能体与能力、观察与证据、行动与状态、评估准则等模块 + 领域本体。
  - 作用：目标形成与价值对齐（记录目标来源、优先级、授权范围、完成判据、约束，检测目标冲突与未授权修改）；共享语义与世界接地（与工具输出、环境观察、时间戳、溯源、验证结果对接）；系统智能度量（统一任务成功、失败、贡献、恢复、状态一致性、运行时成本的定义）。
  - 分工定位：**本体工程定义共享概念模型 → 图工程实例化为任务相关结构 → 运行时机制强制其操作后果**。

### 2.4 开放挑战（第 5 节）

- **Graph-Native Capability Substrates**：把模型、工具、技能、记忆、数据源、验证器、执行环境统一为类型化节点，边描述依赖、兼容、组合、替换、授权、成本、可靠性（A-MEM、Zep、Graph of Skills、SkillDAG 是早期迹象）。
- **Self-Evolving Graph Systems**：区分"运行时自适应"与"持久系统演化"；需要 **执行 → 结构信用分配 → 图修改 → 验证 → 提交/回滚** 的闭环，以及**跨图协同演化**（改任务图会改变所需能力，换智能体会使通信/权限失效）。
- **Graph-Native Agent Operating Systems**：把任务、智能体、能力、运行时状态做成一等系统对象（类型化、版本化图）；共享运行时提供图调度、能力发现、状态存储、事件与溯源日志、结构事务、权限强制、检查点、重放、回滚、图级可观测性（AIOS 是重要先例，LangGraph、MCP 提供部分机制）。
- **Privacy and Ethics**：敏感信息在组件间复制、经工作流传播、被持久化保存，带来未授权访问、跨任务泄漏、从执行轨迹推断隐私属性的风险；分布式决策使问责更难。
