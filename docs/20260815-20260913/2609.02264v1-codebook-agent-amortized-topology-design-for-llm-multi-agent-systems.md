## 摘要
针对每个查询调整LLM多智能体系统的通信拓扑，可同时提升准确率和效率；然而，当前的设计方法将其视为条件图生成：变分、自回归或扩散解码器在N×N邻接空间中进行搜索，而一个基于效用以及边数等结构代价训练得到的图网络代理模型对采样候选进行排序。我们认为，这种形式化与问题本身并不匹配。经验上，即使码本容量从8增加到64，通过奖励过滤的拓扑也坍缩为大约六种不同的图；边数与实测token消耗呈负相关（Pearson r ≈ -0.4），因此使图稀疏化反而会让推理更昂贵；并且，当智能体共享同一画像时——这是已发表基准的默认配置——基于智能体画像节点的消息传递评分器具有邻接不变性，因此在该情形下根本无法对候选进行排序。这三个事实促成了Codebook Agent：一个向量量化自编码器将成功的拓扑压缩为与查询无关的16项码本；一个奖励加权的MLP将查询嵌入映射为码上的分布；以及一个读取展平邻接矩阵的MLP代理模型，其以实测效用和按任务归一化的token成本为回归目标，在单次批量前向传播中对排名靠前的解码候选重新排序。在测试时无需迭代搜索、也无需消息传递的情况下，Codebook Agent在我们比较的全部六个基准上都是最准确的方法（平均84.6，而最强的先前设计器为83.0），在2.4毫秒内生成拓扑，并少用21.9--33.2%的LLM token。

## Abstract
Adapting the communication topology of an LLM multi-agent system to each query improves both accuracy and efficiency, yet current designers treat this as conditional graph generation: a variational, autoregressive, or diffusion decoder searches the $N \times N$ adjacency space, and a graph-network proxy trained on utility and a structural cost such as edge count ranks the sampled candidates. We argue that this formulation is misaligned with the problem. Empirically, topologies that survive a reward filter collapse to about six distinct graphs even when the codebook capacity grows from 8 to 64; edge count is negatively correlated with measured token consumption (Pearson $r \approx -0.4$), so sparsifying the graph makes inference more expensive; and a message-passing scorer over agent-profile nodes is adjacency-invariant whenever agents share a profile---the default configuration of published benchmarks---so it cannot rank candidates at all in that regime. These three facts motivate Codebook Agent: a vector-quantized autoencoder compresses successful topologies into a query-independent 16-entry codebook; a reward-weighted MLP maps the query embedding to a distribution over codes; and an MLP proxy that reads the flattened adjacency, regressed on measured utility and per-task normalized token cost, reranks the top decoded candidates in a single batched forward pass. With no iterative search and no message passing at test time, Codebook Agent is the most accurate method on all six benchmarks we compare (84.6 average against 83.0 for the strongest prior designer), emits a topology in 2.4 ms, and uses 21.9--33.2% fewer LLM tokens.

## 一、论文的核心问题与整体含义

- **研究背景**：LLM 多智能体系统通过通信拓扑交换中间结果，拓扑决定“谁看到谁的消息”，直接影响任务准确率与 token 成本。领域已从手工设计拓扑，发展到学习拓扑，再到为每个查询生成新拓扑的 query-conditioned 生成器。
- **核心问题**：当前主流设计把拓扑设计视为“条件图生成 + 图网络代理排序”：用变分、自回归或扩散解码器搜索 \(N \times N\) 邻接空间，再用基于效用和边数 \(|E|\) 等结构代价训练的图网络代理对候选排序。论文认为这一形式化与真实问题错位。
- **三个关键经验事实**：
  - **设计空间坍缩**：通过奖励过滤的成功拓扑只坍缩为约 6 种不同图，即使码本容量从 8 增到 64 也是如此。
  - **成本代理被反转**：边数与实测 token 消耗呈负相关，Pearson \(r \approx -0.4\)。稀疏图反而导致更长补全，最小化 \(|E|\) 可能最大化 token 账单。
  - **同质团队下评分器失效**：当智能体共享同一画像时，基于画像节点的消息传递评分器对邻接矩阵不变，所有候选得分相同，无法排序。而这是已发表基准的默认配置。
- **整体含义**：拓扑设计不应再是“生成邻接矩阵并迭代搜索”，而应是“离线离散化成功拓扑为短码本，在线按查询选择并重排”。这引出 Codebook Agent：用摊销式、单次前向的方式完成拓扑设计。

## 二、论文提出的方法论

- **核心思想**：把查询条件拓扑设计拆成三个前馈组件：
  - 向量量化自编码器：将成功拓扑压缩为查询无关的 16 项码本。
  - 奖励加权 MLP：将查询嵌入映射为码本上的分布。
  - 执行接地 MLP 代理：读取扁平邻接矩阵，按实测效用与归一化 token 成本对候选重排。
- **离线数据收集**：对每个 benchmark，用 50 个训练任务在 6 个固定拓扑下执行真实 LLM 智能体，得到 300 条 \((A_j, c_j, u_j, \tau_j)\) 记录。6 个固定拓扑包括 complete、chain、star 和三个 Erdős–Rényi 样本。
- **问题定义**：智能体画像嵌入为 \(x_i\)，拓扑为无自环有向邻接矩阵 \(A\)。执行返回效用 \(u(A,q)\in\{0,1\}\) 与 token 成本 \(\tau(A,q)\)。目标是最大化复合奖励 \(R = u - \lambda \tilde{\tau}\)，其中 \(\tilde{\tau}\) 为按同任务平均 token 归一化的成本，默认 \(\lambda=0.1\)。
- **拓扑码本（VQ 自编码器）**：
  - 将邻接矩阵非对角项展平为 \(a\)，编码为 \(z_e\)，在大小 \(K=16\)、维度 \(d_z=32\) 的码本中找最近码 \(e_k\)，得到量化表示 \(z_q\)。
  - 解码器输出边 logits，经 sigmoid 后以 0.5 阈值得到二进制拓扑。码本用 EMA 更新，衰减 0.99，commitment 系数 0.25，直通梯度，未使用码在 50 个 batch 后重置。
  - 只在 \(u>0.5\) 的成功记录上训练 VQ 自编码器，使码本存储“解决过任务”的拓扑。编码器和解码器不条件于查询，查询依赖完全由码预测器承担。
- **奖励加权码预测**：
  - 将训练记录过冻结编码器与量化器得到码索引 \(k_j\)。对每个查询条件 \(c\)，构造软目标 \(y_k(c)\)，用 \(\exp(\gamma R_j)\) 加权，\(\gamma=2\)，使高奖励、低成本的码获得更大质量。
  - 码预测器为 MLP：\(d \rightarrow 256 \rightarrow 256 \rightarrow K\)，dropout 0.1，用软交叉熵训练。这是查询进入生成的唯一位置。
- **执行接地 MLP 代理**：
  - 因同质团队下消息传递评分器对 \(A\) 不变，代理改为 MLP 读取 \(\text{vec}(A)\) 与查询嵌入 \(c\)，输出 \((\hat{u}, \hat{c})\)。
  - 回归目标为实测效用 \(u_j\) 与按任务归一化 token 成本 \(\tilde{\tau}_j\)，损失为均方误差。
  - 由于真实执行记录稀疏，加入结构 token 辅助目标：另设 \(K_{tok}=32\) 的重建量化器，对增强拓扑池做软码分配，辅助头预测该分布；总损失 \(L_\phi = L_{rew} + \lambda_{code} L_{code}\)，\(\lambda_{code}=0.1\)。增强池仅用于辅助目标，奖励监督只来自真实执行。
- **单次推理**：
  - 对查询嵌入 \(c\)，取码预测器 top \(M=5\) 个码，解码并去重得到候选集合。
  - 用代理模型在一次批量前向中评估所有候选，选择 \(\arg\max (\hat{u} - \lambda \hat{c})\) 的拓扑执行。
  - 测试路径无迭代搜索、无稀疏图构建、无消息传递，只有预测器一次、至多 5 次解码和一次批量代理前向。
