## 摘要
多语言多智能体系统在英语之外表现出显著性能下降，然而先前的研究很少指出当用户请求被转换为可执行计划时，任务关键信息是如何丢失的。我们将多智能体系统中的规划器视为请求到动作的接口，并从失败的真实世界任务执行中推导出一个可操作的规划-基础失败分类法。基于LLM的分析表明，随着语言资源可用性的下降，这些失败在未成功执行中所占比例不断增加，在低资源语言中影响最为显著。为了测试该分类法是否支持缓解措施，我们引入了TART（分类法引导的可操作表示），它使分类法的关键方面对规划器和下游子代理明确可见。在多种语言、三个LLM骨干、两个数据集和两种代理配置中，TART consistently提升了性能。在多语言GAIA上，它将一个最先进系统的准确率在跨越低资源到高资源设置的十一种语言上平均提高了5.6个百分点。

## Abstract
Multilingual multi-agent systems exhibit substantial degradation beyond English, yet prior work rarely identifies how task-critical information is lost when user requests are converted into executable plans. We study the planner in a multi-agent system as the request-to-action interface and derive an actionable taxonomy of planning-grounding failures from failed real-world task executions. LLM-based analysis shows that these failures constitute an increasing share of unsuccessful executions as language-resource availability declines, with the strongest effects in low-resource languages. To test whether the taxonomy supports mitigation, we introduce TART, Taxonomy-Guided Actionable Representation, that makes the taxonomy's key aspects explicit to the planner and downstream sub-agents. Across multiple languages, three LLM backbones, two datasets, and two agentic configurations, TART consistently improves performance. On multilingual GAIA, it raises a state-of-the-art system's accuracy by 5.6 percentage points averaged across eleven languages spanning low- to high-resource settings.

## 1. 核心问题与研究动机

- **背景**：基于语言模型的多智能体系统被广泛用于通用任务，但跨语言可靠性是一个显著挑战——训练数据中语言资源分布不均衡，导致系统在非英语（尤其是低资源语言）环境下性能显著下降。
- **核心问题**：先前研究仅确认了多语言多智能体系统存在性能退化现象，但未系统性地表征**任务关键信息在系统内部（尤其是请求→计划转换环节）是如何丢失或扭曲的**。
- **关键切入点**：作者将规划器（planner）视为“请求到动作”的接口，定义**规划-接地失败（planning-grounding failure）**为：即使计划被正确执行，其结果也无法满足原始请求的情况。
- **研究目标**：① 推导一个可操作的失败分类法；② 验证其跨模型、跨语言的普遍性；③ 基于分类法设计缓解方法并实证其有效性。

## 2. 方法论

### 2.1 规划-接地失败分类法（Taxonomy）

通过对失败样本的定性分析，归纳出**五类规划-接地失败**：

| 类别 | 定义 | 示例 |
|------|------|------|
| **实体接地失败（Entity）** | 计划错误翻译、幻觉或替换查询中的实体 | Igbo查询要求找“Physics and Society”论文，计划却引入了一篇完全无关的论文 |
| **来源接地失败（Source）** | 改变指定来源标识、或用错来源（如正确答案在图片中，却搜索网页文本） | 文件路径从`e8d2`被讹变为`e812`；应在图片中找日期却扫描整个网页 |
| **时间接地失败（Temporal）** | 更改或遗漏查询中的时间约束 | 查询要求比较2021-04-21的菜单，计划却用了2021-04-20 |
| **操作接地失败（Operation）** | 保留表面约束但执行错误的推理链或变更任务目标 | 应先找到“Esther书中第一个地名”再查1977年总理，计划却在书中找“prime minister”这一角色 |
| **输出格式接地失败（Answer Format）** | 推理正确但输出格式不符 | 要求只输出名称“Berkshire”，却输出“Berkshire 2-8-4 steam locomotive” |

### 2.2 分类法推导过程

- **样本筛选**：仅分析“英文查询成功但非英文查询失败”的配对样本，以隔离跨语言规划退化。
- **人工分析**：一名研究者主分析，三名研究者讨论确认分类；按**饱和度（saturation）**停止——分析80个失败样本横跨6种低资源语言后达到饱和。
- **配置隔离**：使用Qwen2.5-32B-Instruct和Cohere Aya-Expanse-32B在Open Deep Research框架中推导，与后续评估所用的模型/框架完全隔离，防止过拟合。

### 2.3 TART：分类法引导的可操作任务表示

- **核心思想**：分类法的每个失败类别对应计划必须保留的一种语义承诺，因此将这些信息**显式化**并注入系统，即可从源头缓解失败。
- **实现方式**：当查询进入系统时，LLM先将其转换为结构化JSON表示（TART），字段包括：`entities`、`time_constraint`、`source_constraint`、`attachment_type`、`operations`、`answer_type`。这些字段与五类失败一一对应。
- **关键特点**：
  - TART不要求修改模型参数，也不替换多智能体框架，仅作为提示注入；
  - TART **不只在规划阶段使用**，而是注入到规划器、协调器和工人代理的系统提示中，确保约束在整个执行链路中可见；
  - TART不翻译查询、不回答问题、不生成计划，仅做语义规范化。

## 6. 主要结论与发现

- **资源梯度效应显著**：随着语言资源可用性降低，分类法覆盖的失败占比**持续上升**（尤其操作接地和实体接地），而回答格式失败和“其他”类失败占比下降。说明低资源语言的失败越来越集中于TART可纠正的结构性错误模式。
- **TART一致性提升性能**：
  - **GAIA-MAPS / GPT-5-mini**：平均EM从0.249→0.305（**+5.6点**），11种语言中10种提升；
  - **GAIA-MAPS / Mistral-Large-3**：0.196→0.255（**+5.9点**），所有语言提升；
  - **GAIA-MAPS / Qwen3-VL-235B-A22B**：0.199→0.235（**+3.6点**），7种语言中6种提升；
  - **MULTITAT / Mistral-Large-3**：0.210→0.310（**+10.0点**），所有语言提升；
  - **MULTITAT / Qwen3-VL-235B-A22B**：0.307→0.338（**+3.1点**）；
  - 无任何语言出现显著性能退化（仅俄语-0.006，可视为噪声）。
- **操作接地是最大失败类别**：三个模型上分别占失败的24.0%（GPT-5-mini）、36.5%（Mistral-Large-3）、30.2%（Qwen3-VL），且在低资源语言中占比最高。
- **任务复杂度分析**：TART显著提升Level 1（+9.0点）和Level 2（+5.0点）任务，对Level 3 持平。原因是Level 3任务参考步骤（13步）和工具数（3.38）接近Level 2的两倍，即使规划接地失败被修复，更长的下游执行链仍给检索/工具/推理错误留下更多机会。
- **消融结果**：Input（仅实体/时间/来源）→ +Operation → Full 呈累积增益（均值0.233→0.256→0.287），操作字段对低资源语言（Igbo）增益最大。

## 7. 优点

- **可操作性的闭环验证**：从诊断分类法直接推导缓解方案并实证有效，而非停留在描述层面，形成“诊断→设计→验证”的完整闭环。
- **分类法推导严谨**：使用与评测隔离的模型/框架、跨6种低资源语言、80个样本达到饱和；三类研究者交叉确认。
- **方法轻量且通用**：TART不修改模型参数、不更换多智能体框架，仅通过提示注入实现，易于集成到现有系统。
- **实验矩阵全面**：覆盖3个模型家族、2个数据集、11种语言（资源跨度约5个数量级）、较完整的消融，支持结论的泛化性。
- **结果稳健**：GPT-5-mini双轮运行确认改善非偶然；LLM-judge分类经人工验证（88.9%一致，κ=0.860，macro-F1=0.906）。

## 8. 不足与局限

- **机器翻译语料**：6种低资源语言来自Google Cloud Translation，可能与自然撰写的查询存在语义或语体差异。Baseline和TART虽接受相同翻译保证比较公平，但结论在自然低资源语料上需重新验证。
- **分类法推导的偏差风险**：仅从“英文成功/非英文失败”对照样本归纳，可能遗漏英语中同样普遍或跨语言共有的失败模式。
- **LLM-judge验证不足**：大规模失败量化依赖Claude Opus 4.8作为裁判，人工验证仅覆盖一个模型（Mistral-Large-3）约30%的失败样本，裁判在不同语言/模型上的校准性未充分保证。
- **重复运行缺失**：除GPT-5-mini外，Mistral和Qwen均基于单次运行，缺乏方差信息。
- **Level 3任务的局限性**：TART对最复杂任务无增益，作者归因于任务内在复杂度，但这也表明仅靠规划端约束不足以解决长链路执行中的累积误差。
- **结果呈现的轻微不一致**：文中对标注者人数（正文提到6名，附录称7名）和样本数（122 vs. 117 vs. 280）存在前后不一致，略有损严谨性。
