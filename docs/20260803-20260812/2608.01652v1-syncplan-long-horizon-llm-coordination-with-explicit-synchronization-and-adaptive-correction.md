## 摘要
基于 LLM 的多智能体协调在动态环境中面临效率与自适应性之间的根本权衡。现有方法通常依赖重复的 LLM 调用或多轮通信来在执行期间调整决策，这引入了大量延迟，并使协调容易受到异步进展和环境变化的影响。相反，一次性规划降低了协调开销，但生成的开环计划可能迅速变得过时，或在动作依赖于其他智能体和环境时失败。我们提出 SyncPlan，一个通过显式同步和自适应修正实现长时程协调的计划-执行-修正框架。给定状态和团队级任务，一个集中式 LLM 协调器在单次规划调用中生成每个智能体的动作链。在执行过程中，显式等待原语和死锁检测强制执行智能体间以及智能体与环境间的依赖关系，同时一个轻量级的计划过时检测器持续评估剩余计划，并在环境变化使其假设失效时触发重新规划。我们进一步通过 SFT 和面向规划的 RL（利用密集任务进度和结果级执行反馈）优化协调器。在公开的 Overcooked 基准测试和复杂的《王者荣耀》环境上的实验表明，SyncPlan 在实现最先进的任务成功率的同时，与现有的基于 LLM 的协调器相比，仅使用不到 0.05% 的挂钟运行时间。代码和数据集将公开提供。

## Abstract
LLM-based multi-agent coordination faces a fundamental trade-off between efficiency and adaptivity in dynamic environments. Existing approaches typically rely on repeated LLM invocations or multi-round communication to adapt decisions during execution, introducing substantial latency and making coordination vulnerable to asynchronous progress and environmental changes. Conversely, one-shot planning reduces coordination overhead but produces open-loop plans that can quickly become stale or fail when actions depend on other agents and the environment. We introduce SyncPlan, a plan-execute-correct framework for long-horizon coordination through explicit synchronization and adaptive correction. Given the state and team-level task, a centralized LLM coordinator generates per-agent action chains in a single planning call. During execution, explicit wait primitives and deadlock detection enforce inter-agent and agent-environment dependencies, while a lightweight Plan Staleness Detector continuously assesses the remaining plan and triggers replanning when environmental changes invalidate its assumptions. We further optimize the coordinator through SFT and planning-oriented RL with dense task progress and outcome-level execution feedback. Experiments on the public Overcooked benchmark and the complex Honor of Kings environment show that SyncPlan achieves state-of-the-art task success rates while using less than 0.05% of the wall-clock runtime compared with existing LLM-based coordinators. Code and datasets will be made publicly available.

## 1. 核心问题与整体含义
- **研究动机**：LLM 为多智能体协同提供了灵活手段，但在实时动态环境（如 MOBA 游戏、烹饪合作任务）中，现有基于 LLM 的协调器面临**效率与自适应性之间的根本权衡**。
- **问题定位**：
  - 重复调用 LLM 或多轮通信虽然能动态调整决策，但引入高延迟，难以满足实时约束；
  - 一次性规划虽然开销低，但生成的开环计划在环境变化时容易“过期”，导致协调失败。
- **三大核心挑战**：
  1. **实时约束**：环境逐帧演化，频繁调用 LLM 的计算开销不可承受；
  2. **计划过时**：环境变化可能使联合计划失效，延迟重规划会让智能体继续执行陈旧动作，而固定频率重规划又浪费计算；
  3. **协调冲突**：异步执行产生的时间/条件依赖（如等待队友或环境条件）通常以自然语言描述，底层执行器难以可靠验证和强制执行。
- **核心问题**：如何让基于 LLM 的多智能体协调在执行过程中既高效、又同步、且具备自适应性。

## 2. 方法论
SyncPlan 提出 **“计划-执行-纠正”（plan-execute-correct）** 框架，主要包含三个模块：

### 2.1 协作规划（Collaborative Planning）
- 集中式 LLM 协调器在**单次规划调用**中，根据当前状态和团队任务生成每个智能体的低层动作链（action chains），动作链可跨多个环境帧执行，从而摊薄规划成本。
- 提出**显式同步原语**，借鉴操作系统进程同步中的 wait 操作：
  - `Wait_agents`：等待另一智能体到达指定里程碑；
  - `Wait_entity`：等待环境实体满足指定条件。
- 通过等待谓词将隐式的协调意图转换为可机器检查、可执行的约束。

### 2.2 运行执行（Runtime Execution）
- 每个智能体维护一个指向动作链当前步骤的指针，逐帧推进执行；
- 可执行动作（move、attack、interface 等）直接派发；
- 同步原语被解释为可执行的等待谓词，阻塞该智能体直到条件满足，其他智能体不受影响；
- **死锁检测**：维护有向等待图 `G=(V,E)`，边 i→j 表示智能体 i 正在等待智能体 j；每帧检查是否存在有向环。增量算法通过可达性检验 R(j,i) 判断插入新边是否会成环，复杂度 O(K^2)，实际 O(K)（每个智能体最多一条出边）。

### 2.3 自适应纠正（Adaptive Correction）
- 引入轻量级 **Plan Staleness Detector（PSD）**，用于判断当前剩余计划是否仍有效，按需触发重规划，避免固定频率重规划的浪费。
- PSD 输入：
  1. 链-实体关联矩阵 `C_t ∈ {0,1}^{N×M×L}`（规则构造，不学习）；
  2. 当前实体状态矩阵 `X_t ∈ [0,1]^{M×F}`；
  3. 状态差分矩阵 `Δ_t ∈ [-1,1]^{M×F}`（与 `k_ref=3` 帧前比较）。
- 模型结构：双通路（chain pathway 和 state pathway）获得实体嵌入，交互后经 MLP + sigmoid 输出重规划概率 `P_replan(t)`，超过阈值 η 则触发重规划（η=0.7，网格搜索确定）。
- PSD 采用小规模网络，最终选定 Wide + Focal loss 结构（74.5 万参数），F1≈0.838，召回率>0.99。

### 2.4 训练优化：SFT + RL
- **SFT 预热**：从专家轨迹和蒸馏数据构建指令-响应对，学习输出结构化、可执行的动作链和同步原语。
- **规划导向 RL**：使用 GRPO（Group Relative Policy Optimization）优化完整动作链，奖励函数为：
  `R(A) = R_prog(A) + α·1[Ω(A)=Success] − (P_syn + P_sem + P_dlk + P_tmo)`
  - 进度项 `R_prog` 由链内完成比例、效率（完成时间）、长度正则组成；
  - 五种终止结果：Success、SyntaxError、SemanticError、Deadlock、Timeout；
  - 死锁惩罚最重（λ_dlk=1.0），语义错误次之，超时无额外惩罚，语法错误按严重度缩放。
- 整个流程可概括为：初始计划 → 逐帧执行 → 死锁/过时检测 → 按需重规划。

- SyncPlan 在 Overcooked 动态任务上显著优于现有 LLM 协调器，同时墙钟时间降低 2~3 个数量级；完整版在标准 Coordination 达到 96.1% TAR，动态 Ring 达到 88.3%。

## 8. 不足与局限（续）

- **集中式协调的潜在瓶颈**：所有智能体的行动计划均由单个集中式 LLM 协调器统一生成。虽然单次规划摊薄了推理成本，但该架构仍然存在**单点故障风险**——一旦协调器输出包含语法错误或语义错误的动作链，所有智能体将同时受影响。此外，集中式规划的可扩展性未在更多智能体（如 10 人以上）场景中得到验证，跨团队规模扩展时可能存在规划长度与复杂度上限。
- **同步原语的表达能力有限**：SyncPlan 仅定义了 `Wait_agents` 和 `Wait_entity` 两类等待原语，覆盖了基于"等待某个智能体/实体"的简单时序依赖，但难以表达更复杂的协调逻辑，如互斥访问（mutex）、条件分支同步、超时兜底、或基于事件回调的异步触发。在需要精细资源竞争控制的场景（如多个智能体争抢同一关键道具）中，原语表达能力可能不足。
- **PSD 的关联矩阵依赖人工设计**：链-实体关联矩阵 `C_t` 需要依据每个环境的具体语义手工构造规则（如实体位置与动作目标的对应关系），这限制了 SyncPlan 在新环境中零成本迁移的能力——每引入一个新任务，都需要领域专家重新设计关联规则。
- **RL 训练信号依赖完备的终止判定器**：复合奖励中的语法错误、语义错误、死锁、超时等信号均依赖外部验证器精确判定。在更复杂或更开放的环境中，构建这样的判定器本身可能是一项难题，且判定器的准确性直接影响最终策略质量。
- **对 LLM 基数能力的依赖**：实验表明 1B 以下的模型无法稳定生成合法动作链，说明该方法对底层模型的基础编码和结构化输出能力仍有较高门槛；在算力受限的部署场景中，这一约束可能成为实际瓶颈。
- **高度动态场景下的 TAR 仍有提升空间**：在 Overcooked 动态 Ring 布局上与任务特定 RL 基线仍有差距（SyncPlan 88.3% vs 任务特定 RL 更高），说明极端动态条件下，基于 LLM 的协调方案尚不能完全取代针对特定任务训练的强化学习方法。
- **缺乏多语言/多模态输入的验证**：所有实验均基于英文文本状态输入；同步原语在中文、低资源语言或图像/传感器输入下的表现未知，实际工程部署时可能需要额外适配。

## 9. 未来研究方向

- **分层可扩展协调**：探索"群体级—个体级"的分层规划架构，由高层 LLM 协调器生成粗粒度目标，由低层轻量策略（如 RL 控制器或规则系统）负责细粒度执行，从而缓解集中式单点瓶颈并支持更大规模团队。
- **更丰富的同步原语库**：借鉴并发编程中的信号量、管程、屏障（barrier）等机制，扩展同步原语的语义空间，或设计原语的自动合成方法，使其能表达更复杂的时序约束。
- **端到端可学习的 PSD**：用可微分的预测模块替代当前基于规则的链-实体关联矩阵构造，让系统在训练过程中自动习得"计划何时过时"的判别信号，减少人工工程干预。
- **跨域泛化评测**：在更多协作环境（如多智能体导航、工厂仓储调度、搜索救援、合作游戏之外的通用 Embodied AI 基准）上验证 SyncPlan 的通用性。
- **在线自适应 RL**：当前 RL 在离线仿真中训练，未来可探索在真实在线环境中持续微调，使系统随部署环境动态演化。
- **混合人类-AI 团队协调**：将同步原语扩展到人类-智能体混合团队场景，使人类指令与 LLM 规划通过统一的同步接口对接，提升人机协作效率。

## 10. 总体评价

SyncPlan 的核心贡献在于精准识别了 LLM 多智能体协调中"效率 vs 自适应"这一根本矛盾，并通过三个正交且互补的机制（显式同步、增量死锁检测、按需重规划）给出了一套工程上完整、理论上自洽的解决方案。其价值不仅体现在性能数字上——更在于将操作系统领域的同步思想迁移到 LLM 规划领域，并为"何时该重新思考计划"这一通用问题提供了一个具有启发性的轻量级判别框架。

从学术角度看，该工作在方法创新性、实验系统性和工程实用性三方面均达到较高水准；但同时也应认识到，其集中式架构和人工设计的 PSD 关联规则仍带有明显的"第一代 LLM 协调器"特征——未来的工作方向大概率会朝着分布式、自适应、自动学习判别信号的方向演进。总体而言，这是一篇设计思想清晰、工程落地能力强、并具备良好可扩展研究空间的系统性工作。
